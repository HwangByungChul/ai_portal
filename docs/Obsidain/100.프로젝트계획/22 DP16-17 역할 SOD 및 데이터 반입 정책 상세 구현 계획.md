# DP16-17 역할 SOD 및 데이터 반입 정책 상세 구현 계획
본 계획서는 전체 기능명세서 잔여 기능 개발 실행 계획([[15 전체 기능명세서 잔여 기능 개발 실행 계획]])의 순서 7에 따라, 역할 템플릿 기반 세부 권한 통제(DP-16), 직무 분리(SOD: Separation of Duties), Microsoft Entra ID 연계 인터페이스 및 데이터 Scope별 반입 승인 파이프라인(DP-17)을 실제 서비스 오픈 수준으로 구현하기 위한 상세 계획입니다.

## 1. 배경 및 핵심 목표
- **역할 템플릿 및 세부 권한 (DP-16)**: 기존 3대 기본 역할(`USER`, `TADMIN`, `PADMIN`)을 보완하여 기능별 템플릿(`AGENT_DEVELOPER`, `APPROVER`, `DATA_OWNER`, `SECURITY_REVIEWER`) 및 capability 검증 체계를 확립합니다.
- **직무 분리 (SOD) 강제**: 배포 승인 및 데이터 반입 승인 시, 요청자 본인이 스스로 승인하는 자기 승인(Self-Approval)을 원천 차단(`SELF_APPROVAL_FORBIDDEN`, 403)하여 내부 통제를 준수합니다.
- **SSO 연계 인터페이스 (OIDC/Entra ID)**: 클라이언트 임의의 claim 주입을 거부하고, 서버 주도의 state/nonce 검증 및 내부 계정 매핑을 수행하는 표준 SSO 엔드포인트(`/auth/sso/start`, `/auth/sso/callback`)를 제공합니다.
- **데이터 Scope 및 반입 승인 (DP-17)**: 문서/지식 자산의 조직·부서 범위 반입 신청(`data-imports`)과 승인 프로세스를 구축하고, 미승인 문서는 RAG 인덱스 및 검색에서 격리(`quarantined`)되며 타인 승인 후에만 정식 서비스 검색에 반영되도록 통제합니다.

## 2. 인터페이스 및 계약 설계
- **SSO 인터페이스 계약**:
  - `GET /api/v1/auth/sso/start?provider={alias}`: 서버 허용 목록의 IdP에 대해 state/nonce를 발급하고 인가 URL 반환
  - `GET /api/v1/auth/sso/callback?code={code}&state={state}`: state 유효성 및 만료를 검증하고 내부 사용자 세션 발급
- **데이터 반입 승인 계약**:
  - `POST /api/v1/data-imports`: `{ "document_id": UUID, "classification": "internal"|"confidential", "target_scope": "org"|"department", "reason": string }`
  - `GET /api/v1/admin/data-imports`: 반입 요청 목록 조회 (필터: `status=pending|approved|rejected`)
  - `POST /api/v1/admin/data-imports/{import_id}/decisions`: `{ "decision": "approve"|"reject", "comment": string, "expected_revision": int }` (SOD 검사: requester == approver 시 403 차단)
- **DB 스키마 및 보안 함수 계약 (`041_rbac_capabilities_and_data_import.sql`)**:
  - 테이블: `portal.data_imports` (OWNER `ai_owner`, FORCE ROW LEVEL SECURITY)
  - 감사 이벤트: `ops.audit_events`에 `data_import.request`, `data_import.decide` 원자적 기록
  - 보안 함수: `security.data_import_request`, `security.data_import_decide`, `security.data_import_list` (SECURITY DEFINER, strict search_path)
