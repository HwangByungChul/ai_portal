# 시연 비교 자료 재검토와 개발 범위 조정안

**검토 의견: 기존의 멀티테넌트·호출 통제·규정 RAG를 기반으로 확장할 수 있습니다. 시연 전체 범위를 구현하려면 화면과 함께 새로운 업무 데이터/API/권한 정책을 개발해야 합니다.** 제공된 자료의 “백엔드90% / 화면70% / 완료16개”를 개발 완료율로 사용하지 않습니다. 이번 검토는 날짜·마감·기간 산정 없이 범위, 우선순위, 선행 관계와 완료 기준을 제시합니다.

자료: [[05 시연 화면과 구현 기능 비교 분석 보고서]], [[06 제안 시연 전체 화면(36종) 대비 기능 비교 분석]]. 기존 두 문서는 원본으로 보존하고, 재분류와 추진 검토는 본 문서 및 [[08 기능 중심 단계별 개발 추진 검토안]]에서 관리합니다. 현재 구현의 기준은 소스 HEAD `1daf4f7db309b36796527343da6e164710907f11` 및 [[13 잔여 1~6 작업 검증과 화면 검토 준비 결과]]입니다.

“확인 안 됨”은 본 검토의 앱·공통코어·migration·의존성·등록 API 범위에 한정합니다. 다른 저장소의 기능을 현재 앱에 연동한 것으로 간주하지 않습니다. 이번에는 새 실행 시험이나 유료 호출을 하지 않았습니다.

## 2. 시연 파일 기준

원본 `04.시연` 최상위에 PNG36개, `2차`에6개가 있습니다. 최상위는 번호 화면34개와 Home 변형2개입니다. 두 Home은 파일명과 SHA가 다르며, 2차 Home은 최상위 Home 중 하나와 SHA가 같습니다. 따라서 **35개의 화면 의미와 파일별 변형/개정판을 구분**해야 합니다. 2차 화면이 있다는 이유만으로 자동으로 모두 승인된 최종본으로 선택하지 않습니다. 첫 요구정의 작업에서 화면별 채택본을 명시합니다.

파일 목록·SHA와 두 입력 문서·현재 소스 기준은 [검토 근거](evidence/20261006-demo-development-review/review-evidence.json)에 저장했습니다. 파일 전수 집계와 코드 대조를 했으며 PNG42개 모두의 시각 디자인 수용 시험을 했다고 주장하지 않습니다. 05의 가이드 챗봇/회의 패널은8대 시나리오 요구로 별도 추적합니다.
