# 상세 수정 재검토 F1~F8 잔여 결함 보완 작업 계획서

**Goal:** 재검토 F1~F8의 실제 운영 배선·영속 실행·정보 표시 결함을 수정하고 단계별 HTTP/실행 관리자/DB/브라우저 수용으로 확인한다.

**Architecture:** 기존 인증 context, tenant_transaction/security capability, 정확한 승인 publication, RunTicket/Gateway/정산 원장을 유지한다. 로컬 엔진 단위시험만 추가하는 대신 main→manager→provider→저장/stream, 승인→실행, 관리정책→실행 검사 경로를 실제로 연결한다.

**Tech Stack:** 현 Python/FastAPI/PostgreSQL/React/TypeScript/Vite/Playwright. 새로운 외부 프레임워크가 필요하지 않다.

**Spec:** [[2026-10-13 상세 수정 계획 이행 및 추가 개발 재검토]], [[26 추가 개발 결함 보완 및 실서비스 실행 계약 상세 계획]], [[23 포털 UI UX 확정과 사이트 분리 검토]], [[27 포털 High-End UI UX 전면 개편 및 듀얼 아이덴티티 상세 구현 계획]].

**실행:** 이번 요청은 작업 계획서 보고이며 개발·DB 적용·유료 모델 호출은 수행하지 않는다. 기존 계획26을 폐기하지 않고 실제 재검토의 잔여와 변경된 소스 기준을 보완한다. 이후 순차 실행하며 각 단위에서 실패 재현→최소 수정→독립 수용→기록 순서를 따른다.

## 1. 계획 작성 시점의 기준선과 범위

### 1.1 최신 코드 반영

이전 재검토 시점에는 manager의delta가hub로전달됐다. 계획작성 시점의현재manager는private_chunks를수집한뒤최종body를hub에전달한다. 따라서‘모든일반대화가여전히chunk원문을직접보낸다’는과거판정을현재코드에그대로확대하지않는다. 새버퍼는코드진척이며이번에는전체SSE를재시험하지않았다.

현재남은확인: Gateway다른호출자의delta안전, buffer UTF-8 byte제한, 결과저장/현재권한검사보다앞선hub공개, stream/저장일치, RAG/summary/trial/Workflow개별경로. F1작업은이미추가된버퍼를중복구현하지않고정확한완료순서와실제수용을보완한다.

다른핵심소스도확인했다. manager는GLOBAL_ROUTER 기본, main은mode/key를담은router를주입하지않음; engine은_CURRENT_POLICY; toolcache는client ID→hash; Overview정상상수와독립admin앱kind누락은남아있다. 이번내용은새실행시험결과가아니라계획작성용코드확인이다.

- SQL000~043은보존한다. 신규044이상만추가하며구현전실제최신번호를확인한다. 기존042/043을수정해이미적용된DB와소스지문을어긋나게하지않는다.

### 작업 계약

- privatebuffer의총량은UTF-8 byte누적계수로제한한다. 현재sum(len(text))는문자수이며반복합산이라바이트상한과다르다. 상한은기존provider출력/서비스32768byte범위와일치시킨다.
- 일반대화흐름은입력/자료권한→dispatch/meter→출력검사→현재권한으로DBfinish→공개순서다. finish거부/저장실패에는hub에답변을추가하지않는다.
- DBfinish와stream공개사이의권한회수는stream읽기gate에서다시거부한다. 임시delta에단계/심박만표시하고원문은공개하지않는다.
- Gateway중앙은다른caller가unsafe on_delta를넘겨도검사전private수집만하도록계약을확정한다. 안전한최종body만노출하고receipt를손상시키지않는다.

안전한실행순서의구현예시:

```python
outcome = await gateway.execute(ticket, collect_private_delta)
if outcome.body is not None and outcome.safe_error_code is None:
    saved = await repository.finish(ticket, outcome.body)
    if saved:
        hub.append(ticket.run, outcome.body)
    else:
        hub.clear(ticket.run)
```

- [ ] 실제manager와Gateway를통과하는spyprovider로PII를두chunk로나눠반환한다.
- [ ] UTF-8초과/금지문/부분실패/timeout/cancel/철회/finish실패를시험한다.
- [ ] SSE, pollingJSON, 저장메시지, trial/Workflow결과에원문0/마스킹일치·실제발생비용보존을단언한다.
- [ ] 기존빈received_from_hub배열단언을실제SSE소비또는hub관찰로교체한다.
- [ ] 결과와바이트상한/진행상태UX를기록한다.

**완료:** 거부/저장실패의최종답변공개0, 검사전원문0, 허용body저장/stream일치, 취소해도이미발생한비용보존.
