# DP18-19 전 과정 가드레일 및 보호 정책 상세 구현 계획
## 목표
사용자 입력(프롬프트)과 AI 출력(답변)에 대한 **실시간 콘텐츠 보호 정책 엔진**을 구현한다. PII 탐지, 금칙어/프롬프트 인젝션 차단, 출력 필터링, 정책 버전 관리, 위반 감사 원장을 통합하여 전 과정 안전성을 확보한다.

## 범위 한정
- **구현 대상**: 입력 가드레일(프롬프트 필터), 출력 가드레일(답변 필터), 정책 레지스트리, 위반 감사 원장, 관리 화면
- **DRM/DLP 어댑터**: 계약 인터페이스만 정의하고 실제 기관 연동은 후속 (기관 DRM/DLP 환경 확보 후 별도 증적)
- **기존 보존**: `document_ingest.py` (문서 수집 정책)의 PII/인젝션 룰은 유지하며 새 엔진과 공유

## 구현 항목

### Task 1: 가드레일 정책 엔진 (백엔드)
- `src/backend/app/guardrails/engine.py`:
  - `GuardrailPolicy` 데이터클래스: `policy_id`, `revision`, `rules` (PII/금칙어/인젝션/출력 필터 각 ON/OFF), `severity` (block/warn/log), `scope` (input/output/both)
  - `GuardrailEngine.evaluate_input(text) -> GuardrailResult`: 입력 검사
  - `GuardrailEngine.evaluate_output(text) -> GuardrailResult`: 출력 검사
  - 기존 `document_ingest.py`의 PII/인젝션 패턴을 재사용하되 프롬프트/답변 전용 금칙어 룰 추가
  - 금칙어: 폭력/차별/성적 표현/불법 행위 안내 패턴
  - 출력 필터: PII 마스킹 (주민번호→`***-*******`), 계좌번호 마스킹
- `src/backend/app/guardrails/audit.py`:
  - `log_violation(tenant_id, user_id, direction, rule_ids, text_hash, policy_revision)`: 위반 감사 기록 (원문 미저장, SHA256 해시만 보존)
- `src/backend/app/guardrails/routes.py`:
  - `GET /api/v1/admin/guardrails/policies`: 현재 정책 조회
  - `PUT /api/v1/admin/guardrails/policies`: 정책 갱신 (PADMIN 전용, CAS revision)
  - `GET /api/v1/admin/guardrails/violations`: 위반 목록 조회 (커서 페이징)

### Task 2: Gateway 파이프라인 통합
- `AiGateway.execute` 흐름에 입력 가드레일 삽입: `evaluate_input` → 차단 시 `GUARDRAIL_INPUT_BLOCKED` 반환
- `ExecutionManager._run` 흐름에 출력 가드레일 삽입: 답변 저장 전 `evaluate_output` → 차단 시 `GUARDRAIL_OUTPUT_BLOCKED`, warn 시 마스킹 후 저장
- 문서 요약/RAG 실행에도 동일 가드레일 적용

### Task 3: 프론트엔드 관리 화면
- `src/frontend/src/GuardrailPolicyPage.tsx`: 관리자 가드레일 정책 대시보드
  - 현재 정책 규칙별 ON/OFF 토글, 심각도 설정, 정책 리비전 표시
  - 위반 이력 테이블 (방향/규칙/시각/해시, 원문 미표시)
- `admin-web/src/App.tsx`: 네비게이션에 '보호 정책' 메뉴 등록

### Task 4: 수용 테스트
- `test_dp18_dp19_acceptance.py`: 4건
  - C01: 입력에 PII(주민번호) 포함 시 `GUARDRAIL_INPUT_BLOCKED` 반환
  - C02: 입력에 프롬프트 인젝션 시도 시 차단
  - C03: 출력에 PII 포함 시 마스킹 적용 후 저장
  - C04: 정책 관리 API PADMIN 전용, CAS revision 충돌 검증

### Task 5: 빌드 검증 및 기록
- `build:user`, `build:admin` 코드 경계 검증
- `test:config` 19/19 유지
- 작업 기록 갱신

## 기술 제약
- 기존 SQL000~041 수정 금지 (가드레일 정책은 인메모리 레지스트리 + 감사만 DB)
- 감사 원장은 기존 `ops.audit_events`에 `guardrail_violation` 유형으로 추가 (새 테이블 불필요)
- 원문 텍스트는 감사 원장에 저장하지 않음 (SHA256 해시만 보존)
- `document_ingest.py`의 기존 룰 ID(`PII_RRN`, `PII_PHONE`, `PII_EMAIL`, `PII_ACCOUNT`, `PROMPT_OVERRIDE`)를 가드레일 엔진에서 재사용
