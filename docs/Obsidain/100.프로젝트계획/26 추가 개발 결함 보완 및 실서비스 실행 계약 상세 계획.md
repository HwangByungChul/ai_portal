# 추가 개발 결함 보완 및 실서비스 실행 계약 상세 계획

**Goal:** 독립 검토 R1~R7을 수정하고 추가 Agent·Workflow를 인증·승인·자료 권한·모델·정산·감사 계약을 갖춘 실제 서비스 구현으로 전환한다.

**Architecture:** 기존 FastAPI context, PostgreSQL tenant_transaction/security capability, 승인 publication, RunTicket/AiGateway/실행 관리자/사용량 원장을 재사용한다. 신규 정책과 실행 정보는 조직·소유자 범위를 가진 영속 원장과 불변 snapshot으로 저장한다. React A/A/B 방향을 유지하며 운영 상태는 검증된 API 데이터로만 표시한다.

**Tech Stack:** 현재 Python/FastAPI/Pydantic/PostgreSQL/React/TypeScript/Vite/Playwright를 사용한다. 새로운 외부 프레임워크 도입은 전제하지 않는다.

**Spec:** [[2026-10-13 추가 개발 독립 검토 보고서]], [[23 포털 UI UX 확정과 사이트 분리 검토]], [[13 승인 A안과 실제 React 사용자 화면 차이 검토]], [[14 관리 A 홈과 B 승인 패널 실제 앱 차이 검토]].

**실행 방식:** 순차 실행용 계획이다. 각 작업을 재현 시험→최소 수정→검증→증거·문서 기록으로 마무리한다. 이번 요청은 계획 작성이며 앱 수정·DB 적용·배포는 수행하지 않는다. 별도 에이전트/스킬의 가용성을 실행 전제로 삼지 않는다.

## 8. T4 · 출력 전달 전 검사（R4）

**수정:** ai/gateway, execution/manager/stream, guardrails/service. **시험:** test_remediation_output_gate.py 및 기존 실행/취소·브라우저 시험.

**초기 방안:** 전체 결과를 제한된 private buffer로 수집하고 진행 중에는 단계/심박만 전달한다. 검사 후 안전한 최종문만 한 번 공개한다. chunk 경계를 넘는PII 때문에 정규식만으로 조각별 검사를 구현하지 않는다. 버퍼는 로그/디스크에 저장하지 않으며 출력한도 초과는 중지·비용 보존한다.

```python
chunks = []
async def collect_private_delta(text: str):
    chunks.append(text)  # 승인된 byte 상한을 검사하고 hub에는 전달하지 않음
outcome = await provider.generate(claim, ticket.messages, collect_private_delta)
# outcome.body만 최종 검사의 출처로 사용한다.
# 검사 전 hub/메시지/클라이언트에는 원문을 공개하지 않는다.
```

- [x] 두chunk로 나뉜 합성PII provider 시험에서 검사 전hub출력0, mask후SSE/JSON/저장문에 원문0을 검증한다.
