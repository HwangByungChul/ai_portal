# 10월 말 MVP 목표 일정과 WBS

## 일정 기준

사용자가 2026-10-04 지시한 **10월 말 완료 목표를 2026-10-31**로 해석한다. 검토 기간은 10월 4~31일, 28일이다. 사용자는 주당 20시간 이상 투입 가능하다고 답했다. 계획 기준은 주 20시간 × 4주 = **80시간**으로 둔다. 이는 가용시간의 예산이며 작업별 실측 공수나 일정 달성 보장은 아니다. 모델 환경은 OpenAI API 사용 예정으로 확인했다. API 실습 예산은 최대 30,000원이다. 구체 모델·API 사용 가능 여부는 기술 검토 시 확인한다.

현재 **250.구현 / I250-3 문서·GraphRAG 구현** 단계다. C01 저장·현재 권한 기반까지 완료했으며 다음은 C02 원문 파싱·청킹·규칙 Graph다. 아래 주차/목표 날짜는 초기 계획으로 유지하고, 실제 상태는 마지막 「2026-10-05 실적 현황」을 기준으로 확인한다. 아래 날짜가 도래하는 것만으로 다음 단계 구현이 승인되거나 완료되는 것은 아니다.

## 가용시간과 예비 배분

사용자 확인: 주 20시간 이상. 초과 투입을 일정 성립의 전제로 삼지 않고 우선 주 20시간만 배분한다. 학습·대화형 설계 검토·문서 작성·시험·결함 수정도 이 시간 안에 포함한다.

| 기간 | 예비 배분 | 합계 |
|---|---|---|
| 10/04~10/10 | 계획·구조/요구·분석·첫 설계 16h + 진행 관리 2h + 조정 여유 2h | 20h |
| 10/11~10/17 | 기본 포털·공통 진입·AI 호출 18h + 모듈 검증 2h | 20h |
| 10/18~10/24 | GraphRAG·문서·근거·파일럿 16h + 격리/색인 검증 4h | 20h |
| 10/25~10/31 | 통합 검증 6h + 이행·문서·완료보고 6h + 결함 수정/조정 여유 8h | 20h |
| 전체 | 기능·검토·검증 70h + 조정 여유 10h | **80h** |

이 배분은 계획 검토용이며 검토 대기시간은 작업시간과 구분한다. 문서 관리·검증은 표의 관련 작업에 포함하며 400 대장은 작업과 함께 갱신한다. 초기 배정한 시간에 기능이 끝나지 않으면 실측 소요와 남은 작업을 기록해 중간 점검의 축소 기준을 적용한다.

## 중간 점검과 범위 조정 기준

- **10/10:** 첫 기능 명세와 구현계획이 준비되지 않으면 구현 완료일을 기계적으로 유지하지 않는다. 사유·가용시간·축소안을 기록한다.
- **10/17:** 실제 채팅·기록·조직 검사·중지/한도가 연결되지 않으면 화면 옵션·통계 장식·관리 CRUD의 편의 기능을 먼저 축소한다.
- **10/24:** GraphRAG 색인·근거·격리 파일럿이 동작하지 않으면 문서 형식/수와 도메인 관계 종류를 줄여 최소 흐름에 집중한다.
- **10/28:** 신규 기능 추가를 멈추고 핵심 결함·재현·시연 정리에 집중한다. 권한 우회·근거 오연결·데이터 소실은 미해결 상태로 완료 표시하지 않는다.

논리 격리, 본인 기록 분리, 허용 근거만 인용, 삭제 반영, 실제 사용량 상태는 유지한다. 시간 부족 시 복잡한 승인·프롬프트 편집·통계 시각화·내보내기 등 편의 범위를 줄인다. 핵심 범위가 남으면 10/31 완료보고에 미완료와 후속 작업을 명시하며 임의로 목표를 달성했다고 표시하지 않는다.

## 10월 말 검증 기준

1. 조직 A/B 계정의 문서·대화·Agent·관리 기능을 직접 ID/URL로 접근해도 권한이 강제된다. 동시 요청·비동기 색인에서 조직 문맥이 섞이지 않는다.
2. 일반/RAG Agent가 공통 AI 호출 경로로 실제 응답하고 실패·취소·한도 초과·중지 상태를 조회할 수 있다.
3. 관계와 원문 근거가 정확히 매칭되며 권한 없는 근거는 응답과 링크에 나타나지 않는다.
4. 프로세스 재시작 후 계정·대화·색인·실행 이력이 유지되고, 삭제 문서는 재검색되지 않는다.
5. 예상 질문 20개(단일 문서6·관계6·근거 부족4·권한 거부4)의 정답/허용 근거와 실측 결과를 기록한다. 조직 우회가 허용되거나 근거가 교차 연결되는 결함은 남기지 않는다. 일반 답변 품질 결과는 성공·실패 그대로 보고한다.
6. 설치·데이터 초기화·시연 순서를 따라 재현할 수 있고 최종 산출물에 실제 검증 증거가 연결된다.

실제 모델을 사용할 수 없으면 모의 기능의 검증 결과를 별도 기록하고 실제 모델 항목은 미완료로 남긴다. OpenAI API 사용 가능 여부·단가·사용량 통제는 실제 호출 전에 확인한다. 기관 운영 적합성·물리 격리·SSO·DRM·HA 검증은 이번 완료 주장에 포함하지 않는다.
