# 사용자 관리자 독립 앱과 빌드 분리 실행 계획

사용자가 다음 단계 진행을 승인했다. [[100.프로젝트계획/12 사용자 관리자 사이트 분리와 상용 이행 설계]]의 2단계를 실행한다. 기존 실제 앱 통합 결과21과 시험22는 이전 단계 증거다.

## 구현 순서

1. 현재 변경 상태·대상 파일의 SHA를 고정하고 변경 전 파일을 사적으로 보존한다. 새 runtime 의존성·별도 lock을 추가하지 않고 기존 frontend lock으로 두 빌드를 재현한다.
2. `src/frontend/apps/user-web/src`와 `apps/admin-web/src`에 각각 App/main/index 진입점을 만든다. 사용자 홈·개인 업무와 관리자 홈·승인·관리 화면을 정적으로 다른 그래프로 연결한다.
3. `packages/api-contract/src`에 기존 types/api/session 구현을, `packages/ui/src`에 기존 scoped/LoginPage/TenantHeader/스타일과 공통 인증·레이아웃을 옮긴다. 기존 `src`는 같은 canonical 모듈을 re-export하여 단일 SessionStore를 유지한다.
4. 공통 문서·사용량·Job 화면의 관리 분기를 사용자 빌드에서 제거한다. 사용자 빌드는 관리 전용 화면·공유·한도 변경 코드를 포함하지 않게 build module graph와 번들 검증을 추가한다. 관리자 화면은 서버 권한 검사를 그대로 사용한다.
5. 사용자 `/user/home`, 관리자 `/manage/admin`을 로컬 같은 출처5173에서 제공한다. 과거 `/home`·`/workspace`·`/admin`은 기존 호환 앱으로 유지한다. 새 앱은 서로 이동할 때 전체 페이지로 이동하여 인증을 재확인한다. 쿠키·Origin·CSRF·API 서버는 변경하지 않는다.
6. `build:user`/`build:admin`의 독립 outDir, 빌드 manifest/모듈 지문과 경계 검사·전체 두 빌드 명령을 추가한다. 산출물은 각각 index.html과 assets를 가진다. 현재 하위 경로 정적 호스팅 계약을 README에 남긴다.
7. 격리 DB로 새 사용자/관리자 로그인·권한·직접 주소·화면 이동·승인·개인 문서·모바일·로그아웃과 기존 핵심 회귀를 시험한다. 소유 서비스만 정지하고 시험 후 정상 복구한다. 이번 변경은 backend 업무 코드·DB 이행을 변경하지 않는다.
8. 실행 결과·초기 실패/수정·source SHA·빌드 경계·시험 결과를 Obsidian에 기록하고 계획12/설계23/작업로그02/안내에 연결한다.
