# 프로젝트계획서

## 1. 목표·제약과 MVP 범위

개인적으로 AI 통합 플랫폼을 직접 학습·구축하고 향후 유사 사업 제안·시연에 활용한다. 목표일은 2026-10-31, 사용자 가용시간은 주 20시간 이상이다. 기본 계획은 4주 80시간이며 학습·문서·검증·결함 수정 여유를 포함한다. 실측 완료시간 보장은 아니다.

실제 모델은 OpenAI API를 사용한다. **10월 API 실습 예산은 최대 30,000원**이다. 생성·문서/질의 임베딩·LLM 추출(사용 시)·실패/재시험 호출을 합산한다. 별도 인프라 지출은 이 결정에 포함되지 않았으며 비용 발생 전에 검토한다. 구체 모델·원화 환산·단가/사용량 통제는 210/240에서 설계하고 실제 호출 전에 확인한다.

| 사용자 포털 | 관리자 포털 | 공통 기반 |
|---|---|---|
| 로그인·조직 선택·Agent 선택·채팅·본인 기록·문서 근거 조회 | 사용자/조직 역할·문서 등록/색인 상태·Agent 설정/중지·사용량/한도 조회 | 논리 멀티테넌트·API 공통 진입·AI 호출 통제·GraphRAG·DB 지속 저장 |

가상 조직 A/B, 일반 질의 Agent와 합성 규정/책무 RAG Agent의 고정 흐름을 범위로 정한다. 합성 TXT/Markdown 문서 5~10개와 예상 질문 20개로 시작한다. 공통 자산은 승인된 공개 범위로만 접근한다. 기업 SSO·조직별 독립 실행환경·GPU 운영·자유형 Builder·MCP·전체 Marketplace는 후속 범위로 둔다.

**검토 항목 1 승인:** 2026-10-04 사용자가 제시한 10월 MVP 범위와 핵심 완료 기준에 “네”로 답변했다. 1항의 범위·목표일·가용시간·API 예산 및 핵심 완료 기준을 계획 기준으로 기록한다. 2~5항과 상세 기술 설계·구현계획은 이 답변으로 승인된 것으로 간주하지 않는다.

## 2. 추진 방식과 시스템 경계

**검토 항목 2 승인:** 2026-10-04 사용자 “네” 답변으로 React/Vite + 통합 FastAPI + PostgreSQL + 기존 GraphRAG 코어와 API 공통 진입/AI 호출/플랫폼 업무의 책임 분리 방식을 승인했다. 상세 모델·DB 격리 구현은 210/240에서 구체화한다.

비교안은 A(FastAPI 업무 API 내 공통 진입), B(별도 FastAPI 진입 서버), C(Spring Cloud Gateway)다. 비교 근거는 [[100.프로젝트계획/01 프로젝트계획 검토 초안]]에 있다.

검토 결과 **A. FastAPI 통합 공통 진입 방식**을 채택한다. React/Vite 사용자·관리자 화면, FastAPI 업무/공통 진입·AI 호출 모듈, PostgreSQL 지속 저장, 기존 GraphRAG 코어를 연결한다. Middleware는 요청 ID·관측 등 공통 처리, 인증/권한 의존성과 서비스는 사용자·조직·자원 검사를 담당한다. API 공통 진입은 요청·조직·HTTP 제한, AI 호출 모듈은 모델 접근·AI 사용량/한도·실행 상태를 담당한다.

GraphRAG는 문서 처리·벡터/Graph 검색·근거 조립을 담당한다. 플랫폼의 사용자/조직 정책을 입력받고 저장소에서도 이를 강제한다. 기존 미구현 어댑터·권한 미적용·근거 연결 Gap을 보완하며 별도 백엔드의 중복 검색 경로를 통합한다. 이를 통째로 복사하면 완성되는 것으로 판단하지 않는다.

단일 서버에서도 내부 호출을 포함한 조직 검사가 필요하다. 외부 입력 tenant_id만 신뢰하지 않고 로그인 사용자 소속을 서버에서 확인한다. DB 행/스키마 정책·Graph 분리·캐시/Job 문맥의 상세 방식은 210/240에서 결정한다.

## 3. 실행 흐름과 예산 통제

**검토 항목 3 승인:** 2026-10-04 사용자 “네” 답변으로 질의/색인 실행 흐름, 공통 AI 호출, 모의/실제 시험 구분 및 합산 API 예산 통제 원칙을 승인했다. 구체 모델·단가·환산·중지 여유는 후속 설계에서 정한다.

사용자 로그인 → 허용 조직 선택 → 허용 Agent 확인 → 조직/개인 자료 검색 → 허용 근거 조립 → 중앙 AI 호출 → 응답/근거 표시 → 대화·실행·usage 저장 → 본인 기록/관리자 사용량 조회로 이어진다. 일반 질의는 문서 검색 없이 같은 실행/호출 경로를 사용한다.

색인 작업도 사용자/조직/문서 권한 확인 → 파싱/청킹 → 공통 AI 호출을 통한 임베딩/추출 → 조직별 저장 → 검증/색인 상태 갱신으로 이어진다. 질문 시 임베딩이 필요한 경우 검색 전에 공통 AI 경로를 사용한다. 작업은 요청의 조직 문맥을 유지하며 실패 단계는 실패 상태로 남긴다.

모의 모델은 단위/API 흐름 검증에 사용하고 실제 모델은 제한된 대표 시나리오에 사용한다. 파일 해시와 색인 버전을 기록해 변경 없는 자료를 반복 임베딩하지 않는 방안을 설계한다. 질의/응답 길이·동시 실행·재시도 횟수·예상 비용 제한을 둔다. 유료 호출 전 예상 사용량을 확인하고 원장과 대조하며 사용량 불명은 0원으로 처리하지 않는다.

앱 예산 검사는 전용 프로젝트/키의 실제 사용을 대조하는 운영 절차와 연결한다. 앱 내부 추정만으로 공급자 청구액 30,000원 이하를 보장한다고 표시하지 않는다. 호출 원장·단가·환산·세금/수수료 적용 여부를 확인하고 상한 전 추가 호출을 중지할 여유를 설계한다. 자동 충전·추가 결제는 수행하지 않는다.

## 4. 오류·격리·완료 기준

**검토 항목 4 승인:** 2026-10-04 사용자가 오류 처리·논리 격리·근거/삭제·지속 저장·대표 질문 평가 및 핵심 결함 미해결 시 완료 표시 금지 기준에 “네”로 답변했다.

- 인증 실패·조직 미소속·자원 무권한은 실행 전에 거부한다. 메뉴 노출과 API 접근을 따로 시험한다.
- 검색/근거 부족은 답변 보류 또는 근거 부족 상태로 반환한다. 권한 제한을 풀어 재검색하지 않는다.
- 색인 실패는 실제 단계 상태와 오류를 남긴다. Graph 미수행 상태를 완료로 표시하지 않는다.
- 모델 오류·취소·한도 초과·Agent 중지는 실행 상태와 usage 추정/확정/불명을 남긴다. 재시도는 제한하고 중복 원장을 방지한다.
- 재시작 후 대화/조직/색인/원장이 유지되어야 한다. 삭제 문서는 재검색·인용·다운로드되지 않아야 한다.

시험은 반복 가능한 모의 모델/API 검증과 대표 실제 모델 검증으로 나눈다. 조직 A/B 계정, 권한 없는 문서/대화/Agent ID, 관계별 서로 다른 근거를 준비한다. 예상 질문 20개(단일 문서 6·관계 6·근거 부족 4·권한 거부 4)의 기대 결과와 실측을 기록한다. 운영자·조직 관리자도 권한 범위를 구분해 시험하며 동시 요청·비동기 Job·캐시에서 조직 문맥 혼입을 검사한다.

최종 완료는 다음으로 판정한다: A/B 직접 ID/URL 우회 차단, 개인 문서/대화 분리, 동시 요청/Job의 조직 문맥 유지, 관계별 올바른 원문 근거, 실제 모델의 중앙 호출, 관리자 중지·한도 차단, 지속 저장, 초기화/설치/시연 재현, 결함·제약과 실측 결과 기록. 위 핵심 결함이 남으면 해당 범위는 미완료다.

## 5. 일정·산출물과 다음 단계

**검토 항목 5 승인:** 2026-10-04 사용자 “네” 답변으로 4주 일정·80시간 배분·10시간 여유·중간 점검/범위 조정·단계별 진행 방식을 승인했다.

1주차(10/04~10/10) 계획·구조·요구·분석·첫 설계, 2주차(10/11~10/17) 포털/호출 기반, 3주차(10/18~10/24) 지식/GraphRAG·파일럿, 4주차(10/25~10/31) 통합시험·이행·종료를 목표로 한다. 구체 WBS·시간 배분·점검/축소 기준은 [[100.프로젝트계획/02 10월 말 MVP 목표 일정과 WBS]]를 따른다.

계획 내용은 1~5항 각각의 사용자 승인을 반영했으며 문서 전체 최종 검토를 요청한다. 100 완료 후 210→220→230→240으로 상세화하며 250/260은 해당 기능의 설계 검토 및 구현계획 후 진행한다. 기술 상세를 100에서 전부 정하는 방식은 사용하지 않는다.

## 자체 검토 결과

2026-10-04 다음 항목을 대조했다.

- 빈 요구·자리표시자: 목표·범위·시간·예산·완료 기준을 명시했다. 구체 모델/단가·DB/Graph 격리 기법은 210/240의 상세 검토 책임으로 구분했다.
- 일관성: 단일 서버와 논리 격리, 생성/임베딩 공통 호출, 개인/조직 자료 ACL과 관리자 권한, 3만원 합산 예산 기준을 맞췄다.
- 범위: 10월 MVP는 고정 Agent 2개와 소형 합성 평가셋으로 제한한다. 기관 운영 적합성·물리 격리·SSO·GPU·자유 Builder는 후속 범위다.
- 일정: WBS의 4주 배분 합계는 80시간이며 이 중 조정 여유는 10시간이다. 실측 공수 보장은 아니다.
- 승인 상태: 1~5항은 항목별 승인 완료. 이 문서 전체의 최종 검토는 요청 중이며 앱 구현은 미착수다.
