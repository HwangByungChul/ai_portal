# DP13 모델 레지스트리 및 다중 모델 계약 상세 구현 계획
본 계획서는 OpenAI 단일 고정 모델 구조를 탈피하여, 다양한 LLM 제공자(OpenAI, Mock 등)의 모델을 체계적으로 등록·검증·호출하고 가격 스냅샷 및 예산 통제를 일원화하는 DP-13 다중 모델 계약을 구현하기 위한 상세 계획입니다.

## 1. 배경 및 목표
- **임의 모델 및 Key 주입 차단 (DP-13-C01)**: 클라이언트가 임의의 모델명, 제공자, API Key를 페이로드에 전달하는 것을 엄격히 차단하며, 서버에 사전 등록된 `model_id`만 수용합니다.
- **미승인 모델 실행 금지 (DP-13-C02)**: 비활성화(`enabled=False`) 상태이거나 권한 범위를 벗어난 모델에 대한 호출 요청은 실행 전 검증 단계에서 즉시 거부(`MODEL_NOT_PERMITTED`)합니다.
- **다중 모델 가격 스냅샷 및 원장 정합성 (DP-13-C03)**: 모델별 입력·출력 토큰 단가를 반영한 가격 스냅샷(`PriceSnapshot`)을 동적으로 적용하고, 호출 전 예약(`reservation_krw`) 및 호출 후 실측 정산(`cost_krw`)의 안전성을 보장합니다.
- **게이트웨이 외 직접 호출 금지 (DP-13-C04)**: 모든 Provider 호출은 반드시 `AiGateway`의 단일 허가증 발급(`reserve`) → 발사(`dispatch`) → 영수증 정산(`settle`) 흐름을 강제합니다.

## 2. 인터페이스 및 계약 설계
- **모델 참조 DTO (`ModelRef`)**:
  - `model_id`: 식별자 (예: `gpt-4o-mini`, `gpt-4o`, `mock-general`, `mock-advanced`)
  - `provider_key`: 제공자 구분 (`openai`, `mock`)
  - `model_name`: 실제 엔진 명칭
  - `credential_ref`: 서버 환경변수/비밀 설정 참조 키 (클라이언트 응답 절대 제외)
  - `pricing_version`: 가격표 식별자
  - `input_usd_per_million`: 입력 100만 토큰당 USD
  - `output_usd_per_million`: 출력 100만 토큰당 USD
  - `context_window`: 최대 입력 문맥 토큰
  - `max_output_tokens`: 최대 생성 토큰
  - `enabled`: 활성화 여부
  - `capabilities`: 지원 기능 목록 (`chat`, `rag`, `structured`)
- **모델 해석기 (`resolve_model`)**:
  - 요청된 `model_id`를 검증하고, 미지정 시 시스템 기본 모델(`DEFAULT_MODEL_ID = 'gpt-4o-mini'`)로 안전하게 fallback 바인딩 반환
  - `credential_ref`를 바탕으로 런타임 Provider를 매핑하여 `AiGateway`에 전달
- **API 엔드포인트 계약**:
  - `GET /api/v1/models`: 일반 사용자/작성자가 조회 가능한 활성 모델 메타데이터 목록 (비밀 제외)
  - `GET /api/v1/admin/models`: 관리자용 전체 모델 목록 및 상태 조회
