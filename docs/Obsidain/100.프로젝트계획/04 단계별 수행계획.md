# 아키텍처 검토 및 단계 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 승인된 프로젝트계획을 210 아키텍처 검토부터 단계별로 구체화하고 구현계획의 입력을 확정한다.

**Architecture:** 사용자/관리자 공통 프론트, 통합 FastAPI의 업무·API 진입·AI 호출 모듈, PostgreSQL과 GraphRAG 코어를 사용한다. 논리 멀티테넌트와 공통 AI 호출 경계가 모든 단계의 기준이다.

**Tech Stack:** React/Vite, FastAPI, PostgreSQL, 재사용 GraphRAG 코어, OpenAI API.

**Spec:** [[100.프로젝트계획/03 프로젝트계획서]].

## Global Constraints

- 목표일은 2026-10-31, 사용자 가용시간은 주 20시간 이상이다.
- 기본 계획은 4주 80시간이며 학습·문서·검증·결함 수정 여유를 포함한다.
- 10월 API 실습 예산은 최대 30,000원이다.
- 정식 산출물은 사용자 지정 docs/Obsidain의 프로젝트 단계 폴더에서 관리한다.
- 상세 설계·기능별 구현계획 전에 앱 코드 구현을 시작하지 않는다.

## 적용 범위

writing-plans를 적용했다. 승인된 명세는 전체 프로젝트계획 수준이며 코드의 API/DB 상세 명세는 아니다. 사용자가 산출물 단계 순서로 검토하도록 지정했으므로 이번 계획은 **210의 실행 가능한 문서 검토 작업**에 한정한다. 전체 제품을 구현하는 상세 코드 계획이 완료된 것으로 표시하지 않는다.

구현 계획은 240의 상세 명세를 입력으로 다음 독립 검증 단위별로 작성한다: ①조직/사용자 권한과 지속 저장 ②포털·대화/운영 API ③AI 호출·usage/한도 ④문서/GraphRAG·근거/삭제. 각 단위는 앞선 계약을 소비하고 실제 시험 가능한 결과를 만든다. 지금 임의의 함수·테이블·모델 버전을 확정하지 않는다.

단계 순서와 100 명세를 대조했다. 각 문서 작업은 입력·결과·검토 조건을 가진다. 신규 코드·함수 서명을 설계 승인 없이 고정하지 않는다. 전체 앱 구현계획의 완성을 주장하지 않는다. 실행은 현재 대화에서 단계별로 진행하며 사용자 요청 없이 다른 채팅을 생성하거나 메시지를 보내지 않는다.
