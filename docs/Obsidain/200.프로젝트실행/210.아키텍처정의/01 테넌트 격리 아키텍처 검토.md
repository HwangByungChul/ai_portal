# 테넌트 격리 아키텍처 검토

## 입력과 결정 범위

[[100.프로젝트계획/03 프로젝트계획서]]는 확정되었다. 공통 서버·가상 조직 A/B·개인/공유 문서·직접 우회 차단이 기준이다. 이번 결정은 논리 격리의 저장소 구조이며 실제 테이블/SQL/API 명세는 240에서 정의한다.

## 세 가지 방식

| 방식 | 구조 | 장점 | 관리 부담·제약 | 판단 |
|---|---|---|---|---|
| A 공통 테이블 | 공통 DB/테이블의 tenant_id와 문서 ACL, 앱 검사와 DB RLS | 단일 마이그레이션·원장/검색 구조 활용, 개인 MVP 부담 감소 | tenant 조건/정책·연결 풀·쓰기·Graph 모두 일관되게 검증 | **권고** |
| B 조직별 스키마 | 같은 PostgreSQL 안에서 A/B 스키마·접근 역할 분리 | 조직 데이터 이름공간 분리가 명확 | 스키마별 변경·연결/권한 관리, 공유 자산 경로 복잡 | 확장 후보 |
| C 조직별 DB | 공통 서버에서 A/B 데이터베이스 연결 분리 | 저장소 경계가 명확 | DB별 계정·이행/백업·연결 관리, 공통 자산·원장 복잡 | 이번 4주 MVP의 우선안 아님 |

비교는 개인 일정과 기존 재사용 구조에 대한 검토 의견이다. 모두 인증/조직 소속/개인 자원 ACL은 별도로 필요하다. 스키마나 DB 분리가 자동으로 사용자 권한을 완성하지 않는다.

## A 권고안의 적용 기준

1. 서버가 로그인 사용자·활성 소속을 확인해 한 요청의 활성 테넌트를 결정한다. 브라우저가 보낸 조직 ID는 선택 요청이며 권한 증명이 아니다.
2. 플랫폼 서비스와 GraphRAG 어댑터는 조직 조건과 개인/공유 ACL을 강제한다. DB RLS는 행 읽기/쓰기의 추가 방어 계층이다.
3. RLS 사용 시 런타임 계정은 superuser/BYPASSRLS/테이블 소유자가 아닌 역할로 설계한다. 정책과 역할을 실제 조회·쓰기 시험으로 확인한다. 누락된 조직 문맥은 기본 거부한다.
4. DB 연결 풀의 이전 요청 문맥이 재사용되지 않도록 트랜잭션 단위의 조직 문맥 설정·종료와 예외 정리를 설계한다. Worker는 인증된 Job에 기록된 조직/주체와 자체 세션으로 작업한다.
5. 문서·청크·개체·관계·근거·근거 링크의 모든 조회/쓰기/삭제는 조직 경계에 묶는다. 도메인명 또는 workspace category만으로 조직 권한을 대체하지 않는다.
6. 개인 자료는 같은 조직에서도 소유자/허용 대상 ACL을 추가 확인한다. 조직 격리만으로 개인 자료 보호가 완성되지 않는다.
7. 파일 경로·캐시 키·Job·실행/사용량 원장에 조직 경계를 유지한다. 링크와 다운로드도 서버 권한 검사를 통과한다.
8. 그룹 공유는 승인된 특정 자산 버전과 수신 조직 Grant로 표현한다. 모든 조직 문서를 함께 읽는 전역 우회 권한으로 구현하지 않는다. 철회 후 신규 검색/인용/다운로드 권한을 재검증한다.
9. 조직 관리자도 요청 조직 범위 안에서만 관리한다. 그룹 관리자는 조직을 명시적으로 선택해 처리하고 활동을 기록하며 무조건 RLS를 우회하는 런타임 계정으로 운영하지 않는다.

## 공식 기능 근거와 한계

PostgreSQL RLS는 행의 조회·삽입·수정·삭제에 정책을 적용할 수 있다. RLS가 활성화되고 적용할 정책이 없으면 기본 거부하며 superuser/BYPASSRLS와 통상 테이블 소유자는 우회한다. 그러므로 활성화만 확인하지 않고 런타임 역할과 읽기/쓰기 정책을 함께 시험해야 한다. [PostgreSQL 공식 문서](https://www.postgresql.org/docs/current/ddl-rowsecurity.html), 확인 2026-10-04.

이 문서는 SQL/코드 구현이나 격리 시험 결과가 아니다. 기존 GraphRAG 메모리 어댑터의 AuthContext 미적용과 DB 어댑터 골격은 [[개발/AI 통합 포털/06 GraphRAG 재사용 검토]]의 Gap이다. 이를 보완하지 않으면 A를 채택해도 실제 격리가 성립하지 않는다.

## 후속 시험 입력

- 조직 A로 B의 문서/대화/Agent ID를 요청하면 거부.
- 조직 A 내에서도 타인의 개인 문서/기록은 거부.
- 런타임 DB 역할에서 조직 조건이 누락된 조회·쓰기의 정책 강제 확인.
- A/B 동시 요청·실패/rollback·연결 풀 재사용·색인 Worker에서 문맥 혼입 없음.
- Graph seed/관계/근거/원문 링크가 권한 범위를 벗어나지 않음.
- 공유 승인/철회와 관리자 조직 전환 후 동일 권한 적용.

2026-10-04 사용자 답변 “1”에 따라 **A. 공통 테이블 + 서버 권한 검사 + DB RLS**를 채택했다. 상세 테이블·정책 SQL·인덱스·마이그레이션은 240 단계 산출물로 정의한다. 아키텍처 결정의 승인으로 실제 격리 구현/시험 완료를 의미하지 않는다.
