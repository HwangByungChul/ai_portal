# 시스템과 모듈 경계 정의서

## 기준과 배포 단위

[[100.프로젝트계획/03 프로젝트계획서]]와 승인된 [[200.프로젝트실행/210.아키텍처정의/01 테넌트 격리 아키텍처 검토]]를 입력으로 한다. 1차 MVP의 배포는 React/Vite 화면, 통합 FastAPI 서버, PostgreSQL을 기준으로 한다. 모듈별 독립 서버를 처음부터 만들지 않는다. 색인 작업은 업무 API 요청과 별도 Job 실행 문맥/DB 세션을 사용하며 별도 배포 여부는 후속 실행환경에서 결정한다.

문서의 경로는 후속 코드 구성 기준안이며 아직 실제 파일/모듈은 생성하지 않았다. 자세한 함수·테이블·API/상태 계약은 240에서 정의한다.

## 모듈의 책임과 입력/출력

| 모듈·후보 경로 | 책임·소유 상태 | 소비하는 입력 | 제공하는 출력 |
|---|---|---|---|
| 사용자/관리 UI: src/frontend | 화면·조직 선택·폼·실행 상태 표시 | 권한별 메뉴/업무 API·응답/근거·usage | 로그인/조직 선택·업무 요청. 서버 키와 권한 판정은 보유하지 않음 |
| API 공통 진입: src/backend/app/api | 인증 확인·조직 소속·요청 ID·HTTP 요청 제한·공통 오류 | 인증정보·선택 조직·요청 | 확인된 요청/주체/조직 문맥. 개인 자원 허가는 업무 서비스와 함께 검사 |
| IAM/Tenant: src/backend/app/modules/iam_tenant | 계정·활성 소속·역할·조직 정책 | 인증 결과·조회/변경 요청 | 허용 조직·역할·정책. 로그인용 최소 조회와 조직업무 조회의 권한 경계는 별도 설계 |
| Agent/대화/문서 업무: src/backend/app/modules | Agent 설정/중지·대화·문서/ACL·실행 상태 | 확인 문맥·허용 자원·질의/업로드 | 허용 실행·이력·등록 문서·색인 Job. 다른 조직 관리자 작업을 허가하지 않음 |
| AI 공통 호출: src/backend/app/gateways/ai_gateway | 모델 호출·Timeout/취소·usage 계측·재시도 제한 | 실행 문맥·용도·승인 모델·Payload·예약/허가 결과 | 응답/스트림·Provider ID·usage/불명·호출 종결 상태 |
| Usage/Quota: src/backend/app/modules/usage_quota | 사용자/조직/프로젝트 원장·한도·예약/정산·예산 정책 | 실행/호출·예상 비용·실측 usage·정책 | 호출 허가/거부·예약·정산·관리자 집계. 원장 변경의 단일 책임 |
| GraphRAG 어댑터/코어: src/common_core | 문서 처리·개체/관계·벡터/Graph 검색·근거 조립 | 확인된 조직/ACL 범위·문서/질의·스키마/색인 버전 | 구조화 근거·검색 결과·색인 산출물. 자체 관리자 권한 부여 금지 |
| 색인 Job 실행: src/backend/app/workers | 작업/단계 진행·재시도·조직 문맥 유지 | 승인된 Job ID·주체/조직·문서/버전 | 실제 단계별 상태·검증 결과·실패 사유. 요청 세션을 그대로 재사용하지 않음 |
| 플랫폼/검색 저장소: src/backend/app/db 및 common_core 저장소 어댑터 | 지속 저장·트랜잭션·RLS·조직/개인 ACL | 서버가 확인한 문맥·읽기/쓰기 | 허용 데이터·변경 결과. 조직 누락과 무권한은 거부 |

원장의 소유자는 Usage/Quota다. AI 호출 모듈은 이를 이용하며 별도 중복 원장을 만들지 않는다. API 요청 횟수 제한과 모델 토큰/예산 제한도 같은 수치로 취급하지 않는다. 조직별 한도 합계가 10월 프로젝트 API 상한 30,000원을 넘는 호출을 허용해서는 안 되므로 프로젝트 공통 예산도 검사한다.

## 호출 방향

사용자/관리 화면 → API 공통 진입 → IAM/Tenant 확인 → 담당 업무 서비스 → (GraphRAG 검색/근거 또는 AI 호출) → 저장/원장 → 응답/상태 표시.

GraphRAG의 생성·임베딩·추출 호출이 필요하면 코어가 제공자 키를 직접 사용하지 않고 주입한 공통 AI 호출 계약을 이용한다. 업무 서비스는 모델 제공자를 직접 호출하지 않는다. 코어는 플랫폼 DB의 사용자/역할 테이블을 직접 수정하지 않는다.

파일 업로드: API/문서 권한 확인 → 문서 등록·Job 저장 → 색인 실행 → GraphRAG 처리/공통 AI 호출 → 조직 범위의 저장·검증 → Job/문서 상태 갱신. 호출 예약·정산은 모든 용도에 같은 원장 경로를 적용한다.

## 인증 문맥의 수명

- 로그인 과정에서는 사용자 식별과 허용 소속 확인에 필요한 최소 데이터만 조회한다. 아직 조직을 선택하지 않은 로그인 조회를 일반 조직 데이터의 전역 조회 권한으로 확장하지 않는다.
- 한 요청은 하나의 활성 조직을 사용한다. 서버의 확인 문맥은 HTTP 요청·DB 트랜잭션·비동기 작업 경계마다 명시적으로 전달한다.
- 조직 전환은 다음 요청의 활성 문맥을 바꾸며 기존 대화/문서/실행의 소유 조직을 바꾸지 않는다.
- 백그라운드 작업·캐시·다운로드에서도 조직/주체를 다시 확인한다. DB 연결 풀에 이전 문맥을 남기지 않는다.
- 그룹/조직 관리 화면도 같은 업무 API 권한 경로를 사용한다. UI와 로그인이 DB RLS를 대체하지 않는다.

## 변경·실패 경계

플랫폼 서비스가 실행 상태와 Job을 소유한다. 모델 오류/취소·색인 실패는 해당 실행/호출/Job의 실제 상태로 기록한다. 사용량 불명과 정산 실패는 원장 상태로 분리해 누락되지 않도록 한다. 프론트의 연결 종료가 공급자 사용량 0을 뜻하지 않는다.

GraphRAG의 조회·근거 처리와 AI 답변 생성은 별도 결과로 기록한다. 자료가 없거나 권한으로 제한되면 근거 부족/접근 거부를 유지하며, 다른 조직 자료로 폴백하지 않는다. 실측 임베딩 오류와 무관한 임의 문서 폴백도 허용하지 않는다.

## 재사용의 경계

GraphRAG의 계약·파이프라인·추출/검색/근거 골격을 선택해 재사용한다. 기존 별도 backend의 직접 모델 호출·모의 인증·미연결 색인·중복 검색은 새 업무/AI/색인 계약으로 수렴한다. 원본 Git 변경과 untracked 파일을 보존하고 재사용 버전을 기록한다. 기존 관리자 PoC를 새 플랫폼 IAM/정책/원장의 권한 엔진으로 간주하지 않는다.

## 220/230/240으로 전달

220: 로그인/조직·관리자 역할·개인 ACL·Agent 중지·예산·검색/근거·Job 요구와 거부 시험.

230: 기존 코어/웹 앱의 재사용 Gap, 모의 기능·직접 호출·저장소 골격과 화면/API 연결 분석.

240: 요청 문맥·실행/호출/Job 상태·원장 계약, 로그인 전 최소 조회, RLS 역할/정책·복합키·Graph ACL·다운로드/캐시·취소/재시도 설계.

현재 상태: 사용자 검토중. 이 문서의 책임 분리 승인 후 모델/예산/저장소 운영 기준을 다음 210 항목으로 검토한다.
