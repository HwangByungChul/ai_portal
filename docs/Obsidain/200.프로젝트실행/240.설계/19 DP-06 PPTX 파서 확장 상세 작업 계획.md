# DP-06 PPTX 파서 확장 상세 작업 계획

작성일: 2026-10-07. [[19 DP-06 XLSX 시트와 셀 검증 및 후속 작업]] 다음 묶음이다. 일정 마감일을 두지 않고220→230→240→250→260→280의 수용 기준을 따라 수행한다. 이 문서는 후속 계획이며 PPTX 구현 완료를 의미하지 않는다.

**Goal:** 제한된 PPTX 슬라이드의 제목·본문 및 단순 표 텍스트를 개인·관리자 문서함에 등록하고, 기존 GraphRAG 질문에서 실제 슬라이드/도형/문단 또는 표 셀 출처와 원본 바이트를 확인한다.

**Architecture:** 명시적 허용 OOXML 부품·관계만 읽는 격리 파서가 canonical UTF-8 및 위치 맵을 반환한다. 기존 현재 권한·접수 제한·확정 재접수·최소 수집 정책·source/original 두 지문·지정 버전 공유/회수·다운로드를 재사용한다. sealed location 네 필드와 SQL000~024를 유지한다.

**Tech Stack:** 현재 Python3.13 표준zipfile·defusedxml0.7.1·macOS 격리/자원 감시, FastAPI/PostgreSQL/React/Playwright. PowerPoint 실행이나 유료 변환 API를 도입하지 않는다. 새 라이브러리는 필요성과 라이선스를 먼저 확인한다.

## 220 요구 정의 — 텍스트 지원 범위 확정

초기 범위는 Transitional PPTX의 실제 슬라이드 순서대로 제목/본문 텍스트 도형과 중첩·병합 없는 표다. 도형 내부 문단/런의 텍스트·줄바꿈을 보존한다. 페이지를 추정하지 않고 실제 슬라이드 번호를 사용한다. 시각적 배치·읽기 순서는 도형 XML 순서와 다를 수 있으므로 화면 의미를 재현한다고 표현하지 않는다.

미지원 범위 초안: 이미지·미디어·SmartArt·차트·OLE/임베딩·매크로·외부 링크/하이퍼링크·애니메이션/자동 실행·숨김 슬라이드/도형·발표자 노트·주석·필드·중첩/병합 표. 일반 시연 슬라이드는 이미지/복합 부품을 포함할 수 있다. 이를 자동 제거하거나 텍스트를 조용히 누락하지 않고 파일 전체를 거부하는 초기 범위를 검토한다. OCR/그림 해석은 별도 후속이다.

슬라이드 마스터/레이아웃의 상속된 텍스트·숨김/필드 처리와 일반 PowerPoint 기본 파일의 부품 구성을 합성 자료로 확인한다. 상속 텍스트를 보이지 않는 값으로 오인하거나 임의로 제외하지 않도록 지원·거부를220에서 확정한다. 모양/테마만 있는 마스터/레이아웃도 내용 존재를 먼저 검증한다.

한도 초안: 원본128KB, 추출40,000자/128KB, 슬라이드20개, 비어 있지 않은 문단/셀2,000개, ZIP200부품/각1MB/총4MB/압축비100배, XML 깊이50/합산20,000노드. 실제 기본 템플릿 부품 수와 함께 확인한다. 한도를 자동으로 늘리지 않는다. `220.요구정의/14 DP-06 PPTX 슬라이드와 도형 수용 기준.md`에 정상/거부 및 위치 기대값을 기록한다.

## 230 영향 분석 — 슬라이드/도형 provenance

presentation→관계→slide→layout/master/theme의 최소 해석 경계를 분석한다. 외부 관계·중복/누락 ID·잘못된 타입/타깃·연결되지 않은 부품은 거부한다. package 내부 절대 URI는 정확한 허용 ZIP 키로만 해석하고 파일시스템 경로로 사용하지 않는다. ZIP 항목의 절대/상위/중복/심볼릭 링크는 차단한다.

canonical 레이블은 원문 텍스트와 별도 줄로 구성한다. XLSX에서 주소 레이블을 같은 줄에 붙였을 때 GraphRAG 업무명이 오염된 사례를 재발시키지 않는다. 비어 있는 슬라이드나 텍스트가 없는 도형의 처리와 원본 출처 순서를 명시한다. 원문 지문/문자 오프셋과 현재 origin 검증의 명시적 PPTX 분기를 설계한다.

산출물: `230.분석/07 DP-06 PPTX 원본과 슬라이드 위치 변경 영향 분석.md`.

## 240 상세 설계 — 구현 전 위치 계약 확정

`extract_pptx(raw) -> {text, locations, parser_version}`를 설계한다. 초안은슬라이드/도형/문단 또는 표/행/열과start/end다. 정확한 kind·키 집합·번호 계산·빈 구조 처리·합산 한도를 수용 기준과 일치시킨다. 조회 응답의 안전한 구조 위치만 추가하고 봉인 FactPacket/location_snapshot은 유지한다.

현재 CPU2초/실행5초·RSS512MB 감시 종료50ms·비밀 환경 미전달·macOS 읽기/쓰기/통신/하위 실행 차단을 유지한다. RSS는 하드 메모리 상한이 아니다. 시간·메모리·격리/감시·ZIP/XML 장애는 안전한 코드로 차단한다. 지원 MIME/확장자/magic/OOXML main type를 모두 확인한다.

`240.설계/20 DP-06 PPTX 격리 파서 상세 설계와 실행 계획.md`에서 부품 허용 목록·원문 의미·위치·안전한 오류를 확정한다. SQL이 필요하면 새 번호만 추가하지만 기존텍스트origin을 재사용해 새SQL없이 구현하는 방안을 우선한다.

## 250 구현 — 작은 단위와 기존 경계 연결

1. tests/pptx_support.py,test_pptx_parser.py의 정상/위험/위치 기대값을 먼저 작성하고 미구현 실패를 확인한다.
2. app/documents/pptx_worker.py,pptx.py,pptx_locations.py에서 ZIP/XML·상속/구조·텍스트·위치·자원 검증을 구현한다. 기존 DOCX/XLSX 허용 목록을 확대하지 않는다.
3. upload.py,repository.py,storage.py에 MIME 및 형식별 파서/origin 검증을 연결한다. 현재 권한·재접수·제한 확인 후 파싱하고 제목+지원 범위의 전체 추출 텍스트를 수집 검사한다.
4. evidence_routes.py와 화면 types/api/DocumentsPage/RagEvidencePanel에 슬라이드/도형 근거와 document.pptx/정확한MIME 다운로드를 연결한다.
5. 원본/canonicalSHA·개인/관리자·지정 버전 공유/회수·현재 권한·동시 접수·감사 실패 복구·삭제 정리를 시험한다. 결과는 `250.구현/14 DP-06 PPTX 슬라이드와 도형 구현 결과.md`에 기록한다.

## 280 회귀·인수 전달·다음 OCR

개인/관리자 등록→게시→질문→슬라이드 근거→원본 바이트 일치, 타 사용자/조직 차단·삭제 회수·공유/회수를 화면에서 확인한다. 전체 화면/서버 영향 범위/빌드 및주DB32개테이블 원본 열/행·SQL000~024 지문 보존을 순차 검증한다. 모의 시연을복구한다.

공개증거에는 실제 시험수·소스/라이브러리 지문·유료호출0을 기록하고 원문/질문/키/비밀번호/DSN을 넣지 않는다. `280.통합시스템테스트/20 DP-06 PPTX 슬라이드와 도형 검증 및 후속 작업.md`로 전달한다. 다음 OCR은 지원 이미지/언어·실패/불확실도·비용·격리·출처를 별도 설계한다. 사용자 직접 인수와기관 운영검증·DP-18전체정책은별도후속이다.
