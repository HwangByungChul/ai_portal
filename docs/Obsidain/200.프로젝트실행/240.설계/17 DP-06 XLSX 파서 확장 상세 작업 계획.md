# DP-06 XLSX 파서 확장 상세 작업 계획

작성일: 2026-10-07. 다음 형식은 XLSX다. [[18 DP-06 DOCX 본문과 표 검증 및 후속 작업]] 이후 수행하며, 일정 마감일 대신 단계별 수용 기준으로 관리한다. 이번 문서는 후속 계획이며 XLSX가 구현됐다는 의미가 아니다.

**Goal:** 사용자·관리자가 제한된 XLSX의 표시 가능한 시트/셀 데이터를 등록하고, 기존 GraphRAG 질문에서 시트·셀 위치와 정확한 원본을 확인한다.

**Architecture:** 제한된 OOXML ZIP/XML 격리 파서가 canonical UTF-8와 불변 시트/셀 위치를 반환한다. 현재 접수 전 권한·제한·재접수 처리, 문서 수집 검사, original/source 보관, 현재 권한 다운로드를 재사용한다. 봉인된 GraphRAG 위치 계약을 변경하지 않는다.

**Tech Stack:** 현재 Python/FastAPI/PostgreSQL/React, 표준 zipfile, 버전·지문을 고정한 defusedxml0.7.1. Excel 프로그램 실행·새 유료 서비스는 도입하지 않는다. 공유 ZIP/XML 경계를 추출할 경우 기존 PDF/DOCX 회귀를 먼저 고정한다.

## 220 요구 정의 — 지원 데이터와 의미 확정

초기 범위는 일반 `.xlsx`의 표시 가능한 시트와 병합 없는 셀이다. 문자열(sharedStrings/inlineStr), 숫자, 불리언, 명시적 ISO 날짜를 우선 검토한다. **수식은 계산하거나 캐시 값을 사실로 사용하지 않고 파일 전체를 거부한다.** 매크로·외부 링크·암호화·OLE/임베딩·그림·차트·피벗·주석·병합·숨김 시트/행/열 및 미지원 부품도 거부한다. 지원하지 않는 데이터가 조용히 누락되지 않아야 한다.

숫자 셀의 날짜/백분율/통화 서식은 데이터 의미를 바꿀 수 있다. 초기에는 승인한 기본 숫자 서식만 허용하고 날짜 직렬수 등 해석이 필요한 서식은 거부하는 기준을 확정한다. 화면 모양/수식/서식 재현을 구현 완료 기준으로 삼지 않는다. 지원·거부 목록과 일반 Excel 기본 파일 부품을 합성 자료로 대조하여 실제 입력 제약을 명시한다.

한도 초안: 원본128KB, canonical40,000자/128KB, 시트10개, 비어 있지 않은 셀2,000개, sharedStrings 항목10,000개, ZIP 부품200개/개별1MB/총4MB/압축비100배, XML 깊이50/파일 전체 노드20,000개. 셀 주소는 Excel의 유효 행1~1,048,576/열A~XFD 범위와 순서·중복을 검증한다. 한도는 위험 검증 없이 자동으로 늘리지 않는다.

산출물: `220.요구정의/13 DP-06 XLSX 시트와 셀 수용 기준.md`. 정상/거부 합성 자료와 예상 텍스트·위치를 함께 기록한다.

## 230 분석 — 셀 출처와 기존 저장 영향

워크북→관계→허용 worksheet→sharedStrings/style의 해석 경계를 분석한다. 외부 관계나 누락된 부품·잘못된 sharedString 인덱스·중복 셀은 안전한 오류로 종료한다. 빈 셀과 시트는 텍스트에서 생략하되 실제 시트 순서/원래 셀 주소를 유지한다. 임의 시트 이름은 안전하게 처리하고 개인정보 검사 범위에 포함한다.

canonical 구성은 시트 이름+셀 주소+값 등 명시적 형식으로 결정한다. 시트 이름만 바뀌어도 결과 지문이 달라져야 하며 개인정보 후보가 시트 이름에만 있어도 저장 전에 차단해야 한다. 셀 값에 포함된 줄바꿈과 탭의 의미를 보존한다. 숫자·날짜는 근거 원문과 다른 값을 만들어 내지 않는다.

산출물: `230.분석/06 DP-06 XLSX 원본과 셀 위치 변경 영향 분석.md`. 현재 PDF/DOCX origin, 정확한 형식별 키 집합, sealed location의 불변성, 정리/복구 영향을 검토한다.

## 240 설계 — 실행 전 확정할 계약

`extract_xlsx(raw) -> {text, locations, parser_version}`를 설계하고 위치 맵의 정확한 키/오프셋을 확정한다. 예시 방향은 `{sheet_index, sheet_name, cell, start, end}`이며 아직 최종 계약은 아니다. 조회 응답의 안전한 시트/셀 정보와 봉인 위치 네 필드를 분리한다.

CPU2초/실행5초와 현재 RSS512MB 종료 감시·macOS 격리·비밀 환경 미전달을 적용한다. RSS는 50ms 간격의 감시 종료 기준이며 하드 메모리 상한으로 표현하지 않는다. ZIP은 메모리에서만 펼친다. 격리/감시 장애는 차단한다. MIME·확장자·magic 및 OOXML 타입을 모두 확인한다.

새 SQL이 필요하지 않은 방향을 우선 검토한다. 필요할 때만025 이후 새 번호를 추가한다.000~024의 지문과 현재32개 테이블 원본 열/행은 유지한다. `240.설계/18 DP-06 XLSX 격리 파서 상세 설계와 실행 계획.md`에서 지원 부품·오류 코드·위치 맵을 확정하고 250으로 전달한다.

## 250 구현 — 작은 단위로 연결

1. `tests/xlsx_support.py`, `test_xlsx_parser.py`에 정상/거부 기대값을 먼저 작성하고 실패를 확인한다.
2. `app/documents/xlsx_worker.py`, `xlsx.py`에 한도·관계·안전 XML·셀 해석을 구현한다. 공유 ZIP/XML 경계를 추출하면 DOCX 기존 부품 허용 범위를 넓히지 않는다.
3. `upload.py`, `repository.py`, `storage.py`의 명시적 XLSX 분기를 연결한다. 파싱 전에 현재 권한과 제한·확정 재접수를 확인하고, 파싱 후 제목+시트 이름+셀 전체를 수집 검사한다.
4. SHA-256 두 개와 불변 셀 위치를 저장하고 색인·검색은 canonical 텍스트만 사용한다. 다운로드는 현재 권한과 두 지문 확인 뒤 `document.xlsx`의 원본 바이트를 반환한다.
5. 사용자/관리자 파일 선택·지원 제한 안내, 근거의 시트/셀 표시, 안전한 한글 오류를 구현한다. TXT/PDF/DOCX 다운로드를 유지한다.
6. `250.구현/13 DP-06 XLSX 시트와 셀 구현 결과.md`에 변경과 실제 제한을 기록한다.

## 280 통합 검증과 인수 전달

개인 등록→게시→질문→시트/셀 근거→원본 바이트 일치, 관리자 등록/공유/회수, 다른 사용자·조직의 원본 차단, 삭제 후 회수를 화면에서 확인한다. 기존 전체 화면과 서버 영향 범위 회귀, 타입/빌드,32개 테이블 원본 열/행과 SQL 지문 보존을 확인한다. DB를 사용하는 시험은 역할 비밀번호 충돌을 피하도록 순차 실행한다.

유료 호출0회, 소스/라이브러리 지문·시험 수·원본 데이터 보존을 공개 증거 JSON에 기록한다. 원문·키·비밀번호·DSN은 증거에 넣지 않는다. 모의 시연을 복구하고 `280.통합시스템테스트/19 DP-06 XLSX 시트와 셀 검증 및 후속 작업.md`로 전달한다. 다음은 PPTX, 이후 OCR을 별도 묶음으로 검토한다. DP-06 전체 완료와 사용자 직접 인수는 각각 별도로 판단한다.
