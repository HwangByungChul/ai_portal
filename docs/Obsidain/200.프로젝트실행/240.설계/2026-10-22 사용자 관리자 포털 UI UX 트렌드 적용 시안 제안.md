# 사용자 관리자 포털 UI UX 트렌드 적용 시안 제안

> [!info] 상태
> A안은 사용자 선택을 받아 기존 실제 React 화면에 스타일로 반영했다. 이 문서의 클릭형 HTML은 비교용 목업이며, 목업의 예시 데이터·기능이 실제 앱/API·저장에 연결된 것은 아니다.

관련: [[200.프로젝트실행/240.설계/23 포털 UI UX 확정과 사이트 분리 검토]], [[200.프로젝트실행/240.설계/25 포털 첫 화면 사용자 관리자 구분 시안 검토]], [[400.프로젝트관리/02 포털 UI UX 작업 기록]].

## 요청과 결정
- 사용자 요청: 사용자·관리자 사이트에 최신 UI UX 아이디어를 적용한 목업 시안 2종 제안.
- 사용자 확정: 시안마다 사용자 홈, 관리자 운영 홈, 관리자 승인·검증 상세를 포함한 클릭형 단일 HTML 목업으로 구성하고, 이후 A안을 선택해 실제 화면 적용을 요청.
- 색상 차별화는 의도된 사이트 식별 요소로 유지한다. 선택된 A안의 사용자 업무 화면은 인디고(`#4F46E5`), 관리자 운영·승인 화면은 틸(`#12635C`)을 사용한다. 로그인 화면은 기존 별도 승인 설계를 따른다.

## 시안
- **A · 소프트 스페이스:** 업무 홈과 운영 개요에 제한적으로 부드러운 깊이와 모듈형 배치를 사용한다. 승인 상세는 불투명 표면, 요청 범위, 변경 비교, 근거 목록으로 가독성을 유지한다.
- **B · 트러스트 워크플로:** 장식 효과를 줄이고 사용자 이어서 하기, 관리자 요청 큐, 검증 근거·변경점·처리 상태의 읽기 순서를 우선한다. 역할에 맞춰 표시하되 핵심 탐색과 업무 상태의 위치는 일관되게 둔다.
- 두 시안에서 추천은 선택형 제안으로 표현하고 요청 접수·검토·승인·게시 상태를 구분한다. 관리자 권한·테넌트 범위는 기존 승인 경계를 전제로 한다.

## 변경 파일
- 프로젝트 목업: `UI_UX_제안_20261022/portal-mockups.html`

## 검증 결과
- 로컬 브라우저에서 목업을 열어 A/B 시안 선택과 사용자 홈·관리자 운영·승인 상세 화면 전환을 확인했다.
- 화면 레이아웃은 작은 뷰포트에서 적층되는 반응형 목업으로 작성했다. 그래프·계정·상태·수치는 설명용 예시다.
- 실제 프론트엔드 코드, 인증·API·데이터 저장·권한 검증, 기관 UAT 및 운영 배포는 변경하거나 검증하지 않았다.

## A안 선택과 실제 앱 반영
- 사용자가 A안을 선택하고 실제 작업을 진행하도록 요청했다.
- 실제 사용자 홈·관리자 운영 홈·관리자 승인 스타일을 공통 UI 원본에 반영했다. 실제 데이터 조회, 승인·검증 동작, 역할·테넌트 경계는 기존 React/API 구현을 유지했다.
- A안의 소프트뎁스, 모듈 카드, 180ms 안팎의 가벼운 반응, 사이트별 인디고/틸 강조를 적용하고 모바일 적층과 reduced-motion을 반영했다.
- 실제 프론트엔드 사용자/관리자 분리 빌드 및 번들 경계 확인 결과는 [[200.프로젝트실행/250.구현/2026-10-22 사용자 관리자 포털 A안 Soft Space UI 반영 결과]]에 기록한다.
- 실제 인증 사용자 브라우저 확인과 기관 UAT, 상용 배포는 이 작업에서 수행하지 않았다. 이 문서는 기존 확정 설계의 과거 결정을 삭제하지 않으며 23 설계 문서의 날짜별 변경 이력을 따른다.
