> **현재 기준 — 2026-10-04 종합 승인:** 사용자가 종합 설계 보고 후 “네 진행 바랍니다”로 후속 진행을 지시하여 이 설계를 확정했다. [[200.프로젝트실행/250.구현/01 인증과 테넌트 기반 구현 계획]]으로 전달한다. 아래 각 D240 작업 당시의 검토 대기/미수행 서술은 작성 이력이다. 현재250의A01환경·health/DB도구는구현·시험완료다. 인증·테넌트업무DB/RLS·화면/AI·전체시험은미수행이며250 결과문서를따른다.

## 1. 목적·현재 상태·책임

2026-10-04 사용자 “네 진행 바랍니다”로 D240-07을 수행했다. 요구41/V41·ACL16·Q20·F01~08 및 DB/요청/AI/Graph/화면 하위 입력을 시험 입력·기대 결과·증거와 연결한 **검증 설계 문서**다. 문서 작성/자체 점검 완료이며 런타임 fixture/시험기/DB/앱/제공자 호출을 생성하거나 실행하지 않았다. 기존 Q20은 모두 execution.status=not_run이다. 240 종합 사용자 승인은 아직이다.

예상25분은 기존215분 문서 계획의 배정이며 시험 실제 수행 시간/통과 수/구현 공수 측정값이 아니다. 80시간에는10시간 조정 여유가 포함된다. 승인된 모델2개·10월30,000원·논리 격리·공통 FastAPI 및 src/frontend/backend/common_core 구조를 유지한다.

검증 책임: 250은 기능별 실제 소스/시험기/초기화·버전 고정 계획과 구현, 260은 모듈·DB/권한/실패 시험, 270은 개인 파일럿 사용, 280은 통합 UI/API·Q20·대표 실제 호출/성능, 290은 설치/재현/이행 확인, 300은 증거 기반 완료/미완료 보고다. 대표 실제 호출을260에서 이미 증거와 함께 수행했다면280에서 동일 증거의 버전 적합성을 확인해 재사용하고 불필요한 유료 반복을 하지 않는다.

## 2. 시험 경계·실행 준비 기준

M은 **제공자만 모의**라는 뜻이다. 실제 FastAPI 인증/CSRF/ACL·PostgreSQL 런타임 역할/RLS/복합 FK·transaction/원장·Job·브라우저 UI를 전부 모의로 바꾸지 않는다. R은 승인 예산 안의 실제 중앙AI 경로다. 코드 정적 점검은 별도 D(문서/소스 점검)로 기록하고 M/R 동작 통과로 세지 않는다.

| 경계 | 필수 실물/입력 | 모의 가능한 부분 | 필수 증거 |
|---|---|---|---|
| 인증/조직/직접 API | 실제 서버/쿠키/Origin/CSRF/헤더·현재 membership | 시험 계정/합성 시각 조건 | 정제 HTTP 결과·권한 전후값·provider 호출 수 |
| DB/RLS/풀/동시 저장 | 실제 PostgreSQL+vector, web/index/meter 비우회 역할, 2개 이상 DB 연결 | 오류 주입/실행 barrier | 역할 속성·허용/거부 행 수·transaction 결과·복합키/집계 |
| 일반/RAG/색인 | 실제 허가/예약/dispatch/상태/검색·원문 규칙 추출/저장 | M provider의 텍스트/벡터/usage·지연/오류 | run/Job/call/event ID·단계·mode·provenance·정산 |
| 화면/stream | 실제 브라우저/프론트/서버·현재 조직/역할 | M 응답을 지연해 늦은 이벤트 주입 | 상태별 화면·네트워크 조직/세대·반환 필드 검사 |
| 실제 모델 | 승인된 OpenAI 모델/키·실제 usage/모델/종결 | 제공자 응답 대체 불가 | 제공자 receipt 최소 필드·내부 원장·실제/추정 구분 |

실행 준비 조건: 해당 기능 설계 승인, 버전 고정/기동 확인, fixture mapping/DB migration 완료, 현재 검증 대상 Git SHA/모드 명시, 오류 주입이 시험 환경 전용임을 확인한 뒤 수행한다. 하나라도 미충족이면 not_run + 이유를 남긴다. 파일만 있거나 버튼만 보인다는 이유로 pass를 주지 않는다.

real/mock 환경은 별도 시험 DB/색인 namespace로 구분한다. mock DB는 `ai_portal_mvp_test_` 접두어와 synthetic_only 표식을 확인하고 외부 제공자 호출/실제 키 주입을 금지한다. real은 하나의 지속 DB `ai_portal_mvp_real`에서 승인 기간 예산/기발생 원장/예약/unknown을 유지한다. real DB 복제·초기화·원장 삭제로 예산을 다시 사용할 수 있게 만들지 않는다. 앱 프로세스는 workers=1, real 실행 중 자동 reload 없이 운영한다. mock 반복 DB를 만들 때 real 키를 복사하지 않는다.

## 3. F01~08 생성·초기화·정리 설계

현재 존재하는 것은7개 UTF-8 Markdown 원문, 평가용 manifest/Q20의9개 파일이다. manifest의 actors/ACL/Grant는 선언이며 실제 account/session/DB 권한이 아니다. 문서6개/버전7개/근거18개/관계16개/액터9개를 유지한다.

| fixture | 현재 상태 | 구현 후 생성할 입력/초기화 | 정리/검증 경계 |
|---|---|---|---|
| F01 계정/조직 | 선언만 | A-U1/A-U2/B-U1/A-ADM/B-ADM/DUAL/DUAL-ADM/P-A/INACTIVE; A/B membership·관리 소속; P-A 관리A만/글로벌권한 별도 | 매 mock case의 원래 권한 복원. 쿠키는 실제 로그인으로 얻음; 관리자 init와 앱 DB role 분리 |
| F02 문서/관계 | 7원문 존재, DB/색인 미생성 | 6 logical doc/7 versions를 실제 업로드→원문 규칙 추출/청킹→embedding→검증/공개. 실물 bytes/hash 대조 | manifest 관계/EV 정답으로 DB graph/vector를 seed하지 않음. mode별 공개 index 분리 |
| F03 대화/run | 미생성 | A-U1/A-U2/B-U1의 정상·실패·진행 run/대화; 일반/RAG와 revocation 후 과거 인용 | 원칙적으로 실제 업무 API로 생성; DB 특정 장애 시 필요한 상태만 init 주체가 시험 DB에 seed하고 구분 |
| F04 Agent | 선언만 | 조직별 general/rules_rag 설정/중지/config version·조직별 UUID; B만 허용된 설정으로 직접 ID 시험 | 유형2개 유지. 별도 Agent 유형 생성 없음. 설정 변경/중지 후 fixture revision 복원 |
| F05 ACL/Grant | 선언/BASE·SHARE_REVOKED 명세만 | 개인 owner/reader, A 소유 D-S v1→B 활성 Grant, v2 미공유; 동일 ID의 실제 회수 | BASE를 복원한 격리 case에서 Q-019 선행 답변/링크 생성→소유자 회수. 실제 관리 API/현재 gate 검사 |
| F06 원장/한도 | 미생성 | 생성/query/doc embed의 settled/failed/unknown·reserved·slot, 경계 cap/동시 잔여; 기간2026-10·mode | 가공 값은 mock 원장에만. real의 기발생 지출/예약/불명은 fixture 정리로 지우지 않음 |
| F07 오류/경합 | 미생성 | 부분 delta/EOF/usage 유실/429/timeout/벡터 오류·DB commit 전후 장애·서버 kill·현재권한 회수·CAS barrier | 시험 전용 provider/fault hook; 제품 API에 오류 주입/강제 완료/정산 수정 endpoint 추가 금지 |
| F08 실행환경 | 미생성/설치 미확인 | 실제 DB/extension/migration·런타임 역할/connection pool·파일/메모리cache·Job lease/epoch·2탭·실측 환경 | role owner/superuser/BYPASSRLS/상속/함수grant 확인; mock 풀을 real 키/DB에 연결하지 않음 |

seed mapping은 suite마다 선언 ID→runtime UUID의 actor/tenant/doc/version/index/Job/Grant/evidence 대응을 기록한다. manifest의 source_path/hash/ACL 선언 중 필요한 부분만 신뢰된 초기화 주체가 읽어 업로드 metadata를 구성한다. 업무 실행기/모델에는 manifest 전체·relations·expected_facts·EV 정답을 넘기지 않는다. index 출력과 원문 구간으로 evaluator가 EV18/R16 대응을 검증한다.

P-A의 read-only/write-only/권한회수 사례는 각 격리 mock case에서 같은 액터의 글로벌 권한 조합을 변경/복원한다. 액터/역할/관리 범위를 영구 확대하지 않는다. 동일 조직 명시 reader 허용/회수 사례도 시험 초기화와 실제 ACL 통제 경계를 구분한다. 계정 비밀번호는 로컬 시험 비밀 설정에서 관리하고 문서/증거에 출력하지 않는다.

파괴적 mock reset은 DB 접두어+synthetic_only+mode=mock+real 키 없음을 모두 확인하고 명시 reset 입력이 있어야 한다. 조건 불일치 시 중단한다. 원본 GraphRAG/제안 자료·manifest/Q20은 변경하지 않는다. real은 비콘텐츠 fixture/회수 상태만 현재 API로 정리하고 예산·원장·불명/remote slot은 유지한다. 합성 개인 본문도 일반 로그에는 넣지 않는다.

## 7. 모의 반복과 최소 실제 호출 계획

### 7.1 M 반복 시험

provider 모의는 정상 delta/finish/usage, usage없는정상종결, EOF전오류, 지연/timeout, 완전한429/5xx응답, length/refusal/empty, 정상/오류embedding/차원/NaN을 독립 입력으로 제공한다. 호출 카운터는 dispatch ID/step별 기록한다. 벡터는 deterministic mock으로 별도 namespace에만 저장하며 실제 검색 품질/모델 성능이라고 표시하지 않는다. relation/근거는 실제 원문 추출/저장 경로를 통과해야 한다.

권한/음성경계·동시/장애시험은 필요 case별 반복3회로 같은 결과를 확인한다. 세차례 성공해도 필수 입력 누락이면 상위pass가 아니다. lease/session 기한은 시험 전용 시각/DB의 오래된 timestamp를 준비해 경계 전후를 재현하되 app/DB의 실제 권한·durable상태를 우회하지 않는다. real에 fakeclock/hook을 활성화하지 않는다.

execution_status=not_run/running/completed은**시험실행 상태**다. verdict=pass/fail/not_run은시험판정이다. 제품run.completed와시험pass를혼동하지않는다. 실제정상거부는negative case의pass일수있다. 시험오류/필수증거누락이면완료판정을하지않고not_run+이유(필요시결함)를남긴다. 기능동작이기대와다르면fail이다. 제품run의failed/blocked/interrupted/needs_review 자체를시험불합격으로단순치환하지않는다.

HTTP증거에는메서드/정제경로·선택조직·status·응답허용필드·request ID만남기고Cookie/Set-Cookie/Authorization/CSRF/비밀번호/key원문을제거한다.
