# 시험 이력·수동 평가·버전 비교

사용자 계속 진행 승인에 따라 [[28 DP11 Agent Builder 프롬프트 RAG Playground 상세 개발 계획서]]의 Task4를 이어 구현한다. 실제 서비스를 위한 서버 저장·권한·불변 증적을 제공하며 운영 배포 승인으로 확대하지 않는다.

1. migration033: 기존 SQL000~032 동결. 본인 trial의 자산별 이력을 20건 keyset pagination으로 조회한다. 목록은 실행 ID·버전·상태·모의/실제·시각만 반환한다. 본문·개인 입력·평가 코멘트는 목록에 넣지 않는다. 다른 관리자도 본인 이력만 조회한다.
2. 증적 상세는 현재 관리 권한/본인/조직/자료 ACL을 다시 확인한다. 저장된 모델·profile·조합·결과 지문/정확한 자료 binding/시각/정산 상태와 append-only 수동 평가를 조회한다. 입력값과 credential은 새 응답에 추가하지 않는다. 자료 회수 시 상세·평가·비교 차단; 최소 이력 메타데이터는 유지한다.
3. 수동 평가: 완료 결과만 대상. rubric manual-v1, 정확성·업무 적합성 1~5점, 기대 답변/부족근거, 판정 적합/보완/부적합, 코멘트 최대1000자. 새 평가가 과거 평가를 덮어쓰지 않는다. client_request_id 재시도는 동일 receipt, 변경 payload409. 평가 결과는 semantic 자동 검증이나 배포 승인으로 취급하지 않는다.
4. 비교: 같은 자산의 본인 시험2개를 서버의 한 transaction에서 재검사한다. 버전·모델·profile·조합·자료·결과·정산·평가를 병렬 표시한다. 같은 사용자 질문/목적/모드/자료 여부를 명시하며 다르면 직접 우열 비교 조건이 아님을 표시한다. 질문 내용은 새 비교 메타데이터에 노출하지 않고 지문으로 비교한다.
5. React: 페이지 재진입 후 이력 선택·추가 페이지·상세·평가·두 시험 비교. 조직/자산 전환 및 오류/권한 회수 후 이전 증적을 지운다. 비동기 응답 역전 방지, dirty 상태 결과 숨김. 평가 접수 불명은 같은 ID로 복구한다.
6. 검증: isolated PostgreSQL fixture의 이력 cursor/타인·타조직·권한 회수/완료 전 평가/재시도·append 불변/비교조건/기존 실행 회귀 및 React browser와 분리 build. fixture migration과 browser는 순차 실행. primary DB는 백업 후 기존43표 전행/33checksum 보존 확인, synthetic run/유료호출 없이 migration만 적용한다.

변경 예정: migrations/033_builder_evidence.sql, app/builder/trials.py, frontend/src/BuilderEvidence.tsx 및 BuilderTrial 연결, tests/test_builder_evidence.py와 migration/브라우저 시험, catalog/RLS·fixture cleanup 검사.

수용 이후 기록: 구현/시험 노트와 [[23 포털 UI UX 확정과 사이트 분리 검토]], [[02 포털 UI UX 작업 기록]]. 다음 DP12는 정확한 trial/version 증적을 타인 승인 요청에 연결할 별도 공유·자료 권한 계약을 구현한다. 현재 개인 시험 결과를 다른 관리자에게 공개하지 않는다.

미완료로 유지: 자동 평가셋/expected claims 원문 검증 확장·독립 장시간 timeout·SSE·dynamic 승인/게시·secret 참조/다중 모델·실제 Entra/실제 제공자 품질·기관 수용·운영 배포. 현재 source ACL guard와 실행 시 원문 검증을 보존하며 이 단계에서 저장소 재변조 원문 탐지 전체를 수용 완료로 표현하지 않는다.
