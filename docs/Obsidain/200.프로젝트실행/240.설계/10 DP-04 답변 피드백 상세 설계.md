# DP-04 답변 피드백 상세 설계

## 승인 범위와 선택

승인된 09 DP-04 계획을 구현한다. 평가를 대화 메타데이터에 넣으면 여러 답변을 구분하지 못하고, 원장에 넣으면 비용 기록과 변경 책임이 섞인다. 실행별 독립 평가 테이블을 선택하여 실행·답변·비용 기록을 보존한다. 관리자 개인 의견 업무는 개인정보 정책 검증 이후로 유지한다.

## 데이터·동시성

portal.response_feedback은 tenant_id/run_id를 기본 키로 사용하며 conversation_id/owner_user_id/agent_key/execution_mode를 기존 실행에 외래 키로 묶는다. rating은 positive/negative, comment는 선택적 문자열(최대 1,000자), revision은 1부터 증가하며 created_at/updated_at/withdrawn_at을 둔다. 데이터가 없으면 API 버전은 0이다. 철회 시 의견을 비우고 활성 집계에서 제외하며 감사는 남긴다. 재등록 시 버전을 계속 증가시킨다.

쓰기 전에 기존 run_authorize의 현재 주체·계정·세션·소속을 잠그고 대화 행을 잠근다. 따라서 삭제와 평가 등록도 직렬화한다. 동일 내용의 현재/직전 버전 재전송은 중복 행·감사를 만들지 않는다. 오래된 버전의 다른 변경은 409 FEEDBACK_CONFLICT다. bigint 최댓값에서는 충돌로 거부하여 숫자 넘침을 방지한다.

## API 계약

- GET /api/v1/runs/{id}/feedback: 본인 현재 평가. active/revision/rating/comment/updated_at을 반환한다. 없음·철회는 active=false, rating/comment=null이다.
- PUT 같은 경로: rating, 선택적 comment(기본 빈 문자열), expected_revision을 받는 완전 대체 요청이다. 의견 생략은 기존 의견을 비운다. 성공 200과 replayed를 반환한다.
- DELETE 같은 경로: expected_revision으로 논리 철회한다. 최초 없음의 버전 0 철회는 안전 응답이다.
- GET /api/v1/admin/feedback/summary: period(월 첫날, 기본 예산 월), agent_key(선택)를 받는다. 모드는 서버 설정을 사용한다. 기간은 2000~2100년으로 제한한다.

미완료·실패·취소·현재 읽을 수 없는 완료 답변은 409 FEEDBACK_NOT_READY, 타 사용자·타 조직·삭제된 실행은 404다. 세션·CSRF·조직 컨텍스트·추가 필드·중복 쿼리·형식은 기존 공통 계약을 따른다. 읽기는 기존 읽기 횟수 제한을 사용한다. 입력 오류와 감사에 의견 내용을 복사하지 않는다. 의견은 Unicode·NUL 검사 후 앞뒤 공백을 제거하며 화면에는 문자열로 표시한다.

## 권한·최소 집계

FORCE RLS, ai_owner 소유, 고정 search_path와 SECURITY DEFINER 정책 함수를 유지한다. 웹 역할에 직접 쓰기·삭제를 허용하지 않는다. 직접 읽기도 본인의 현재 완료 답변에 제한한다. ai_index/ai_meter와 PUBLIC에 평가 권한을 부여하지 않는다.

feedback.summary_read는 별도 can_read_feedback_summary 함수로 판정한다. 현재 조직 can_manage를 매핑하며 글로벌 권한만 있는 사용자는 허용하지 않는다. 집계 전용 범위에서만 정책 실행 역할이 평가와 삭제 상태를 읽고 고정된 집계 결과를 반환한다. 일반 사용자는 집계 API를 호출할 수 없다.

기간은 현재 활성 평가의 마지막 수정 시각(UTC)을 기준으로 한다. 과거 월별 상태를 보관한 통계는 아니다. 기간·Agent·모드별 활성 평가를 집계하며 삭제된 대화는 제외한다. Agent별 서로 다른 참여자가 3명 이상일 때만 positive_count/negative_count/total_count를 표시한다. 1~2명은 status=suppressed와 null 건수, 0명은 empty와 0을 반환한다. 사용자·실행·제목·질문·답변·의견·참여자 식별자는 반환하지 않는다. 이 최소 건수 규칙은 완전한 익명화 인증을 의미하지 않는다.

## 화면·실패 처리

현재 저장된 답변에 ‘도움 됐어요/아쉬워요’, 선택적 의견, 평가 저장과 평가 철회를 제공한다. 서버 확인 후 상태를 변경하며 충돌은 최신 평가를 다시 조회한다. 의견은 브라우저 영구 저장소에 저장하지 않는다. 조직 전환·권한 변경·답변 삭제·RAG 원문 권한 회수 시 내용을 비운다. 관리자 메뉴 ‘답변 평가’는 건수와 숨김 이유만 표시한다.

## 검증과 완료

220 기준 H08-01~08에 서버·직접 SQL·화면 시험을 연결한다. 버전·재전송·동시 등록·철회/재등록·형식·CSRF·타 소유자/조직·삭제·권한 회수·감사 실패·비용 보존·모드/기간/Agent·소규모 숨김을 확인한다. 기존 대화·RAG·사용량·권한 시험, 타입 검사와 배포용 빌드를 수행하고 250/260/280에 증거를 남긴다. 직접 사용자 수용은 별도로 관리한다.
