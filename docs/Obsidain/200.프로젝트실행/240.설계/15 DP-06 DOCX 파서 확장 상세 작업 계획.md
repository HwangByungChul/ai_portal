# DP-06 DOCX 파서 확장 상세 작업 계획

작성일: 2026-10-07. 기존 [[13 DP-06 파일 파서 확장과 수집 검사 상세 작업 계획]]의 P2를 DOCX부터 순차 수행한다. 일정 마감일은 두지 않는다. PDF·최소 수집 검사 결과는 [[17 DP-06 텍스트 PDF와 수집 검사 검증 및 후속 작업]]에서 확인한다.

**Goal:** 개인·관리자 문서함에 제한된 DOCX 본문/표를 등록하고 기존 GraphRAG 검색·문단/표 근거·원본 내려받기·삭제 정리를 연결한다.

**Architecture:** OOXML ZIP의 구조·압축 해제 한도·외부 참조를 먼저 확인한 격리 파서가 UTF-8 텍스트와 문단/표 셀 위치 맵을 반환한다. 기존 등록 전 권한·접수 제한과 수집 정책을 적용한다. 기존 source/원본 sidecar·봉인된 위치 계약을 재사용한다.

**Tech Stack:** 현재 Python/FastAPI/PostgreSQL/React 및 Python 표준 ZIP 처리. XML 파서는 외부 엔터티·DTD를 차단하는 구현을 선정하고 버전/지문/라이선스를 확정한다. 새 라이브러리는 별도 프로세스 안에서만 사용한다.

**Global Constraints:** 유료 모델 호출 없이 합성 문서로 검증. 현재 tenant/user/CAS/receipt 계약과 원본 정리를 유지. 기존 마이그레이션000~024 변경 금지. ZIP·XML·파서 예외/원문을 로그·응답에 노출하지 않음. 사용자가 선택한 파일명은 보관 경로 권한이 아님. HWP/OCR/XLSX/PPTX 및 DP-18 전체 정책 화면은 이번 DOCX 묶음 밖의 후속 작업.

## 1. 요구 기준과 합성 자료 — 220/230

- 새 요구 기준 문서에 지원 MIME `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `.docx` 확장자, ZIP magic 및 OOXML 필수 부품 검증을 정의한다.
- 본문 문단과 표의 셀 텍스트를 문서 순서대로 추출한다. 머리말·꼬리말·주석·변경 추적·각주·텍스트 상자 처리 여부를 명시한다. 초기에는 해당 복합 구조를 감지하여 거부하는 보수적 범위를 권고한다.
- DOCX는 화면/프린터에 따라 페이지가 바뀌므로 PDF처럼 페이지 번호를 추정하지 않는다. 문단 번호와 표/행/열 위치를 근거로 표시한다.
- 한글/영문 문단, 중첩 없는 표, 빈 문단, 개인정보 후보, 위장 ZIP, 외부 관계, 매크로/첨부/활성 콘텐츠 및 압축 폭탄 합성 fixture를 준비한다.
- 한도 초안: 원본128KB, 추출40,000자/128KB, ZIP 부품200개 이하, 전체 펼친 데이터4MB, 개별 부품1MB, XML 깊이50·노드20,000 이하. 실측을 바탕으로 확정하며 자동으로 한도를 올리지 않는다.

완료 산출물: DOCX 수용 기준/거부 목록/영향 분석/합성 자료 목록과 예상 TP·FP·FN 분류.

## 2. ZIP/XML 격리 파서 — 240/250

1. 실패 시험을 먼저 작성한다. ZIP 안의 절대 경로·상위 경로·중복 항목·암호화·심볼릭 링크·높은 압축률·초과 해제·과다 부품을 거부한다.
2. 디스크로 압축을 풀지 않는다. 명시적 허용 부품만 메모리에서 제한된 길이로 읽는다.
3. `[Content_Types].xml`과 관계 파일을 확인해 DOCX 본문 타입을 검증하고 외부 TargetMode, 매크로/VBA/OLE/임베딩/활성 콘텐츠를 거부한다.
4. XML의 DTD/외부 엔터티/네트워크 해석을 금지한다. 구조 제한과 CPU2초·시간5초·RSS512MB 초과 종료를 적용한다. 자원 감시·격리 실패 시 차단한다.
5. 반환 인터페이스는 `extract_docx(raw) -> {text, locations, parser_version}`로 제한한다. 위치는 `{kind:paragraph|table_cell, paragraph|table,row,column,start,end}` 등 합성 fixture와 일치하는 불변 맵으로 확정한다.
6. 파서 환경에 프로젝트 비밀·DB·모델 키를 전달하지 않는다. 실제 프로젝트 읽기/쓰기/통신/하위 프로세스 차단 시험을 재사용한다.

완료 기준: 정상 문단/표 추출과 거부 fixture 통과, 원본 바이트와 추출 위치의 재현성 확인. 격리 해제 우회 없음.

## 3. 기존 수집·저장·검색 연결 — 250

- 새로운 MIME/확장자/magic 계약을 multipart에 추가하되 클라이언트 권한 필드는 늘리지 않는다.
- 먼저 현재 권한/동일 접수/제한을 확인한 뒤 파싱하고 제목+추출 전체 텍스트에 최소 수집 검사를 적용한다.
- `source_mapping.origin` 검증을 파일 형식별 명시적 분기로 확장한다. 기존 PDF origin을 그대로 해석하고 TXT/Markdown에는 origin을 요구하지 않는다.
- 원본 DOCX 및 canonical 텍스트의 SHA-256을 각각 보관한다. 지문 불일치·원본 유실은 검색/다운로드/게시 차단으로 처리한다.
- worker·search는 기존 canonical 텍스트의 GraphRAG 계약을 유지한다. 구조 위치는 sealed FactPacket/location_snapshot에 넣지 않고 현재 권한의 조회 응답에서만 파생한다.
- 원본 다운로드의 MIME/파일명을 `document.docx`로 반환하고 화면에서도 정확한 MIME만 허용한다. TXT/PDF 다운로드 회귀를 포함한다.

완료 기준: 사용자/관리자 DOCX 접수→게시→자료 선택→질문→문단/표 근거→원본 바이트 일치. 재접수는 추가 파싱·작업·호출 없음.

## 5. 완료 보고와 다음 형식

250 구현 결과,260 모듈 결과,280 통합 결과와 공개 증거 JSON을 작성한다. 소스/라이브러리 지문·기존 DB 원본 열/행 보존·시험 수·유료 호출0 여부를 실제 결과로 기록한다. 주 DB 변경이 필요하면 새 번호만 추가하고 초기화/재시딩 없이 적용한다. 작업 후 모의 시연을 복구한다.

완료 상태는 **DP-06 DOCX 묶음**으로 표시하며 Office/OCR 전체 완료로 확대하지 않는다. 다음 XLSX를 표/시트/셀 출처 중심으로 설계한 뒤 PPTX 및 별도 OCR을 검토한다. DOCX 구현 전 이 문서의 지원/거부 범위와 새 파서 라이브러리 선택을 확정한다.
