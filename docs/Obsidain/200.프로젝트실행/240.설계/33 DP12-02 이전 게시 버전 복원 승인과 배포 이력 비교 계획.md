# 이전 게시 버전 복원 승인과 배포 이력 비교 Implementation Plan

**Goal:** 과거 승인된 정확한 버전을 별도 타인 승인으로 복원하고 게시/철회 이력과 두 버전의 차이를 실제 DB/API/React로 제공한다.

**Architecture:** 기존 asset_deployments에 kind/source_request_id를 추가하고 기존 불변 trigger를 유지한다. 새 publication_events는 append-only metadata이며 이전 승인 기록·현재 상태만 출처를 구분해 backfill한다. 복원 요청은 현재 게시 revision/공개 대상을 봉인하고 승인 시 재검사하여 새 publication revision을 만든다. SQL000~037은 동결하고038만 추가한다.

**Tech Stack:** PostgreSQL forced RLS/security RPC, FastAPI/Pydantic, React/TypeScript, pytest/Playwright.

**Spec:** [[32 DP12 동적 Agent 승인 게시와 사용자 실행 상세 계획]], [[33 DP12 동적 Agent 승인 게시와 사용자 실행 구현 결과]], [[34 DP12 동적 승인 공개 대상 실행과 정산 검증]]. 사용자 최신 지시는 이전 버전 복원 승인/배포 이력 비교 진행 승인이다. writing-plans/brainstorming의 추가 승인/다중 agent/기본 저장 경로/commit보다 사용자의 기존 계획→구현 지시·Obsidian 위치·현재 공유 작업 보존을 우선하여 순차 실행한다.

## Global Constraints / 결정

- 제품 명칭 생성형 AI 플랫폼, 사용자 A/관리 A/승인 B 흐름 유지. local/dev/tb/prd·포트 분리와 기존 인증/CSRF/owner ACL·예산·meter 유지. 기관 상용 배포로 표현하지 않는다.
- 즉시 관리자 복원(빠르지만 검토 이력 부족), 신규 Builder 초안 복제/시험(명확하지만 기존 정확한 승인 버전 복원과 다름), 기존 승인 snapshot의 별도 타인 복원 승인(채택)을 비교했다.
- 복원 target은 같은 자산의 과거 approved request/version/profile만 가능하다. 임의 초안/다른 자산/타조직은 불가. 현재 공개 대상 유지로 과거 넓은 대상의 자동 복원을 막는다. 대상 변경은 별도 일반 게시 요청이다.
- old latest_version/same_profile 불일치는 이전 버전 복원에서 예상된다. historical exact version/profile hash를 불변 원장과 대조한다. shared 증적 철회·same_mode/same_policy 변경·현재 독립 자료 ACL 미충족은 복원 승인 불가이며 반려 가능하다. 정책 변경 뒤 재시험/새 게시 요청은 별도 후속 경로다. 자기 승인 금지·품질/보안 체크·명시 의견은 유지한다.
- published 상태의 동일 version 복원은409. retired 상태에서는 과거 승인 버전 재게시 가능. 승인 때 current publication CAS와 공개 대상 동일성, 계정/회원 활성 확인. 이전 run 상세는 기존 current publication fence로 차단하며 사용량 이력 유지.
- 이벤트 기록은 exact publication revision/request/version/status/time/hash/actor metadata, 과거 approval_record와 관찰 current_state를 구분한다. 과거 누락 철회/actor를 추측하지 않고 history_complete 표시한다. 현재 자료가 없으면 이력 metadata는 제공하지만 prompt 비교는404다.
- 비교는 두 exact 이벤트의 immutable builder version/profile을 own ACL로 확인하고 이름/설명/system/developer/user template/model/자료 선택의 before/after/changed만 반환한다. 개인 trial 입력/답변·평가기대조건·private claim은 포함하지 않는다.
