# DP11-05 업무 평가셋과 자동 조건 검증 상세 계획

**Goal:** 저장 버전별 본인 업무 평가 사례를 불변 저장하고, 같은 입력/버전의 완료 시험에 결정적 조건 검증을 수행해 결과 지문과 함께 보존한다.

**Architecture:** 기존 개인 builder trial·현재 관리/자료 ACL·worker/원장을 재사용한다. migration034의 owner 전용 평가 사례/검증 원장과 capability RPC를 추가한다. 평가 자체는 제공자 호출을 하지 않는다. 사례 입력으로 시험을 시작할 때만 기존 admission/예산/정산을 적용한다.

**Tech Stack:** FastAPI/Pydantic, PostgreSQL forced RLS/security RPC, React/TypeScript, pytest/Playwright.

**Spec:** [[11 DP11-04 이후 잔여 개발 항목과 진행 순서]], [[28 DP11 Agent Builder 프롬프트 RAG Playground 상세 개발 계획서]], [[30 DP11-04 시험 이력 수동 평가와 버전 비교 구현 결과]].

사용자 다음 작업 진행 승인에 따라 계획→직접 순차 개발→검증→Obsidian 기록을 수행한다. 사용자 지정 Vault 경로와 기존 변경 보존을 스킬 기본 경로/커밋/추가 승인 권장보다 우선한다. 하위 에이전트는 사용하지 않는다.

## 제약과 선택

- SQL000~033 동결. 현재 local44표/34migration/127security함수. 기존44표 전행과34checksum 보존을 검증하고034만 적용한다.
- 생성형 AI 플랫폼, 사용자A/관리A/B승인 화면 유지. 신규 draft 공개 실행404·사용자 대화에서 개인 시험 숨김 유지.
- 평가 사례는 본인 현재관리/조직/저장버전/자료ACL 전용. 다른관리자도 개인시험 입력이나 기대조건을 읽을 수 없다. 저장·재시도·목록상세·시험·평가·증적조회 모두현재권한 확인.
- 사례는 name, values, purpose, 기대 answer/insufficient_evidence, 필수문구/금지문구 각최대10개·각200자, 기대 자료최대5개 정확한document/version. 빈문구·중복·잘못된자료·과도길이/NULL/extra거부. 자료 기대는 저장 profile scope부분집합이고 결과가 실제인용/반환한 자료binding을 검사한다.
- 문구조건은 대소문자·공백을 포함한 정확한 부분문자열 규칙이다. 의미적 동치/사실 정확성/업무품질을 자동 판정하지 않는다. required/forbidden 없이도 답변유형·자료조건은 검사하되 평가조건 부족을 사람이 확인할 수 있게 표시한다. mock통과는 실제모델품질·배포승인아님.
- 과거 RAG 검색 후보에는 자료binding이 없을 수 있다. 신규 후보에 최소binding을 봉인하고 과거결과는 소급수정하지 않는다. 기대자료를 증명할 수 없으면 통과시키지 않는다.
- 결과없는실패/취소/진행trial은 평가409. 권한거부를 평가 성공으로 저장하지 않는다. 정상·부족근거·권한회수/타인거부는 격리 수용시험으로 검증한다. 제품 차원의 임의 다른계정 권한시험/자동negative수트 실행은 후속이다.
