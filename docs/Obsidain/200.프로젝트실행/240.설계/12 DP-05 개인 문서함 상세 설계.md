# DP-05 개인 문서함 상세 설계

승인된 [[11 DP-05 개인 문서함과 질문 첨부 상세 작업 계획]]을 구현하기 위한 상세 설계다. [[10 DP-05 개인 문서함 수용 기준]], [[03 DP-05 개인 문서함 변경 영향 분석]]과 함께 관리한다.

## HTTP 계약

| 경로 | 동작 | 제한 |
|---|---|---|
| POST /api/v1/documents | multipart 개인 신규 등록, 202 | client_upload_id/title/media_type만 입력; 현재 세션 주체·조직·private 고정 |
| GET /api/v1/documents/mine | 개인 관리 목록 | 본인이 사용자 경로로 등록한 문서만; limit 1~50·서명 커서 |
| DELETE /api/v1/documents/{id} | 논리 삭제/정리 예약 | 본인 사용자 문서만; expected_revision |
| GET /api/v1/document-jobs | 개인 처리 목록 | 본인 사용자 문서의 작업만 |
| GET /api/v1/document-jobs/{id} | 상태 조회 | 타인/타 조직 404; 재시도 권한 없음 |
| GET /api/v1/documents | 기존 게시 자료 목록 | 기존 읽기 정책 유지 |
| POST /api/v1/runs | 기존 document_refs 사용 | rules_rag, 게시 버전 최대 5개; 접수·실행·결과 조회 모두 현재 권한 검증 |

## DB와 실행

user_owned boolean NOT NULL DEFAULT false를 문서 접근 행에 추가한다. private 체크와 기존 식별자 불변 트리거에 이 열을 포함한다. 정책 실행 전용 NOLOGIN 역할만 고정 함수를 실행하며 공개 EXECUTE와 일반 로그인 역할의 직접 쓰기는 금지한다.

새 user_document_authorize/preflight/register/admission_window/list/job_view/delete/request_trace는 사용자 경로 전용이다. 등록 함수는 소유자·공개 범위·독자·기존 문서 여부를 재검증한다. 동일 ID의 관리자 등록 영수증을 사용자 개인 업로드로 재사용할 수 없다. 삭제 후 동일 ID 재접수는 원문을 복원하지 않고 충돌 처리한다.

document_job_authorized/background_control/cleanup_background/pending은 기존 관리자 조건 또는 해당 대상의 사용자 개인 소유 조건을 검사한다. 활성 계정·조직·멤버십, 작업 종류·모드·리스·현재 규정 Agent 상태·요금 통제를 유지한다. 기존 document_manage와 관리자 등록/공유/작업 조작 함수는 변경하지 않는다.

등록은 사전 권한·중복 확인 후 불변 파일 저장, DB 등록/감사 순서다. 삭제는 접근/게시/공유/작업 권한 차단을 먼저 커밋하고 내용·파일 정리를 별도 작업으로 수행한다. 원장과 저장된 실행 식별자는 삭제하지 않는다.

## 화면과 오류

내 자료 화면에 개인 등록 폼, 본인 문서 상태/삭제/처리 목록, 기존 읽기 자료를 제공한다. 개인 등록은 공개 범위 선택을 노출하지 않는다. 관리자 문서 관리 폼/버전/공유는 기존 UI를 사용한다. 미게시 문서는 질문 자료 목록에 나타나지 않으며 게시 후 규정 질의 자료 새로고침으로 선택한다.

권한 위조 422, 대상 없음/타인 404, 접수/수정 충돌 409, 제한 초과 429, 불명확한 저장 실패 503. 조직 전환은 useScope 취소/현재성 검사와 화면 재생성으로 이전 데이터를 제거한다.

## 구현/검증 순서

1. 사용자 POST 부재를 확인하는 실패 시험으로 시작한다.
2. 023 및 사용자 저장소/라우트/요청 본문 제한을 구현하고 DB 계약 시험을 실행한다.
3. 개인 화면과 기존 질문 첨부 흐름을 연결하고 브라우저 시험을 추가한다.
4. 마이그레이션/직접 권한/문서 처리·요금·복구·공유·RAG·대화·평가 회귀와 화면 전체 시험/빌드를 수행한다.
5. 주 DB 기존 열·행 보존을 검증하며 023을 적용하고 모의 화면을 복구한다.
6. 250 구현, 260 모듈 시험, 280 통합 결과 및 다음 작업 상세 계획을 작성한다. 실제 호출·사용자 인수는 별도 상태로 명시한다.

설계 자체 검토: 기존 관리 권한을 일괄 완화하지 않으며, 사용자 경로와 작업 대상 검증을 분리했다. 동일 API 경로의 읽기/관리 충돌은 /documents/mine으로 해소했다. 복구·삭제·평가의 접근 회수까지 시험 대상에 포함했다.
