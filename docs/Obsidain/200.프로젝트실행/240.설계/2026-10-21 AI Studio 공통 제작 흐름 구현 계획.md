# AI Studio 공통 제작 흐름 Implementation Plan

> **For agentic workers:** Execute tasks in order with focused review checkpoints. Do not delegate unless the user requests delegation.

**Goal:** 현업 제작자가 Agent/Workflow와 빠른 시작/단계별 제작을 쉽게 선택하고 본인 초안을 이어서 편집할 AI Studio 진입 경험을 제공한다.

**Architecture:** AIStudioHubPage를 진입 컨테이너로 유지하고 시작 선택/초안 이어하기를 작은 컴포넌트로 분리한다. Agent/Workflow는 각자의 기존 tenant-scoped API를 유지하고, 공통 DB/API로 합치지 않는다.

**Tech Stack:** React 19, TypeScript 7, Vite 8, @xyflow/react 12, 기존 API/scoped request helpers, Playwright.

**Spec:** [[2026-10-21 AI Builder 고도화 통합 Studio 설계]].

## Global Constraints

- 제품명은 ‘생성형 AI 플랫폼’; 공통 브랜드에서 BNK 표기를 제외한다.
- 화면 전에 [[23 포털 UI UX 확정과 사이트 분리 검토]]와 [[36 AI Studio 통합 메뉴 및 Hub 구조 상세 구현 방안]]을 읽는다.
- /manage/admin/studio와 기존 /manage/admin/builder, /manage/admin/workflows 경로를 유지한다.
- 승인 전 초안을 일반 카탈로그에 노출하거나 실행하지 않는다.
- UI의 숨김은 ACL이 아니다. 서버 권한 검사를 유지한다.
- 사용자/관리자 빌드 경계를 유지한다.

### Task 1: 시작 선택 화면

**Files:**
- Create: src/frontend/src/StudioStartPage.tsx
- Create: src/frontend/src/ai-studio.css
- Test: src/frontend/tests/ai-studio-start.spec.ts

**Interface:** StudioStartPage receives onChoose(target: 'agent' | 'workflow', mode: 'quick' | 'guided') and returns navigation intent only. It must not call any API.

- [ ] **Step 1: Write the failing Playwright test.** Test all four target/mode choices and assert the callback receives the exact pair. Assert headings and keyboard focus.
- [ ] **Step 2: Implement the start page.** Show plain-language descriptions for quick and guided entry; keep visual rules in the scoped stylesheet. Reuse current design tokens and do not rebuild Agent or Canvas UI.
- [ ] **Step 3: Run the focused browser test.** Run from src/frontend: npx playwright test tests/ai-studio-start.spec.ts. Expected: four paths and accessible focus pass.

### Task 2: Connect the Hub and existing drafts

**Files:**
- Modify: src/frontend/src/AIStudioHubPage.tsx
- Modify: src/frontend/src/AssetsPage.tsx
- Modify: src/frontend/src/WorkflowCanvasPage.tsx
- Test: src/frontend/tests/ai-studio-start.spec.ts
- Test: src/frontend/tests/ai-studio-resume.spec.ts

**Interface:** AIStudioHubPage owns active tab/mode and unsaved-change confirmation. Existing URL tab values and legacy routes remain compatible. Agent resume uses the existing assets list; Workflow resume uses GET /api/v1/workflows/drafts and exact detail calls.

- [ ] **Step 1: Test URL and edit state.** Add cases for existing tab URLs, quick/guided selection, back/forward, and confirming before leaving dirty edits.
- [ ] **Step 2: Integrate the start page.** Preserve the two existing editors and bridge links. Query state determines the selected mode. Tenant/session change clears previous editor state and outstanding requests.
- [ ] **Step 3: Add resume actions.** Reuse each server-owned list/detail API. Do not merge owners from client data or make an aggregate cross-tenant endpoint. Labels must distinguish draft, trial, approval request, approval, and publication.
- [ ] **Step 4: Verify no side effects.** Tests assert listing/resume never calls builder trial, workflow run, approval, or publication APIs.
- [ ] **Step 5: Run tests and boundary builds.** Run from src/frontend: npx playwright test tests/ai-studio-start.spec.ts tests/ai-studio-resume.spec.ts; npm run build:admin; npm run build:user. Expected: tests and both boundary builds pass.

## Handoff

This plan completes guided entry and resume UI only. It does not implement natural-language provider calls, business-user authorization, trial or publication behavior.
