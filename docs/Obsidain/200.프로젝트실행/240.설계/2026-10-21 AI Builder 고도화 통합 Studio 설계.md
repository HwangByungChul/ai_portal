# AI Builder 고도화 통합 Studio 설계

## 목적과 승인된 방향

코딩 경험이 거의 없는 현업 담당자가 자연어 또는 단계별 제작으로 Agent와 Workflow 초안을 만들고, 검토·시험·평가·승인 요청까지 진행하도록 AI Studio를 고도화한다.

사용자가 승인한 방향은 **가이드형 통합 Studio**다. AI Studio는 하나의 진입점이며 Agent Builder와 Workflow Canvas는 탭으로 전환하는 별도 편집 경험으로 유지한다. 자연어 빠른 시작과 수동 제작을 모두 제공하고, 두 유형 모두 자연어로 검토 가능한 초안을 생성한다. 승인된 Agent를 Workflow 노드로 재사용하거나 초안 간 실행 연동하는 기능은 이번 설계 범위에 포함하지 않는다.

## 현재 구현 검토

현재 저장소의 실제 앱에는 다음 기반이 있다.

- AIStudioHubPage가 Agent Builder와 Workflow Canvas를 한 AI Studio에서 탭으로 전환하고 URL 상태와 상호 이동 안내를 제공한다.
- Agent Builder는 자산 초안과 불변 버전, 구조화된 시스템/개발자/사용자 프롬프트, 변수 조합 미리보기, 자료 범위, RAG·모델 시험, 사용량/결과, 수동 평가 및 평가 사례, 승인용 증적 공유를 연결한다.
- Workflow Canvas는 시각적 노드 편집, 초안 동기화, 실행 원장 및 중단 실행의 수동 복구 기능을 포함한다. 최신 복구 구현 노트에는 소유자/PADMIN 왕복과 브라우저 수용이 미검증이라고 기록되어 있다.
- 제작·실행·승인 경계는 기존 API, tenant/owner ACL, 자료 권한, 정책 및 비용 원장을 이용한다.

현재 근거는 로컬/모의 제공자 기반의 실제 앱 구현과 제한된 시험이다. 실제 기관 업무 품질, 외부 제공자 수용, 전면적 Workflow 수용, 운영 게시/배포를 완료한 상태로 취급하지 않는다. 기준 문서는 [[28 DP11 Agent Builder 프롬프트 RAG Playground 상세 개발 계획서]], [[11 DP11-04 이후 잔여 개발 항목과 진행 순서]], [[37 Workflow 중단 실행 수동 복구 구현 결과]]다.

## 사용자 여정

AI Studio 진입 화면은 제작 유형과 시작 방식을 명확히 제시한다.

1. 제작 유형: Agent 또는 Workflow.
2. 시작 방식: 빠른 시작(자연어) 또는 단계별 제작.
3. Agent 단계: 업무 목적과 사용자 → 지침/입출력 → 자료와 RAG → 모델/도구 → 구성 검증 → 시험 → 평가 → 승인 증적 제출.
4. Workflow 단계: 업무 목적과 순서 → 자연어 기반 노드 초안 또는 템플릿 → Canvas에서 노드/연결 검토 → 구성 검증 → 허용된 시험/실행 계약 → 결과 확인 → 승인 요청.
5. 공통 보관함: 본인 초안, 저장 버전, 진행 상태, 이어서 작업하기를 보여준다. 일반 이용 가능 여부는 승인/게시 상태와 기존 카탈로그 정책을 따른다.

### 빠른 시작

사용자는 업무 목적, 대상 사용자, 입력/출력, 필요한 자료와 도구를 자연어로 설명한다. 시스템은 내용을 구조화하고 빠진 정보나 모호한 선택을 질문한 뒤 Agent profile 또는 Workflow graph의 **저장 전 제안**을 만든다. 제안은 사용자가 검토·수정한 뒤 명시적으로 저장한다. 생성만으로 모델 시험, Tool 호출, 사용자 공개 또는 게시를 실행하지 않는다.

### 단계별 제작

업무 템플릿을 선택해 필수 정보를 순서대로 채운다. 초보자에게는 기본 설정을 먼저 보여 주고 고급 옵션은 펼쳐 편집한다. Agent는 기존 설정 폼과 Playground를, Workflow는 기존 Canvas와 Inspector를 재사용한다. 각 단계는 필수 입력, 권한, 설정 효과와 다음 행동을 설명한다.

## 구조와 데이터 흐름

자연어 입력 → 요구사항 정리/누락 질문 → 미저장 제안 생성 → 사용자 검토·편집 → 기존 Agent 불변 버전 또는 Workflow 초안 저장 → 구성 검증 → 별도 시험 접수 → 비용/결과 원장 및 평가 → 명시적 증적 제출 → 타인 승인 → 승인된 버전 게시/실행.

미저장 제안은 운영 자산이나 실행 가능한 버전이 아니다. 저장 이후에도 시험은 기존 목적별 Builder/Workflow API와 승인된 정책 경로를 사용한다. 신규 모델·도구·자료 연결을 임의 endpoint 또는 credential 입력으로 만들지 않고 관리되는 Registry, 서버 참조, 현재 권한 검사로 제한한다.

## 권한과 상태 경계

- 현업 제작자는 본인 초안 편집과 허용된 개인 시험만 관리한다. 조직 이용자나 운영 관리자 권한은 자동으로 부여하지 않는다.
- 승인자는 제출된 증적만 열람하고 독립적으로 승인/반려한다. 자기 승인을 허용하지 않고 개인 시험 원문에 대한 광범위한 접근을 주지 않는다.
- tenant, owner, 현재 자료 ACL, 정책/비용 원장, 감사 및 승인 gate를 저장·시험·심사·실행 때 재확인한다.
- 제품 상태는 제안 → 초안 저장 → 시험 실행/완료 → 승인 요청 접수 → 승인/반려 → 게시 → 운영 실행으로 구분한다. UI의 상태는 실제 처리와 일치해야 한다.
- 현업 제작자 역할과 심사자 분리는 DP16 등 역할 계획과 맞춰 설계한다. 역할 부여 및 실제 계정 수용 전에는 일반 현업 사용 가능으로 표시하지 않는다.

## 오류와 복구

- 입력이 불완전하면 필요한 질문과 수정 위치를 안내하고 원래 입력은 보존한다.
- 자연어 초안 생성에 실패하면 입력을 잃지 않고 단계별 제작으로 전환한다.
- 저장 경합/오래된 버전은 최신 revision을 비교하게 하고 덮어쓰지 않는다.
- 자료/Tool 권한이나 게시 상태가 바뀌면 재검사하고 영향을 받는 검증/시험을 다시 요구한다.
- 시험 취소, 한도 초과, timeout, 결과 불명은 기존 비용 원장·idempotency·복구 규칙을 따르고 성공으로 추정하지 않는다.
- Workflow의 외부 Tool/Agent 결과가 불명확하면 자동 재호출하지 않고 수동 복구 gate를 따른다.

## 단계별 제품 범위

1. **Studio 진입·가이드**: Agent/Workflow와 빠른 시작/단계별 제작 선택, 공통 초안 목록 및 상태 안내.
2. **Agent 빠른 시작**: 요구사항 인터뷰, profile 초안, 기존 버전 저장/시험/평가 연결.
3. **Workflow 빠른 시작**: 요구사항에서 검토 가능한 graph 초안을 만들고 기존 Canvas에서 편집. 자동 실행은 하지 않는다.
4. **현업 제작 역할**: 제한된 draft/trial 권한과 tenant/owner scope, 관리자 심사 분리를 도입하고 부정 권한 사례를 검증한다.
5. **수용**: 현업 사용자가 별도 UAT에서 Agent와 Workflow 각각 초안 작성부터 승인 요청까지 수행한다. 실 제공자/기관 데이터/운영 배포 검증을 합성 fixture 결과와 구분한다.

각 단계의 구현 승인과 세부 순서는 별도 실행 계획에서 확정한다. 이 설계 승인 자체는 코드 변경, 역할 부여, 게시, 운영 실행 또는 배포 승인이 아니다.

## 성공 기준과 검증 계획

- 코딩 없이 Agent와 Workflow 초안을 각각 저장하고 제안 내용과 수정 방법을 이해한다.
- 자연어 제안은 저장 전 검토/편집 가능하며 생성만으로 실행·공개되지 않는다.
- 단계형 경로에서도 필수 항목과 권한 영향을 이해할 수 있다.
- 정확한 버전, 자료/Tool 권한, 비용, 시험 상태, 평가, 승인 상태가 화면과 API에서 일치한다.
- 초안/시험은 작성자와 tenant 범위를 지키고 승인/게시 후에만 일반 사용 경로에 노출된다.
- 키보드/모바일, 권한 회수·자료 변경, 동시수정, 요청 재시도, 중단/결과 불명, 부정 권한을 자동·브라우저·기관 UAT별로 검증한다.
- 실제 업무 적합성은 대표 업무별 정답·근거 기준과 전문가 평가를 정의한 뒤 확인한다. 자동 조건 검증을 의미적 품질 판정으로 간주하지 않는다.

## 범위 밖

- Agent 초안을 Workflow 노드로 직접 참조하거나 하나의 초안 안에서 공동 편집/실행.
- 승인 전 초안을 일반 사용자에게 공개하거나 운영 실행 경로에 연결.
- 승인·비용·감사·tenant/owner/data ACL을 우회하는 자동실행.
- 이 문서만으로 코드 구현, 기존 migration 수정, 실제 외부 제공자/기관 연동, 운영 배포.
- 전체 기능명세 완료 비율 재산정.
