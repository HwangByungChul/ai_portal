## DP-03 최초 구현을 시작할 대표 시험 코드

아래는 향후 `src/backend/tests/test_dp03_acceptance.py`에 추가할 계획 코드입니다. 이미 존재하는 client/db_fixture/login 및 `test_operations.headers`·ops_rows를 사용합니다. ops_rows가 합성 Agent를 활성화하므로 새 PATCH 부재에 도달하기 전에 AGENT_STOPPED로 실패하지 않습니다. 새 metadata_revision은0부터 시작하고 기존 create 응답의 conversation_id를 사용합니다. 이 계약은 DP-03 설계에서 채택한 뒤 구현합니다.

```python
from test_operations import headers, ops_rows

def test_owner_can_rename_but_another_user_cannot(client, db_fixture, login, ops_rows):
    csrf = login(client, 'A-U1')['csrf_token']
    created = client.post('/api/v1/conversations',
        headers=headers(db_fixture, 'A', csrf),
        json={'agent_key': 'general'})
    assert created.status_code == 201
    conversation_id = created.json()['data']['conversation_id']
    path = '/api/v1/conversations/' + conversation_id
    changed = client.patch(path, headers=headers(db_fixture, 'A', csrf),
        json={'title': '합성 대화 제목', 'pinned': True, 'expected_revision': 0})
    assert changed.status_code == 200
    assert changed.json()['data']['title'] == '합성 대화 제목'
    assert changed.json()['data']['metadata_revision'] == 1
    csrf2 = login(client, 'A-U2')['csrf_token']
    denied = client.patch(path, headers=headers(db_fixture, 'A', csrf2),
        json={'title': '권한 없는 수정', 'pinned': False, 'expected_revision': 1})
    assert denied.status_code == 404
```

첫 실행은 현재 PATCH 기능 미제공으로 실패해야 합니다. 구현 후 위 assertion과 C01~C04의 충돌/삭제/CSRF/원장 시험을 함께 통과해야 합니다. test import로 대량 실제모델 실행을 유발하지 않으며 db_fixture의 합성 개인대화를 사용합니다.
