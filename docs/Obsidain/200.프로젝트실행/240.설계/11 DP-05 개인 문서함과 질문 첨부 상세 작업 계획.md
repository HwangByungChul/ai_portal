# DP-05 개인 문서함과 질문 첨부 상세 작업 계획

## 목표와 범위

일반 사용자가 자신의 TXT·Markdown 문서를 올리고 처리 상태를 확인한 뒤, 게시 완료된 버전을 규정 RAG 질문에 첨부할 수 있도록 한다. 기존 문서 저장·색인 작업자·GraphRAG·AI 호출 허가·비용 원장을 재사용한다. 파일 선택만으로 모델을 자동 호출하지 않는다.

초기 범위는 본인 전용 문서의 등록·목록·상태·삭제와 질문 첨부다. PDF·Office·이미지·OCR·웹 URL 수집은 별도 후속으로 관리한다. 조직 게시와 공유 부여는 기존 관리자 경로를 유지하며 사용자 입력으로 조직·소유자·공유 권한을 지정하지 않는다.

## 단계별 수행 계획

| 산출물 단계 | 상세 작업 | 확인 기준 |
|---|---|---|
| 220 요구정의 | AC-H09~10과 F014·F015의 사용자 등록·처리·첨부·삭제 범위 확정 | 허용 파일·상태·권한·재전송 사례 연결 |
| 230 분석 | 기존 관리자 등록 경로, 문서 권한 함수, 작업자·색인·정리·호출 비용·첨부 검사 확인 | 관리자 권한을 일반 사용자에게 확대하지 않는 재사용 지점 식별 |
| 240 설계 | 본인 등록 DTO, 사용자 전용 정책 함수, 요청 지문·버전·수명·삭제 계약 작성 | owner/tenant/share 필드는 서버에서 결정하고 추가 입력은 거부 |
| 250 구현 | 본인 문서 API·권한 → 문서함 → 처리 상태 → 게시 완료 버전 질문 첨부 | 현재 권한을 매번 재확인하고 기존 document_refs 계약 사용 |
| 260 모듈시험 | 형식·크기·중복·동일 ID 다른 내용·타 사용자/조직·처리 중 첨부·회수 시험 | 중복 작업·불필요한 임베딩 호출 방지, 원장 보존 |
| 280 통합시험 | 업로드 → 처리 → 첨부 질문 → 근거·원문 → 삭제·회수 | 대화·피드백·RAG·사용량·관리자 문서 회귀 연결 |

## 제안 API와 변경 파일

- `POST /api/v1/documents`: 파일과 제한된 metadata를 받는다. client_upload_id, 제목·허용 media_type만 사용하며 소유자·조직·공유는 입력받지 않는다.
- `GET /api/v1/documents`: 본인 전용 문서와 처리 상태를 서명된 페이지로 조회한다.
- `DELETE /api/v1/documents/{id}`: 현재 버전과 본인 권한을 확인하고 기존 삭제·정리·감사 절차를 사용한다.
- 기존 `POST /api/v1/runs`의 rules_rag와 document_refs를 재사용한다. 처리 중·게시 전·회수된 버전은 질문에 사용할 수 없다.

서버는 app/documents/user_routes.py, 사용자 입력 검증과 고정 정책 함수를 추가한다. 화면은 DocumentsPage/ReadableDocuments/ChatPage의 사용자 문서 흐름을 확장한다. 새 DB 변경이 필요한 경우 023 파일을 사용하고 000~022는 수정하지 않는다. 시험은 test_dp05_acceptance.py와 dp05-acceptance.spec.ts로 분리한다.

현재 업로드 본문 상한은 147,456바이트다. metadata 상한은 8,192바이트다. 실제 텍스트·토큰·청크·자료 크기 제한은 230에서 기존 파서와 Gateway 설정을 확인해 동일하게 유지한다. 확장 형식이나 더 큰 크기를 이번 작업에서 자동 허용하지 않는다.

## 핵심 수용 시험

1. owner·reader·tenant·share 위조 입력은 422이며 권한·문서·호출 기록을 만들지 않는다.
2. 같은 등록 ID와 같은 파일 재전송은 문서·작업·임베딩 호출을 중복 생성하지 않는다. 다른 내용은 409다.
3. 처리 중 또는 게시 전 버전 첨부는 차단하고 완료·게시 후 질문과 정확한 근거를 확인한다.
4. 타 사용자·조직에서 목록·작업·근거·원문을 읽거나 자료 ID를 직접 첨부하지 못한다.
5. 삭제·회수 직후 검색·질문·근거·원문 및 기존 피드백의 접근 경계를 재검증한다. 기존 비용·감사 기록은 보존한다.
6. 사용자 문서 삭제가 다른 사용자의 문서·조직 게시·봉인된 실행 기록을 변경하지 않는다.

## 완료 조건

코드·DB·사용자 화면·서버 및 화면 시험·보존 검증을 단계별 산출물로 기록한다. 개인 학습·시연용 모의 검증과 실제 모델·기관 환경 검증을 구분한다. 이번 문서는 후속 작업 계획이며 DP-05 구현 완료를 의미하지 않는다.
