# DP09-02 실행 자산 식별과 출처 봉인 상세 작업 계획서

> **실행 방식:** 사용자의 계획 작성 후 개발 지시에 따라 현재 세션에서 작업별 확인란으로 계획→구현→검증을 진행한다. 기존 변경을 보존하고 자동 commit/운영 배포하지 않는다.

**Goal:** 기존 고정 Agent와 연결 UUID의 실행 호환을 제공하고 신규 run에 자산·버전·설정 지문을 불변 저장하여 후속 카탈로그와 승인 배포의 기반을 만든다.

**Architecture:** PostgreSQL 신규 migration028에서 실행 바인딩을 INSERT 시 서버 스냅샷으로 계산하고 UPDATE 변경을 차단한다. 세션·조직 검증을 거치는 resolver와 기존 run_view에 출처 메타데이터를 추가하고 Python worker/React 실행 상세에 전달한다. 기존 예산·정지·설정 변경·문서 ACL·정산 gate는 유지한다.

**Tech Stack:** 현재 FastAPI/Pydantic, PostgreSQL RLS·definer RPC, React/TypeScript, pytest, Playwright.

**Spec:** [[24 DP-09 동적 AI 자산 기반 상세 설계와 실행 계획]], [[15 전체 기능명세서 잔여 기능 개발 실행 계획]], [[09 전체 기능명세서 기준 개발 완료 여부 검토 보고서]].

- 제품명 생성형 AI 플랫폼. 사용자 A홈·관리 A홈/B승인 구성 유지.
- SQL000~027 checksum 고정. 새 변경은028에 추가한다. 기존 실행·대화·문서·정산 데이터와 스냅샷을 수정/재해석하지 않는다.
- local 사용자5173/관리5174/API8000. 공개 환경 local/dev/tb/prd와 CSRF·Origin·세션·RLS·호출 원장 유지.
- 거버넌스 F050~060 제외, PPTX/OCR 보류. DP12 승인/게시 이전 신규 draft 실행 불가.
- 이번 대상은 고정 general/rules_rag 연결, 신규 chat 및 document_summary 실행 식별, 소유자 실행 상세. 동적 승인 버전 실행·카탈로그·Builder·SSO는 별도 묶음이다.
- 상용화는 제안 기능 실제 구현 요구다. 기관 연동/UAT·운영 배포·원본 전체 기능 완료와 모의 검증 완료를 구분한다.
- Entra ID 테스트 환경 준비 예정은 기능 개발의 대기 조건이 아니다. 유료 모델 호출 없이 모의 제공자로 검증한다.

## 확정할 실행 계약

| 계약 | 구현 기준 |
|---|---|
| asset_id | 기존027 view와 같은 md5(tenant UUID + ':portal-agent:' + agent_key)::uuid. 조직별 다른 식별자. 이것은 보안 토큰이 아니다. |
| asset_revision | 신규 run config_snapshot.config_version. 현재 설정을 조회하여 과거 버전을 덮어쓰지 않는다. |
| asset_config_hash | config_snapshot에서 name/description/instructions/execution_kind만 정규화한 JSONB UTF8 SHA256. 선택 이력/문서/질문은 제외한다. 명시적 비어 있지 않은 지시문이 있는 설정은027 view와 동일하다. 기본 지시문이 적용되는 경우 실행의 실효 지시문 지문이며 등록 view의 기본값 지문과 구분한다. |
| asset_version_id | md5(asset_id + ':revision:' + revision + ':' + config_hash)::uuid. 고정 버전의 결정적 연결 ID이며 asset_versions의 draft 행으로 가장하지 않는다. |
| asset_binding | API에 {source:'legacy',asset_id,revision,version_id,config_hash}. 기존 run은 null로 응답해 미기록 상태를 명시한다. |
| 선택 입력 | POST /api/v1/runs 기존 agent_key 필수 + optional asset_id UUID. 생략·동일 alias는 같은 의미/재시도 지문이다. 다른 alias/조직/draft/random UUID는 공통404. malformed UUID/알수없는 agent/주입 필드는422. |
| resolver | security.run_asset_resolve(session uuid,tenant uuid,agent text,asset uuid) -> uuid. run_authorize 후 general/rules_rag만 허용하고 optional asset를 조직별 예상 alias와 대조. draft 표 조회/자동 승격 없음. |
| 봉인 | BEFORE INSERT에서 스냅샷으로 네 컬럼을 산출. 클라이언트/호출자가 넣은 출처값을 신뢰하지 않는다. BEFORE UPDATE에서 old/new 네 컬럼 비교, 변경은23514. 기존 config_snapshot 불변 trigger 유지. |
| worker | RunTicket에 선택적 frozen RunAssetBinding. 신규 run claim의 설정 버전과 동일한 출처를 전달. 과거 run은 None 허용. 실행/모델 라우팅은 기존 허가 경로 유지. |

MD5는 기존 UUID 연결 규약을 유지하기 위한 것으로 충돌 방지 내용 지문은 SHA256이다. hash는 자산 내용 식별이며 서명/비밀/출처 인증 수단으로 표현하지 않는다. 바인딩은 설정 당시 지시문을 봉인하고 실제 모델 사용량/모델명은 기존 호출 원장이 계속 담당한다.

## 자체 검토 및 수용 기준

기존 API는 optional 필드 생략 시 동작·지문 유지, 명시 alias의 재시도는 같은 결과, 다른 selector는 실패한다. 네 컬럼은INSERT 당시 설정에서 계산되어 과거 조회가 현재 asset view와 결합되지 않는다. 기존표 수 증가 없이 forced RLS·권한을 유지한다. generic 승인·동적 활성화를 이번 완료로 표현하지 않는다. 시험의 최종 통과와 기존 데이터 보존을 확인해야 DP09-02 완료로 체크한다.

## 일정/진행 상태

계획 작성 후 즉시 Task1→2→3 순서로 진행한다. 검증 실패나 외부 제약을 발견하면 기록을 남기고 수정한다. 이 문서는 작업 순서·수용 기준이며 전체 기능명세의 출시일을 확정하는 문서가 아니다.

## 설계 보정 이력 · 2026-10-12

코드 확인 결과 기존 run_prepare는 지시문이 없거나 빈 문자열이면 실제 실행 기본 지시문을 적용한다.027 등록 view는 다른 기본 표시값을 갖는다. 기존 SQL027/실행 기본값을 바꾸지 않고 신규 실행 지문은 실효 config_snapshot을 기준으로 봉인한다. 따라서 등록 view의 지문을 실행 당시 지문으로 재조회하지 않는다. 기본값 없는/빈 지시문 두 경우를 별도 수용 시험에 추가했다.
