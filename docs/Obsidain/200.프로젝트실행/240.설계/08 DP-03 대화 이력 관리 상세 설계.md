# DP-03 대화 이력 관리 상세 설계

## 범위와 승인 기준

승인된 상세 개발 계획과 DP-01의 AC-H01~H07을 구현한다. 제목 변경·핀·제목 검색·논리 삭제를 포함한다. 피드백, 본문 검색과 물리 삭제는 후속 범위다. 기존 역할·세션·CSRF·소유자·조직·DB 행 수준 권한, 실행 스트림과 비용 원장 경계를 유지한다.

## 데이터와 API 계약

021 변경 파일로 대화에 `title`, `pinned`, `metadata_revision`, `deleted_at`을 추가한다. 기본 제목은 ‘제목 없는 대화’, 핀은 해제 상태, 메타데이터 버전은 0이다. 질문·답변을 제목으로 자동 복사하지 않는다. 제목은 앞뒤 공백 제거 후 1~120자이며 NUL·개행·잘못된 Unicode를 거부한다. 기존 생성 시각·실행 스냅샷·메시지·비용 값은 바꾸지 않는다.

| 요청 | 계약 |
|---|---|
| PATCH /api/v1/conversations/{id} | 제목·핀 중 최소 하나와 예상 버전을 받는다. 본인의 현재 권한과 CSRF를 검사한다. |
| DELETE /api/v1/conversations/{id} | 예상 버전을 받고 삭제 시각을 기록한다. 비종료 실행이 있으면 409 CONVERSATION_BUSY로 차단한다. |
| GET /api/v1/conversations | q(최대 120자), 선택적 pinned, cursor, limit(1~50)을 받는다. 제목의 대소문자를 무시한 부분 문자열 검색이며 %·_는 일반 문자다. |

변경 성공은 200이다. 같은 내용을 현재 버전 또는 직전 버전으로 재전송하면 안전하게 응답한다. 오래된 버전의 다른 변경은 409 METADATA_CONFLICT다. 삭제의 반복 요청도 본인과 허용 버전을 확인한다. 삭제된 대화의 기존 생성 ID를 재사용하면 409 CONVERSATION_DELETED다. 입력 형식·추가 필드는 422로 거부한다. 타 소유자·조직의 자료는 404, 조직 컨텍스트가 허용되지 않은 요청은 403으로 처리한다.

핀 우선, 생성 시각 최신, ID 순으로 정렬한다. 대화 페이지 서명은 사용자·조직·종류·대상·검색 조건의 SHA-256 지문·핀 필터·정렬 위치에 연결한다. 120자 한글·emoji 검색도 cursor의 1,024자 제한을 지킨다. 다른 조건의 cursor는 422로 거부하며 기존 메시지 페이지 계약은 유지한다.

## 권한과 삭제 경계

`security.conversation_list`와 `security.conversation_mutate` 정책 함수를 추가한다. SECURITY DEFINER, 고정 search_path, ai_policy_executor 소유, PUBLIC 권한 제거와 ai_web 명시 실행 권한의 기존 패턴을 따른다. 감사에는 대상·요청 ID·버전만 기록하고 제목·본문은 복사하지 않는다. 감사 실패 시 전체 변경을 취소한다.

삭제는 인증 주체·세션 검사 후 대화 행 잠금과 진행 실행 검사를 수행한다. 실행 접수도 예산 검사 후 대화 행을 잠그고 삭제 상태를 다시 검사한다. 실행 접수가 먼저 완료되면 삭제를 차단하고, 삭제가 먼저 완료되면 실행을 차단한다.

삭제 상태를 실행 조회·재전송 조회·스트림, 메시지·대화 목록, 생성 요청 재전송, RAG 답변 접근과 직접 DB 조회 권한에 적용한다. 해당 답변의 근거·출처는 실행 읽기 권한을 통해 차단한다. 작업자·정산 역할과 비용·감사·완료 근거 기록은 보존한다. 원문 문서 자체는 독립된 자료 권한으로 관리한다.

## 화면과 실패 처리

목록에 제목·핀 표시, 제목 검색, 핀 필터, 제목 편집과 삭제 확인을 제공한다. 서버가 성공을 확인한 뒤 화면에 반영한다. 충돌 응답이면 목록을 다시 조회한다. 현재 선택 대화 삭제 후 메시지·실행·입력·선택 상태를 비운다. 진행 중인 답변은 취소 또는 완료 후 삭제하도록 안내한다.

검색 결과 없음과 저장한 대화 없음을 구분한다. 검색 조건·조직 전환 뒤 도착한 이전 응답은 요청 세대와 현재 컨텍스트를 검사하여 폐기한다. 휴대폰에서도 목록을 열어 같은 기능을 사용할 수 있다.

## 단계별 검증

1. 기존 시험 자료로 새 PATCH 경로가 없어 실패하는 시험을 먼저 확인한다.
2. 021 DB 정책·삭제 필터, 서버 입력·저장·페이지 처리, 목록 화면 순서로 구현한다.
3. 제목·핀·검색·페이지, 권한·CSRF·버전·반복 요청, 삭제·실행 경합·조회 차단과 원장 보존을 시험한다.
4. 기존 000~020 체크섬, 신규·반복 적용과 DB 함수·권한 속성을 확인한다.
5. 전체 서버 회귀, 타입 검사·배포용 빌드, 브라우저 이력·기존 화면 회귀를 수행한다. 실제 모델은 호출하지 않는다.
6. 250 구현, 260 모듈시험, 280 통합시험에 결과를 기록하고 다음 DP-04 계획을 인계한다.
