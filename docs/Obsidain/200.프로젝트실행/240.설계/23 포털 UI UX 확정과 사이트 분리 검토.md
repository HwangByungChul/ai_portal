> [!success] 사용자 확정 사항

## 1. 요청과 검토 경과

사용자는 기능 개발이 어느 정도 진행된 상태에서 화면을 확인하며 수정 개발하고자 했으며, BNK 제안 준비 당시 홈 PNG를 제공했다. BNK를 제외한 ‘생성형 AI 플랫폼’ 명칭과 전체 UI/UX 두 가지 수정안을 요청했다. 추가로 현재 단일 주소에서 권한별 화면을 분기하는 구성에 대해 사용자·관리자 사이트 분리도 검토하도록 요청했다.

사용자 홈은 A안 업무 허브형과 B안 대화 집중형을 비교했고, 사용자는 ‘a안으로 진행 바랍니다’로 A안을 선택했다. 관리자 화면은 관리 A안 운영 현황형과 관리 B안 승인 업무형을 비교한 후, A를 홈으로 B의 목록·상세를 승인·검증 메뉴로 적용하도록 확정했다.

## 2. 사용자 홈 확정 설계

- 브랜드: ‘생성형 AI 플랫폼’, 특정 기관 로고·붉은 브랜드 배너 제거.
- 톤: 화이트·슬레이트 배경과 틸 강조색. 주색 `#12635C`, 본문 `#182E32`.
- 메뉴: 홈 / AI 채팅 / 에이전트 탐색 / 내 워크스페이스.
- 본문: 업무 질문·문서 첨부 → 업무별 AI 도우미 → 최근 업무·공지.
- 질문 입력과 문서·대화 검색을 구분한다. 사용자 홈에서 전체 비용·전체 사용자·전체 호출 지표를 제외한다.
- 예시 질문과 도우미 선택은 질문을 채우고 사용자가 수정 후 시작하도록 한다.
- 현재 도우미는 예시 질문 연결이며 실제 Agent ID에 의한 실행은 연결하지 않았다. ‘즐겨찾기’처럼 실제 데이터가 필요한 표현은 예시 추천 업무로 정리했다.

## 3. 관리자 사이트 확정 설계

### 기본 홈 — 운영 현황형

운영 알림 → 호출·비용·검토 요청·게시 자산 지표 → 호출 추이·주요 승인 요청 → 서비스 상태·최근 관리 이력 순서다. 사용자 A안과 명칭·글꼴·틸 색상·간격을 공유한다. 기간·조회 조직·집계 기준 시각과 단위를 표시한다.

조직 필터는 예시 지표·그래프·승인 요청을 함께 변경한다. 공통 서비스 상태·최근 관리 이력은 전체 플랫폼 범위로 구분한다. 최근 가입자 전체 목록은 사용자·권한 메뉴로 이동하는 방향이다.

![[200.프로젝트실행/240.설계/첨부/UIUX-20261011/관리_적용_홈.png|900]]

### 승인·검증 — 목록·상세 패널

왼쪽 요청 목록과 오른쪽 검증 상세를 함께 보여준다. 대기 / 검토 중 / 반려 필터와 요청명·담당 조직 검색을 제공한다. 선택한 요청의 요청자·버전·사용 범위, 검증 결과 / 변경 사항 / 처리 이력을 확인한다. 검토 의견은 상세 하단 인라인 입력이다.

관리 A/B안은 하나의 사이트 메뉴 흐름으로 통합했으며 승인 화면의 짙은 사이드바도 홈과 같은 밝은 메뉴로 통일했다. 시안 비교용 상단 A/B 버튼과 하단 비교표는 적용 화면에서 제거하고 원래 비교 자료에 보존했다.

### 관리자 메뉴와 역할

운영 현황 / 승인·검증 / AI 자산 관리 / 모델·연결 관리 / 사용자·권한 / 가드레일·보안 / 감사 로그 / 공지·가이드를 제안한다. 이번 구현 범위는 운영 현황과 승인 검토 시연이며 다른 메뉴는 동선 안내만 제공한다. 운영 시에는 허용된 메뉴·행위만 표시하고 서버에서 권한을 확인한다. 제작자는 전체 관리자가 아니며 제작·검증·승인·보안 권한을 분리한다.

## 4. 사이트 분리 검토 결과

| 방식 | 검토 결론 |
|---|---|
| 단일 주소·앱에서 권한 분기 | 현행 유지 비용은 낮으나 UI와 릴리스가 결합됨 |
| 동일 출처 `/app`, `/admin` | 화면 경계 정리의 중간 단계. 별도 인증·배포를 자동 보장하지 않음 |
| 앱·배포·출처 분리 | 권고안. 공통 SSO·API·업무 데이터는 공유하되 사용자·관리자 앱을 각각 개발·배포 |
| 인증·API·DB까지 전부 분리 | 별도 격리 요구가 있는 경우 검토. 초기 비용과 데이터 동기화 부담 증가 |

제안 주소 `ai.example.com`, `ai-admin.example.com`은 예시이며 개설된 사이트가 아니다. 저장소는 우선 공통 UI·API 계약을 공유하는 모노레포를 검토한다. 사이트별 세션과 SSO 클라이언트, 관리자 API 권한 검증, 쿠키·CSRF·허용 출처·로그아웃·권한 회수 동작은 운영 구조를 확인하여 설계한다.

**주소·앱·저장소·백엔드 분리는 각각 다른 결정이다.** 현재 완료한 것은 사용자·관리자 HTML 파일과 탐색 구조의 분리다. 독립 앱·호스트·배포·SSO·관리 API 연동이 완료된 상태는 아니다. 이번 사용자 승인은 화면 구성에 대한 확정이며 도메인 개설 또는 운영 배포 완료로 해석하지 않는다.

## 5. 검증 범위

사용자 홈: 예시 질문 입력, 기존 시연 대화 진입, 파일명 첨부 상태, 문서함 목록, 에이전트 탐색, 최근 대화, 이용 가이드, 모바일 메뉴를 브라우저에서 확인했다. 질문·파일명은 HTML 문자 이스케이프를 적용했다.

관리자: 기본 홈 진입, 승인 메뉴 전환, 홈 요청에서 해당 상세로 이동, 조직별 예시 지표·목록, 조회 요약, 상태 필터·검색·빈 상태·상세 탭·의견 예시와 텍스트 안전 표시를 확인했다. 1600px·390px 폭에서 문서 전체 수평 넘침과 JavaScript 오류가 없음을 확인했다.

검증은 디자인·HTML 시연 동선에 한정한다. 실제 AI 생성, 파일 내용 분석, 서버 저장, 실제 권한 차단, 정책 판정, 실사용량·과금·장애 감지와 운영 배포는 이번 작업에서 시험하지 않았다. 각 수치·기록·통과 상태는 예시다. 의견은 페이지 메모리에만 남고 새로고침하면 사라진다.

## 2026-10-11 · 후속 실제 앱 통합 상태

기존 HTML 시연 기록 뒤 실제 앱을 통합했다. 사용자 A·관리 A/B 결정은 유지하고 실제 API가 제공하는 지표/요청만 사용한다. 승인 첫 대상은 AI 에이전트 설정 배포다.
