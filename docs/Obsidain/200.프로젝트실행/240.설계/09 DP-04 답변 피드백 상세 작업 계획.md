# DP-04 답변 피드백 상세 작업 계획

## 목표와 범위

본인의 완료된 답변에 좋아요·싫어요 평가와 선택적 의견을 남기고, 변경하거나 철회할 수 있도록 한다. 기존 대화·실행의 소유자·조직 권한과 삭제 차단 처리를 재사용한다. 작성 중, 실패, 취소, 삭제된 답변과 다른 사용자의 답변은 평가할 수 없다.

첫 구현 범위는 본인의 평가·의견 관리와 허가된 조직의 최소 평가 집계다. 자유 의견은 본인에게만 제공한다. 관리자라는 이유만으로 개인 질문·답변·제목·원문 의견을 읽도록 허용하지 않는다. 관리자 의견 조회는 DP-18의 개인정보 정책·마스킹 검증 이후에 검토한다. 분류·개선·종결 기능은 후속 범위다.

## 데이터와 API 설계 입력

평가 자료에는 조직·사용자·실행 식별자, 평가값, 비공개 의견(최대 1,000자), 버전, 생성·수정·철회 시각을 둔다. 동일 사용자와 실행의 평가는 하나로 관리한다. 실행 스냅샷, 답변, 사용량 원장은 변경하지 않는다. 철회 후 재등록해도 버전은 계속 증가하도록 한다.

- `PUT /api/v1/runs/{id}/feedback`: 평가·의견·예상 버전으로 등록 또는 변경한다. 현재 권한과 완료된 답변을 검사하며 같은 요청의 재전송으로 중복 평가를 만들지 않는다.
- `GET /api/v1/runs/{id}/feedback`: 본인의 현재 평가만 조회한다. 타 사용자 또는 삭제된 대화의 실행은 404로 처리한다.
- `DELETE /api/v1/runs/{id}/feedback`: 예상 버전으로 논리 철회한다. 같은 철회 요청의 반복 처리를 정의한다.
- 관리자 집계: 명시적으로 허가된 조직의 평가 수·기간·허용 Agent 단위만 제공한다. 개인 질문·답변·제목·원문 의견은 포함하지 않는다.

위 API는 설계 입력이다. 구체적인 응답 형식, 초기 버전, 오류 코드, 집계 기간과 소규모 집계 노출 기준은 240 설계에서 확정한다. 집계 조회 권한은 후속 DP-16 권한 확장과 호환되도록 명시적인 권한으로 구분한다.

## 완료 기준

- 본인의 완료 답변 평가·변경·철회와 반복 요청 결과가 일관된다.
- 다른 사용자·조직 또는 삭제된 대화의 평가·의견 접근을 차단한다.
- 허가되지 않은 관리자에게 개인 대화·원문 의견을 노출하지 않는다.
- 평가 변경으로 모델을 재호출하거나 발생 비용을 변경하지 않는다.
- 감사 저장 실패 시 평가 변경도 취소한다.
- 서버·화면·DB 시험을 수용 기준에 연결하고 미실행 항목을 구분한다.

이번 문서는 다음 작업을 준비한 계획이며 DP-04 구현·검증 완료를 의미하지 않는다.
