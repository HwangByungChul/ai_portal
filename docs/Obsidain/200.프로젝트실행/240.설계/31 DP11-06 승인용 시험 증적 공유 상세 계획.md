# DP11-06 승인용 시험 증적 공유 상세 계획

**Goal:** 본인이 명시적으로 제출한 정확한 완료 시험·자동 검증의 최소 증적을 현재 조직의 승인 담당자가 조회하고, 작성자는 공유를 철회할 수 있게 한다.

**Architecture:** 개인 trial/case/evaluation의 owner RLS는 유지한다. SQL035에 별도 공유 원장을 추가하고, 본인 제출 시 기존 개인 RPC로 증적을 검증하여 최소 snapshot을 봉인한다. 검토 조회는 실제 검토자 세션·현재 PADMIN·자신의 자료 ACL로 확인한다. 타인으로 identity를 바꿔 개인 시험을 읽지 않는다.

**Tech Stack:** PostgreSQL forced RLS/security RPC, FastAPI/Pydantic, React/TypeScript, pytest/Playwright.

**Spec:** [[30 DP11-05 업무 평가셋과 자동 조건 검증 상세 계획]], [[31 DP11-05 업무 평가 사례와 자동 조건 검증 구현 결과]], [[23 포털 UI UX 확정과 사이트 분리 검토]], [[11 DP11-04 이후 잔여 개발 항목과 진행 순서]].

사용자 진행 승인에 따라 이 세션에서 순차 구현한다. 사용자 지정 Vault와 기존 변경 보존이 스킬의 기본 계획 경로·커밋·추가 선택 권장보다 우선한다. 하위 에이전트를 사용하지 않는다.

## 범위·공유 계약

- SQL000~034 동결, 신규035만 추가. 기존46표/35checksum 보존, backup600 후 local 적용. primary 합성 입력·제공자 호출0.
- 명시 제출 payload는 client_request_id, run_id, evaluation_id, consent=true만 수용한다. 서버가 완료/현재버전/profile/result/case hash·본인 평가를 확인한다. 실패·미완료·타인·다른 시험 평가·구버전·다른 실행모드는409/404/403으로 거부한다.
- 공유 snapshot은 asset/version/revision/config/profile/composition/result/question hash, run ID/mode/purpose/model/운영정책 revision, 선택 자료 document/version/index binding, 평가 ID/case hash/engine/합격 여부와 규칙명별 Boolean만 포함한다. 결과 텍스트/인용/질문/values/평가 기대문구/평가 의견/가격/credential은 공유하지 않는다. 해시도 조직 내부 증적이며 공개 증거에 원문이나 실제 업무 해시를 복사하지 않는다.
- 조건 미충족 평가도 정확한 결과로 제출할 수 있다. 조건 충족은 품질·보안 승인이나 운영 게시를 의미하지 않는다. mock/real 구분을 표시한다.
- 제출 replay는 동일 actor/client/body에 동일 receipt, 변경409, 제출 시 현재 권한 재검사. 미철회 제출 최대20개/작성자. 철회는 본인만 expected_revision CAS·동일 철회 replay; 최소 처리 metadata는 유지하되 상세 snapshot은 반환하지 않는다.
- 검토자는 현재 조직 PADMIN 또는 제출 본인이다. 다른 관리자는404, 일반사용자403, 타조직404. 상세 조회는 검토자 자신의 현재 document/version/index ACL과 출처 실행모드를 확인한다. 자료 회수 시 상세404. 개인 trial/case는 PADMIN에도 계속404다.
- 제출 당시 version/profile/result/evaluation 지문은 불변이다. 제출 이후 자산 최신버전·고정 runtime 정책·현재 실행모드 변경은 snapshot 수정 대신 current_conditions로 차이를 표시한다. 이 원장에는 승인/게시 API가 없다. DP12에서는 이 binding을 다시 검증하고 타인 결정·게시·실행을 별도 원자 계약으로 구현한다.
