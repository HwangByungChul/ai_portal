# DP-09 동적 AI 자산 기반 상세 설계와 실행 계획

> **실행 방식:** 사용자 요청에 따라 이 세션에서 계획→구현→검증 순으로 진행한다. 작업별 확인란으로 추적하며 하위 계획은 착수 전에 확정한다.

**Goal:** 제안 기능을 실제 API·DB·권한·화면·실패복구까지 구현하여 서비스 오픈 수용 기준을 충족한다.

**Architecture:** FastAPI·PostgreSQL RLS/RPC와 독립 React 사용자/관리자 앱을 유지한다. 불변 자산 버전과 실행 스냅샷을 기반으로 카탈로그·Builder·승인·연계 기능을 순차 확장한다.

**Tech Stack:** 현재 저장소의 Python/FastAPI, PostgreSQL/pgvector, React19, TypeScript7, Vite8, pytest, Playwright.

**Spec:** [[09 전체 기능명세서 기준 개발 완료 여부 검토 보고서]], [[10 전체 화면과 기술요건 구현 대조표]], [[비거버넌스 확장 개발 요구 추적표]], [[비거버넌스 하위요구 수용기준]].

## 이번 묶음의 기능 계약

DP09-01은 새 Agent 자산 등록과 버전 보존을 실제 관리자 앱에서 제공한다. DP09 전체 완료가 아니다. 자산 종류는 이번에 agent만 제공하고 Prompt/Workflow/Tool/Model은 해당 실행 스키마가 준비되는 후속 묶음에서 추가한다. F004/019/024/032/046/047/049의 기반 일부이며 전체 F 완료 판정은 유지한다.

`portal.assets`: tenant_id/asset_id/owner_id/client_request_id/legacy_agent_key/latest_revision/created_at. 기존 fixed2는 읽기 전용 view에서 tenant/agent_key 기반의 결정적 UUID alias로 투영하고 기존 설정·run snapshot은 수정하지 않는다. 새 tenant에도 같은 투영이 적용되므로 조회 중 쓰기나 별도 backfill 없이 연결된다. 저장 당시 초안의 지문과 달리 fixed alias 지문은 현재 관리 설정의 지문이며 실행 snapshot이 아니다. fixed alias는 읽기 전용이며 기존 Agent 관리/승인 화면에서 수정한다.

`portal.asset_versions`: tenant_id/asset_id/revision/version_id/config_hash/config/created_by/created_at. 새 config는 name(1~80), description(0~500), instructions(1~2000), execution_kind(general|rules_rag)만 받는다. DB 계산 SHA256로 내용 지문을 저장한다. 초안 버전은 INSERT만 허용하며 UPDATE/DELETE 금지. 게시/활성버전 컬럼은 승인 계약이 준비되는 DP12에서 추가한다. 초안을 운영/배포 완료로 표시하지 않는다.

모든 RPC는 tenant_transaction 세션 context와 DB operations_authorize를 다시 검사한다. TADMIN 및 해당 tenant 관리 권한 PADMIN만 읽기/등록/개정 가능하다. USER·타조직·회수 권한은 차단한다. 직접 테이블 접근은 ai_web/index/meter 모두 차단, 내용/지시문은 목록에 포함하지 않는다. audit에 내용 대신 opaque ID와 revision만 저장한다.

| API | 입력·출력 | 실패/재시도 |
|---|---|---|
| GET /api/v1/admin/assets | limit1~50/cursor UUID → items(메타데이터)/next_cursor | 잘못된/타조직 cursor404, 중복/알수없는 query422 |
| GET /api/v1/admin/assets/:id | 자산 최신 config와 revisions(내용 제외) | 타조직404 |
| POST /api/v1/admin/assets | client_request_id UUID + config → id/revision/version/hash/replayed | 같은 요청/동일 내용200, 다른 내용409, 신규201 |
| POST /api/v1/admin/assets/:id/versions | client_request_id + expected_revision 엄격정수 + config | CAS409, 동일 요청 결과 재현200, 새 버전201, fixedalias409 |

append 요청은 asset lock을 잡고 immutable version을 추가하며 asset latest_revision만 CAS 증가한다. 버전별 client_request_id UNIQUE와 config 비교로 네트워크 결과 불명시 같은 요청 재확인 가능하다. 생성/개정은 같은 transaction에서 audit를 기록하고 audit 실패시 전체 rollback한다. 신규 run 실행은 이번 묶음에 연결하지 않으므로 모델 호출/예산 차감이 없다.
