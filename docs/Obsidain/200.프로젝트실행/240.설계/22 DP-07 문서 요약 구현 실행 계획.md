# DP-07 문서 요약 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 승인된 단일 문서의 원문 발췌 요약·재생성·Markdown 내려받기를 사용자 화면에서 실행한다.

**Architecture:** 현재 rules_rag 설정·중앙 permit/ledger를 사용하되 task_kind=document_summary와 별도 summary 요청/근거 저장으로 규정 답변과 구분한다. 모델은 후보 ID만 선택하며 서버가 원문·지문·현재권한·정책을 검증한 결과만 표시한다.

**Tech Stack:** 현행 Python3.13/FastAPI/PostgreSQL·React/TypeScript/Vite/Playwright, 기존 tokenizer와 모의 provider. 신규 라이브러리 없음.

**Spec:** [[21 DP-07 문서 요약 1차 상세 설계]]. 사용자의 2026-10-07 ‘네 진행 바랍니다’로 설계 승인. [[15 DP-07 문서 요약 1차 수용 기준]] S01~12를 구현/시험한다.

## Global Constraints

- PPTX·OCR은 후속 보류. AI 거버넌스 포털 제외. 기관 연계와 새 모델 도입 없음.
- 문서/버전1개, 핵심3/5개, 전체 입력6,000토큰, 후보128개, 생성 출력512토큰, 생성 호출 최대1회, 요약 자체 임베딩0회.
- 개발 검증 유료 호출0회. 현재 승인된 설정·요금 snapshot·cap 유지, 실제 품질 검증은 미실행으로 표시.
- 사용자/조직/권한은 인증 컨텍스트, 서버 request extra forbid. current source/worker/epoch/config/policy 재검증과 원장 unknown 보존.
- 인용은 quote==canonical[start:end]와 실제 rag.evidence/hash/location을 확인한다. 규정 relation seal을 완화하지 않는다.
- 모의 fixture는 disposable DB만 사용. 주DB reset/reseed 금지. DB fixture/화면 시험은 순차 실행.
- 개발 전부터 존재한 원래32개 테이블 열/행과SQL000~024 파일 지문 보존 비교. 새 migration025에서 신규 열/테이블/함수/제약을 명시.
- 로그와 공개 증거에 원문/키/비밀번호/DSN을 출력하지 않는다. .runtime private 기록은0600.
- 다른 작업·과거 미추적 문서는 일괄 stage하지 않는다. 각 task의 소스/시험만 commit.
