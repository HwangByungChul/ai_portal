# 요구정의 검토 결과와 후속 전달

## 종합 상태

2026-10-04 사용자 지시에 따라 R220-07의 문서 종합 점검과 결과 정리를 수행했다. R220-01~06의 문서 작성·자체 점검은 완료했으며 R220-07의 사용자 최종 요구 검토/기준선 확정은 대기다. 210 종합 문서도 최종 검토 대기 상태로 유지한다. 사용자의 각 문서 작성 진행 지시를 전체 명세 승인이나 앱 구현 착수 승인으로 확대하지 않는다.

## 유지하는 필수 기준

- 일반/RAG 고정 Agent2와 사용자·관리자 화면을 실제 공통 업무/모델 호출에 연결한다.
- 조직 A/B와 조직 내 개인 자료를 보호한다. 관리자도 자동으로 개인 문서/대화 본문을 조회하지 않는다.
- 조직 전환은 신규 요청의 문맥을 변경하며 원래 문서/대화/Job 소유를 바꾸지 않는다. 늦은 이전 조직 응답을 새 화면에 섞지 않는다.
- GraphRAG는 허용 문서/관계별 근거를 연결하고 근거 부족/검색 오류/권한 거부를 구별한다.
- 삭제/공유 회수 후 신규 검색·근거·원문을 차단하며 진행 Job이 자료를 재공개하지 못하도록 한다.
- 대화·문서·실행/Job·usage 상태를 지속 저장한다. 부분 실패/취소 접수/불명 usage를 완료/무료로 표시하지 않는다.
- 생성/문서·질의 임베딩을 공통 AI·단일 usage 원장으로 처리하고 Agent/공통 중지·조직/프로젝트 한도를 적용한다.
- 저비용 기본 모델과 10월3만원 상한을 유지한다. 모델 선택 화면·유료 비교·정교한 과금·별도 Gateway 제품을 추가하지 않는다.

## 역할 세부 배분의 검토 지점

요구 초안의 구체적 배분은 일반 사용자 본인 기록/허용 자료 조회, 조직 관리자 현재 조직 운영, 플랫폼 관리자 명시적 관리 조직 및 프로젝트 최소 운영이다. 조직 관리자의 관리자 승격과 플랫폼 관리자 자기승격은 허용하지 않는다. 조직 소속 비활성화와 전역 계정 정지를 구분한다.

개인 자료 시험은 관리자 합성 등록으로 준비하고 사용자 파일 업로드 화면을 필수에 추가하지 않는다. 조직 공유는 원 소유 조직의 문서 특정 버전·수신 조직 Grant에 한정하며 개인 자료의 타 조직 공유/수신 재공유는 제외한다. 조직 관리자는 상위 배정 이하 한도를 적용하고 플랫폼 관리자도 승인 예산을 임의 확대하지 않는다. 이 세부 배분은 이번 종합 요구 검토의 대상이다.

## 종합 자체 점검과 수정

요구/검증 ID41개의 중복/누락·일대일 연결과 링크를 확인했다. IN12와 ACL16 연결을 대조했고 모의 호출은 실제 DB/RLS·Job 검증을 대체하지 않도록 명시했다. D-S 공유 문서의 원 소유 조직을 A로 명확히 기록했다. 각 V의 다중 행동은 하위별 판정하며 대표 행동 하나로 전체 통과를 표시하지 않는다.

문서 단계에서 권한/Agent/상태/usage 책임의 충돌은 발견하지 않았다. 이 판단은 코드 동작/보안 시험 결과가 아니다. NFR 성능 목표값은 240 환경·측정 계약과 실측이 있어야 판정하며 현재 SLA/성능 합격을 주장하지 않는다.

## 후속/제외 범위

기업 SSO·물리 테넌트 분리·GPU/HA·자유 Agent Builder/MCP·전체 Marketplace·다중 모델 선택·고급 과금/결재·전체 Office/OCR·사용자 대화 공유/조직 간 이동은 후속이다. 원 RFP 전체 조항의 완전 추적은 이번 MVP 기준선과 구분한다. 230은 실제 확인한 코드/화면만 근거로 분류한다.

## 230 전달

[[200.프로젝트실행/230.분석/01 분석 상세 작업 계획]]에 따라 기존 GraphRAG/백엔드/화면의 확인 버전·요구별 재사용/수정/신규·합성6문서/관계/질문20개·핵심 Gap와240 전달을 정리한다. 역사 검토를 현재 코드 사실로 단정하지 않고 원본을 다시 대조한다. 원본 코드/제안 자료는 보존하며 분석 단계에서 앱 코드를 복사·변경하지 않는다.

## 240 전달

세션/권한 재검사·RLS/파일/캐시·공유 버전/회수·개인 문서 운영/본문 분리·API 계약·화면 상태·실행/Job/취소/중지 전이·한도값/예약/불명 정산·재처리·과거 인용 표시·초기화/재현·성능 목표/환경을 상세 설계한다. 권한/포털/AI·usage/GraphRAG 검증 단위별 구현계획은240명세 이후 작성한다.

## 사용자 종합 검토와 완료 조건

210 종합 구조와 위 역할·권한/기능/검증 범위를 함께 검토받는다. 수정 의견이 있으면 관련 요구와 추적표를 함께 수정한다. 사용자 종합 확정 후에만 요구 기준선을 approved로 바꾸고230분석을 본 수행한다. 작성/자체 점검과 최종 승인·구현/시험 완료는 각각 기록한다.
