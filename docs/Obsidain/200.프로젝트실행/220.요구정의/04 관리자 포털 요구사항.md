# 관리자 포털 요구사항

## 작성 상태와 입력

R220-04 요구 초안 작성 및 자체 점검을 완료했다. 실제 화면/API/색인/권한 시험 결과가 아니며 최종 요구 검토는 R220-07에서 묶어서 진행한다. 선행 210 종합 검토 대기 상태를 소급 승인으로 바꾸지 않는다.

기준: [[100.프로젝트계획/03 프로젝트계획서]], [[200.프로젝트실행/210.아키텍처정의/04 아키텍처 검토 결과와 후속 전달]], [[200.프로젝트실행/220.요구정의/02 액터와 권한 정의서]], [[200.프로젝트실행/220.요구정의/03 사용자 포털 요구사항]]. 원 RFP 조항/시연 화면과의 일대일 추적은 아직 수행하지 않았다.

## 관리 흐름·공통 조건

로그인 → 허용 관리 조직 선택 → 사용자/문서/Agent/usage 업무 선택 → 대상과 현재 권한 확인 → 변경/처리 → 실제 상태/결과 조회로 이어진다. 플랫폼의 공통 합산/운영 중지는 조직별 콘텐츠 조회와 별도 권한 경계다.

모든 조직 관리 요구는 현재 조직 범위에 한정하고 플랫폼 관리자도 무조건 조직/개인 ACL을 우회하지 않는다. 관리자 개인 자료 운영과 본문 열람을 구분한다. 작업 변경에는 수행 주체·조직·대상·행동·결과를 최소 기록하며 본문·프롬프트·비밀을 포함하지 않는다. 별도 복잡한 감사 대시보드 구축은 추가하지 않는다.

아래 13개 요구는 필수 초안이다. 각 요구의 상세 UI/필드·API·SQL·상태 전이는 240에서 설계한다. 조직 생성/폐쇄·기업 SSO·자유 Agent Builder·다중 모델 선택·정교한 과금/결재는 후속이다.

| AP-007 | 문서 삭제·신규 접근 차단 | V-019 |

## AP-001 관리 조직 선택과 관리 진입

- **근거:** 100 승인 관리 범위, 210 IN-01·IN-05·IN-10, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 활성 관리 권한 및 허용 조직 소속.
- **입력:** 관리 조직 선택/전환 또는 관리 화면 요청.
- **정상 결과:** 현재 관리 조직을 명시하고 해당 조직의 관리 메뉴·자료만 표시한다.
- **거부/실패 결과:** 일반 사용자 또는 관리 권한 없는 조직 요청은 거부한다. 직접 관리 API 요청도 검사한다.
- **접근 범위:** 현재 허용 관리 조직.
- **수용 기준·V-013:** A 관리자 B 관리 진입/ID 요청 거부; A→B 전환 시 이전 조직 자료와 늦은 응답 미표시. 플랫폼 관리자도 명시적 관리 소속 없이 진입 불가.

## AP-002 조직 사용자·소속·활성 상태 관리

- **근거:** 100 승인 관리 범위, 210 IN-05, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 관리 권한.
- **입력:** 사용자 목록/소속 조회·소속 활성 상태 변경.
- **정상 결과:** 현재 조직 소속과 필요한 최소 사용자 정보를 표시하고 조직 소속 활성/비활성 결과를 저장한다.
- **거부/실패 결과:** 다른 조직 소속 조회/변경은 거부한다. 조직 소속 비활성화를 계정 전체 정지로 처리하지 않는다.
- **접근 범위:** 현재 조직 사용자 소속, 전역 계정 생성/삭제·정지는 후속 운영 범위.
- **수용 기준·V-014:** 동일 사용자 A 소속 비활성화 후 A 신규 요청 거부, 활성 B 소속은 유지. 오래된 로그인 화면/토큰으로 A 신규 요청 우회 불가.

## AP-003 조직 역할 배정·회수

- **근거:** 100 승인 관리 범위, 210 IN-05, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 관리 권한과 역할별 변경 허가.
- **입력:** 대상 사용자/소속과 역할 변경.
- **정상 결과:** 조직 관리자는 일반 사용자 범위에서 관리하고, 허용 플랫폼 관리자는 해당 조직 관리자 배정/회수를 수행한다.
- **거부/실패 결과:** 일반 사용자 역할 변경·조직 관리자의 관리자 승격·플랫폼 관리자 자기승격/플랫폼 관리자 신규 부여는 거부한다.
- **접근 범위:** 현재 조직의 역할, 플랫폼 관리자 초기 부여는 별도 초기화/운영 절차.
- **수용 기준·V-015:** 권한 없는 승격에서 역할 불변; 조직 관리자 회수 후 기존 관리 화면의 새 변경 요청 거부. 변경 대상·주체·결과를 기록하되 비밀은 포함하지 않는다.

## AP-004 문서 등록·범위 지정

- **근거:** 100 승인 관리 범위, 210 IN-06·IN-07, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 문서 관리 권한.
- **입력:** 합성 TXT/Markdown 파일·조직/개인 범위·개인 문서 소유/허용 대상.
- **정상 결과:** 문서와 버전·범위를 등록하고 실제 색인 작업 상태와 연결한다. 동일 내용/색인 버전의 불필요한 재임베딩을 방지한다.
- **거부/실패 결과:** 지원하지 않는 형식·설정된 크기 상한 초과·타 조직 소유/허용 대상 지정은 거부한다. 등록만으로 색인 완료를 표시하지 않는다.
- **접근 범위:** 현재 조직 소유 문서, 개인 자료는 지정된 같은 조직 소유/허용 대상.
- **수용 기준·V-016:** 정상 TXT/Markdown 등록→문서/작업 ID·실제 상태 조회; 오류 파일 거부→색인/모델 호출 없음. 초기 문서 5~10개를 수용하며 등록 관리 책임이 개인 본문 재조회 권한으로 확대되지 않는다.

## AP-005 문서·색인 상태 및 오류 조회

- **근거:** 100 승인 관리 범위, 210 IN-06·IN-12, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 문서 운영 권한.
- **입력:** 문서/Job 목록·상세 상태 요청.
- **정상 결과:** 등록·처리중·완료·실패/중단을 실제 단계/검증 결과와 구분해 표시한다. 완료 여부는 필요한 벡터/Graph/근거 산출물 검증을 반영한다.
- **거부/실패 결과:** 타 조직 Job 상태와 파일 접근은 거부한다. 개인 문서 ACL이 없으면 제목/본문/청크/프롬프트를 오류/상태에서 노출하지 않는다.
- **접근 범위:** 현재 조직 운영 상태, 개인 자료는 문서 ID·단계·오류 코드 등 최소 정보.
- **수용 기준·V-017:** Graph 저장/근거 검증 실패→색인 완료 아님; 재시작 후 미완료 상태 유지; 개인 콘텐츠와 공급자 비밀이 상태/오류에 나타나지 않는다.

## AP-006 실패 색인 작업 재처리

- **근거:** 100 승인 관리 범위, 210 IN-06·IN-09·IN-12, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 실패/중단된 현재 조직 작업, 현재 문서/주체 권한·한도 확인.
- **입력:** Job/문서 버전과 재처리 요청.
- **정상 결과:** 현 권한/버전/한도를 재검사하고 재처리 결과를 원래 작업과 추적 가능하게 기록한다.
- **거부/실패 결과:** 삭제·권한 회수·한도 초과·중복 진행 요청은 거부한다. 기존 실패를 무조건 완료로 바꾸거나 무제한 자동 재시도하지 않는다.
- **접근 범위:** 현재 조직 허용 Job, 저장소/호출의 중복 방지 경계.
- **수용 기준·V-018:** 회수 문서 재처리→새 임베딩/자료 공개 없음; 반복 재처리 클릭→같은 산출물/usage 중복 방지; 실제 실패 결과 보존. 재처리 식별·단계 복구 계약은 240에서 설계한다.

## AP-007 문서 삭제·신규 접근 차단

- **근거:** 100 승인 관리 범위, 210 IN-07·IN-11, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 소유 문서 관리 권한.
- **입력:** 삭제 대상 문서 ID와 확인 요청.
- **정상 결과:** 삭제 상태를 기록하고 신규 검색·인용·원문/다운로드를 차단한다. 연관 처리 작업이 삭제 자료를 다시 공개하지 않도록 한다.
- **거부/실패 결과:** 수신 공유 문서를 원본 소유자처럼 삭제할 수 없다. 삭제 실패를 완료로 표시하지 않는다.
- **접근 범위:** 현재 조직 소유 문서의 관리, 다른 유효 그래프 관계/근거 보호.
- **수용 기준·V-019:** 삭제 후 검색·과거 근거 링크 접근 차단; 진행중 Job 완료 시 자료 재공개 없음; 동일 개체의 다른 허용 문서 근거까지 소실되지 않는다. 즉시 권한 차단과 물리 정리는 240에서 구분한다.

## AP-008 조직 문서 버전 공유 승인·회수

- **근거:** 100 승인 관리 범위, 210 IN-07, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 원 소유 조직 관리 권한, 공유 가능한 조직 문서 버전.
- **입력:** 문서 버전·수신 조직·승인/회수 요청.
- **정상 결과:** 특정 조직 문서 버전에 수신 조직 Grant를 기록하고 회수 후 신규 조회/검색/근거 접근을 차단한다.
- **거부/실패 결과:** 개인 문서 타 조직 공유·수신 조직의 재공유/원본 변경·미허용 원 소유 조직 관리는 거부한다.
- **접근 범위:** 허용 원 소유 조직→지정 수신 조직의 특정 버전, 전 조직 기본 공개 금지.
- **수용 기준·V-020:** A 문서 v1 공유→B에서 v1만 허용; v2 생성으로 자동 공유되지 않음; 회수 후 B의 검색/과거 근거 링크 차단. 복잡한 다단계 결재와 대화 공유는 포함하지 않는다.

## AP-009 고정 Agent 기본 설정

- **근거:** 100 승인 관리 범위, 210 IN-08, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 고정 Agent 관리 권한.
- **입력:** Agent의 표시명·설명·일반/RAG 고정 유형 내 기본 지시문 변경.
- **정상 결과:** 허용 설정과 버전을 저장하고 신규 실행이 적용 설정을 식별할 수 있게 한다.
- **거부/실패 결과:** 무권한 조직/Agent 변경·임의 모델/도구/외부 URL/DB 권한 부여는 거부한다. 설정 오류가 있으면 기존 유효 설정을 유지한다.
- **접근 범위:** 현재 조직의 고정 Agent 2개, 설정으로 사용자/문서 권한 확대 불가.
- **수용 기준·V-021:** A 설정 변경→A 신규 실행에 버전 반영, B 설정/완료 기록 불변. 모델명·키는 사용자 편집 항목에서 제외하며 복잡한 Builder/Prompt 승인 체계는 후속이다.

## AP-010 Agent 중지·재개

- **근거:** 100 승인 관리 범위, 210 IN-02·IN-08, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 Agent 관리 권한.
- **입력:** 고정 Agent 중지/재개 요청.
- **정상 결과:** 중지 상태와 변경 결과를 저장하고 신규 실행/재시도를 차단한다. 재개 시에도 현재 사용자 권한·프로젝트/조직 한도를 다시 검사한다.
- **거부/실패 결과:** 타 조직 중지 요청은 거부한다. 재개가 공통 운영 중지나 한도를 자동 해제하지 않는다.
- **접근 범위:** 현재 조직 Agent, 프로젝트 전체 중지는 AP-013.
- **수용 기준·V-022:** A Agent 중지→A 새 질의 실제 모델 미호출, B 상태 불변; 재개 후 한도 초과 요청 계속 거부. 진행중 호출의 취소/종결 계약은 240에서 설계하고 이미 발생한 usage를 보존한다.

## AP-011 조직 사용량·호출 상태 조회

- **근거:** 100 승인 관리 범위, 210 IN-09, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 사용량 운영 권한.
- **입력:** 기간/Agent 등 최소 조회 조건.
- **정상 결과:** 공통 원장 기반의 생성/임베딩 사용량과 확정/추정/불명 상태, 조직 한도/중지 상태를 표시한다.
- **거부/실패 결과:** 타 조직 또는 일반 사용자의 조직 집계 접근을 거부한다. 원장 임의 수정·불명 usage 0 처리·타인 질문/응답 본문 조회는 허용하지 않는다.
- **접근 범위:** 현재 조직 운영 집계/최소 호출 정보, 별도 중복 과금 원장 없음.
- **수용 기준·V-023:** 색인 임베딩도 조직 집계에 반영; 실패/불명 상태 구별; usage 화면에서 개인 프롬프트·대화·키 비노출. 정교한 원화 분석/기관 정산 기능은 포함하지 않는다.

## AP-012 조직 한도 설정

- **근거:** 100 승인 관리 범위, 210 IN-09, 220 액터/권한 정의.
- **액터·우선순위:** ACT-TADMIN / ACT-PADMIN · 필수.
- **선행 조건:** 현재 조직 한도 변경 권한과 상위 배정 확인.
- **입력:** 최소 조직 실행/토큰/사용량 한도 설정 요청.
- **정상 결과:** 조직 관리자는 상위 배정 이하의 더 제한적인 운영 한도를 적용한다. 플랫폼 관리자는 프로젝트 합산 상한 안에서 허용 조직의 배정을 관리한다.
- **거부/실패 결과:** 음수/형식 오류·상위 배정 초과·타 조직 변경은 거부한다. 한도 감소로 실제 사용/불명 예약을 삭제하거나 0으로 만들지 않는다.
- **접근 범위:** 현재 조직 한도 및 프로젝트 공통 제약, 한도 단위/정확 값은 240 결정.
- **수용 기준·V-024:** 한도 감소 후 현재 확정/예약 사용이 새 한도 이상이면 신규 호출 차단; 동시 요청이 잔여 한도를 중복 사용하지 못하도록 CP 원장 계약과 연결. 복잡한 사용자별 요금제는 후속이다.

## AP-013 프로젝트 합산 조회·공통 운영 중지

- **근거:** 100 승인 관리 범위, 210 IN-09·IN-10, 220 액터/권한 정의.
- **액터·우선순위:** ACT-PADMIN · 필수.
- **선행 조건:** 플랫폼 운영 권한.
- **입력:** 프로젝트 합산 상태 조회·중지/재개 요청.
- **정상 결과:** 모든 생성/임베딩 호출의 합산 상태를 확인하고 신규 유료 호출/재시도를 공통 경로에서 중지한다. 재개 시 전체/조직 제한을 다시 확인한다.
- **거부/실패 결과:** 조직 관리자/일반 사용자 접근·승인 예산 30,000원 임의 확대·정산 원장 수동 수정은 거부한다. 재개로 한도를 우회하지 않는다.
- **접근 범위:** 프로젝트 최소 운영 집계, 조직별 콘텐츠 조회 권한과 분리.
- **수용 기준·V-025:** 공통 중지→일반/RAG 생성 및 문서/질의 임베딩의 신규 실제 호출 없음; 재개 후 한도 초과 여전히 거부. 고가 모델 자동 전환·자동 추가 결제 없음; 앱 추정을 청구액 보장으로 표시하지 않는다.

## 사용자 요구와 연결

AP-001~003은 UP-001/002/011의 로그인·조직 전환·권한 변경 안내에 연결한다. AP-004~008은 UP-006/009/012의 검색·근거·삭제/회수·근거 부족 조건에 연결한다. AP-009/010은 UP-003/004/007/011의 Agent 목록·실행·중지에 연결한다. AP-011~013은 UP-007/011의 호출 상태·한도 거부에 연결한다. 관리 변경 후 기존 화면/캐시의 표시만 믿지 않고 신규 서버 요청에서 현재 정책을 적용한다.

## 240 상세 설계 전달

역할 배정/회수와 소속 활성 상태의 원자성, 개인 문서 등록/본문 접근의 분리, 파일 크기·해시·색인 버전, 작업 재처리와 중복 호출 방지, 삭제 즉시 접근 차단 및 파생 자료 정리, 공유 버전/Grant 회수, 기본 지시문의 길이·검증·버전 적용, 진행중 실행과 중지 경합, 단일 usage 원장과 추정/불명·예약 상태, 한도 단위/환산 여유/동시 예약, 공통 중지의 적용 시점을 전달한다.

## 자체 점검

AP-001~013과 V-013~025의 중복/누락을 확인하고 각 요구의 액터·근거·입력·결과·범위·수용 기준을 점검했다. 개인 콘텐츠 자동 열람·조직 관리자 승격·수신 자료 변경·예산 임의 확대를 제한하고 UP의 상태/권한 안내와 연결했다. 등록/실패/재시도를 완료로 오표시하지 않도록 정의했다. 권한/Agent/한도 변경의 최소 기록은 공통 요구에 전달하며 별도 추가 제품 범위를 만들지 않았다. 문서 자체 점검 결과이고 실제 모델·UI·DB 시험은 없다.
