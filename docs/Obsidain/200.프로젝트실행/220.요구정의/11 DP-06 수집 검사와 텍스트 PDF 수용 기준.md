# DP-06 수집 검사와 텍스트 PDF 수용 기준

승인된 [[13 DP-06 파일 파서 확장과 수집 검사 상세 작업 계획]]의 P0/P1/P3를 첫 구현 묶음으로 수행한다. Office는 P2 후속 묶음이고 DP-18 전체 완료와 구분한다.

| ID | 수용 기준 |
|---|---|
| AC-P06-01 | 신규 TXT/Markdown/PDF의 제목·본문에서 정의한 주민번호·전화·이메일·계좌 및 명시적 지시 공격 패턴을 검사한다. 차단/검사 오류는 저장·게시·외부 색인 송신 전에 멈춘다. |
| AC-P06-02 | PDF는 application/pdf와 .pdf 파일명, 실제 %PDF- 시그니처 및 파서 검증을 모두 통과해야 한다. TXT/Markdown을 PDF로 위장하거나 PDF를 텍스트 MIME으로 제출하면 거절한다. |
| AC-P06-03 | 원본128KB, 추출40,000자/128KB,20페이지, 페이지당 펼친 스트림4MB, 파서 CPU2초/벽시계5초, 주소공간512MB 제한을 적용한다. OS에 격리 수단이 없으면 PDF를 실패 처리한다. |
| AC-P06-04 | 파서는 별도 제한 프로세스에서 네트워크·임의 파일 쓰기·프로젝트 비밀 파일 읽기를 차단한다. AI/PG/인증 환경 값을 전달하지 않는다. |
| AC-P06-05 | 암호·손상·첨부·스크립트/자동 실행·외부/수동 링크·양식·영상/파일 실행·이미지 전용/혼합 비텍스트 페이지는 거절하며 원문/파서 예외를 오류에 노출하지 않는다. |
| AC-P06-06 | PDF 원본과 추출 텍스트의 SHA-256을 각각 보존한다. 페이지 범위는 추출 텍스트 코드포인트 오프셋과 연결한다. 기존 RAG 증거 봉인 계약은 유지한다. |
| AC-P06-07 | 개인/관리자 업로드→색인→게시→질문 첨부→정확한 인용/페이지 표시→원본 PDF 다운로드가 동작한다. 다른 주체/조직은 원문·작업·질문을 우회하지 못한다. |
| AC-P06-08 | 이미 확정된 같은 접수 ID는 파싱·작업·색인 호출을 추가하지 않는다. 다른 원본은 충돌한다. 동시 최초 요청은 파싱을 재검증할 수 있으나 DB 작업과 호출은 하나다. |
| AC-P06-09 | 색인 직전에 현재 수집 정책을 재확인한다. 정책 차단은 알려진 실패 상태로 기록하고 호출 후 미확정 사용량과 구분한다. 기존 게시 자료 검색도 생성용 문맥 구성 전에 검사한다. |
| AC-P06-10 | 삭제·접근 회수는 원본/추출물/색인/기존 답변/근거/평가에 적용된다. 삭제 정리는 두 파일을 제거하고 기존 원장·감사·실행 출처를 보존한다. |
| AC-P06-11 | 기존 TXT/Markdown·관리자 버전/공유·개인 문서함·복구·요금·RAG·대화·평가를 회귀 검증한다. 기존 DB 열/행 보존,000~023 파일 지문 보존, 신규024만 적용한다. |

정책은 고정 document-ingest-v1 중앙 최소 규칙이다. 탐지 사례/오탐/미탐을 합성 fixture로 기록한다. 모든 개인정보·지시 공격 탐지, 일반 대화 입출력 정책, 기관 보안 적합성 또는 PDF 시각 레이아웃 완벽 재현을 주장하지 않는다. 파일 정책 차단은 원문을 격리 보관하지 않고 접수 거절한다.
