# 요구사항과 검증 추적표

## 상태와 추적 기준

R220-06 추적표 작성·문서 자체 점검을 완료했다. 필수 요구41개에 검증41항목을 연결했으며 **연결률100%는 문서 연결 상태**다. 실제 시험은 모두 미수행이며 통과율/품질 점수/기관 운영 적합성을 뜻하지 않는다. 최종 요구 검토는 R220-07에서 묶어서 수행한다.

입력: [[200.프로젝트실행/220.요구정의/02 액터와 권한 정의서]], [[200.프로젝트실행/220.요구정의/03 사용자 포털 요구사항]], [[200.프로젝트실행/220.요구정의/04 관리자 포털 요구사항]], [[200.프로젝트실행/220.요구정의/05 공통 기능과 비기능 요구사항]].

각 V는 묶음 검증이며 아래 수행 행동을 a/b/c 순서의 하위 시나리오로 분리해 기록한다. 예: V-001a 활성 로그인, V-001b 인증 실패, V-001c 로그아웃 후 접근이다. 각 행동에 해당 기대 결과를 대조하고 **모든 필수 하위 조건**에 증거가 있어야 V 전체 통과를 표시한다. 대표 행동 하나의 성공을 전체 V/요구 통과로 확대하지 않는다.

M은 제공자 모의 응답/오류 주입을 사용한다는 뜻이며 DB·RLS·저장/Job·UI를 전부 모의로 대체해도 된다는 뜻이 아니다. 저장소/동시/재시작 검증은 실제 구현 경계에서 수행한다. R은 승인 예산 안의 제한 실제 OpenAI 호출이며 키 값을 문서에 기록하지 않는다. M만 통과한 실제 모델 항목은 R 미수행 상태로 남긴다.

D-S v1/v2는 동일 문서의 두 버전이며 문서 개수를 늘려 세지 않는다. D-A-R1/R2의 공용 개체에는 서로 다른 근거를 연결해 교차 인용을 판별한다. 과거 저장 인용 본문 표시·물리 삭제·성능 목표/한도값은 240 승인 설계가 추가 입력이며 확정 전 해당 세부 시험은 실행 준비중으로 표시한다.

## 검증별 수행·기대 결과

각 항목의 필수 우선순위는 원 요구를 따른다. 기대 결과 문장은 원 수용 기준을 보존한다. 상세 실행 기록에서는 각 행동별 실제 결과/판정을 분리한다.

### V-001 — UP-001 로그인·로그아웃

- **사전 데이터·역할/조직:** F01 사용자 A-U1/비활성 계정.
- **수행 행동:** 활성 로그인 후 조직 목록 조회; 잘못된 정보/비활성 계정 로그인; 로그아웃 후 이전 인증정보로 신규 업무 요청.
- **기대 결과:** 활성 계정 로그인→허용 조직만 표시; 잘못된 로그인→업무 데이터 미반환; 로그아웃→이전 인증정보의 새 요청 거부. 비밀번호/키는 화면 오류에 노출하지 않는다.
- **검증 단계:** 260→280.
- **호출/실행 구분:** M.
- **실제 결과·판정:** 미수행. 증거 파일/실행 기록은 아직 없다.

### V-002 — UP-002 조직 선택·전환

- **사전 데이터·역할/조직:** F01 A/B 겸임 DUAL, F03 A 대화, F07 지연 응답.
- **수행 행동:** A 대화/질문 표시 중 B 전환; A 지연 응답 수신; B 문맥으로 A 대화 ID 요청.
- **기대 결과:** A→B 전환 시 A 대화/근거/질문 입력을 B 화면에서 제거하고 늦게 도착한 A 응답을 B에 표시하지 않는다. A 대화 ID를 B 문맥으로 요청하면 거부한다.
- **검증 단계:** 260→280.
- **호출/실행 구분:** M.
- **실제 결과·판정:** 미수행. 증거 파일/실행 기록은 아직 없다.

### V-003 — UP-003 허용 Agent 목록·선택

- **사전 데이터·역할/조직:** F01 A-U1, F04 허용/미허용·중지 Agent.
- **수행 행동:** 허용 목록 조회; B 전용 ID 직접 실행; 중지 실행; 기존 대화에서 Agent 선택 변경.
- **기대 결과:** A에 허용되지 않은 Agent ID 실행은 거부; 중지 Agent는 실행 차단; 선택 변경은 기존 대화의 Agent/조직 소유 정보를 덮어쓰지 않는다.
- **검증 단계:** 260→280.
- **호출/실행 구분:** M.
- **실제 결과·판정:** 미수행. 증거 파일/실행 기록은 아직 없다.

### V-004 — UP-004 질문 입력·전송

- **사전 데이터·역할/조직:** F01 A-U1, F06 사용량 초기값, 240 입력 상한.

- **기대 결과:** 공백/상한 초과 입력에서 실행/모델 호출 없음; 전송 버튼 반복 클릭과 통신 재전송으로 동일 전송의 실행/과금이 중복되지 않는다. 식별 방식/길이값은 240에서 정의한다.
- **검증 단계:** 260→280.
- **호출/실행 구분:** M.
- **실제 결과·판정:** 미수행. 증거 파일/실행 기록은 아직 없다.

### V-005 — UP-005 일반 질의 답변

- **기대 결과:** 일반 답변에 플랫폼 문서를 검색/인용한 것처럼 근거 목록을 꾸미지 않는다. 실제 모델 미연결 시 모의 응답 표시를 구분하고 실제 검증 완료로 기록하지 않는다.

위 연결은 ACL 시나리오를 해당 V의 하위 검증으로 **포함해야 한다는 요구**다. 예를 들어 V-020에는 개인 자료 공유 거부를, V-024/030에는 수동 원장 수정 거부를 반드시 추가한다. 수행 행동 요약에 모든 공격 변형을 나열한 것은 아니며 ACL 표를 실행 입력으로 함께 읽는다.

## 결과·증거 및 판정 규칙

실행 기록은 V/하위 ID·요구/ACL/Q 연결·버전·환경·사전 조건·행동·기대/실측·실제/모의·usage·증거 위치·통과/실패/미수행/실행 준비중·결함 ID를 갖는다. 실제 키·개인 본문을 증거에 그대로 복사하지 않는다. 결과 증거는 260/280, 설치 재현은 290, 최종 완료/미완료는300에 관리한다.

모듈 통과는 통합 통과를 대신하지 않는다. R 필수 시나리오가 미수행이면 모델 연결/품질은 미완료다. 모든 하위 필수 결과가 확인되기 전 V 전체를 통과로 표시하지 않는다. 권한 우회·관계 근거 교차·기록 소실·한도/중지 우회는 핵심 결함이며 남은 범위를 완료로 표시하지 않는다. 일반 답변 품질은 성공/실패 그대로 보고한다.

NFR-005 성능 합격은 240에서 승인한 환경/목표값과 실측이 있어야 판정한다. 현재 수치 합격 판정은 없다. 앱 비용 추정과 공급자 청구 대조를 구분하고 반복 권한/오류 검증은 M 중심으로 수행한다.
