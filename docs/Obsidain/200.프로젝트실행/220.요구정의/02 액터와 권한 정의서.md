# 액터와 권한 정의서

## 상태·입력

R220-01 입력 확인과 R220-02 문서 작성·자체 점검을 완료했다. 아래 상세 권한 배분은 기존 승인 방향에 맞춘 **요구 초안**이며 사용자 최종 승인 또는 실제 접근 통제 시험 결과가 아니다. 210 종합 문서의 최종 검토 대기 상태를 유지하고, 명백한 승인 범위에서 요구 초안을 준비한다.

입력은 [[100.프로젝트계획/03 프로젝트계획서]], [[200.프로젝트실행/210.아키텍처정의/01 테넌트 격리 아키텍처 검토]], [[200.프로젝트실행/210.아키텍처정의/02 시스템과 모듈 경계 정의서]], [[200.프로젝트실행/210.아키텍처정의/04 아키텍처 검토 결과와 후속 전달]]이다. 원 RFP 전체 역할 체계를 재현했다고 주장하지 않는다.

## 1. 권한 판정 공통 기준

인증된 활성 사용자 + 활성 조직 소속 + 현재 선택 조직 + 조직별 역할 + 자원 소유/허용 조건이 모두 일치할 때 요청을 허용한다. 메뉴 숨김은 권한 검사를 대신하지 않는다. 외부 조직 ID·자원 ID·파일 경로만으로 접근을 허용하지 않으며 서버와 저장소 경계에서 검사한다.

한 요청은 하나의 활성 조직에 속한다. 조직 전환은 신규 요청에 적용하며 기존 대화/Job/문서의 소유 조직을 변경하지 않는다. 소속 없는 조직은 선택할 수 없다. 같은 사용자의 A/B 역할도 각 조직에 한정한다. 조건 누락은 기본 거부한다.

## 2. 액터

| ID | 역할 | 사용 목적 | 경계 |
|---|---|---|---|
| ACT-USER | 일반 사용자 | 허용 Agent 질의, 본인 기록, 허용 문서/근거 조회 | 현재 조직 및 자원 ACL 범위 |
| ACT-TADMIN | 조직 관리자 | 현재 조직의 사용자·문서·색인·Agent·사용량 운영 | 현재 조직 관리 범위, 타인 개인 콘텐츠 조회 권한은 자동 부여하지 않음 |
| ACT-PADMIN | 플랫폼 관리자 | 허용 조직 선택 후 조직 운영, 관리자 역할 배정, 프로젝트 공통 한도·운영 중지 | 관리 가능한 조직을 명시적으로 부여, 전 조직 콘텐츠/DB RLS 우회 금지 |

관리자가 사용자 기능을 사용할 때도 ACT-USER와 같은 자원 접근 조건을 적용한다. 조직 A/B는 합성 초기 데이터로 구성하며 조직 생성/폐쇄 기능·기업 SSO는 이번 필수 범위에 추가하지 않는다. Job 실행자는 인간 역할이 아닌 시스템 주체로, 기록된 승인 범위를 소비하며 독자적으로 권한을 확대하지 않는다.

## 3. 자원 범위

| 범위 | 허용 조건 | 관리/공유 기준 |
|---|---|---|
| 개인 문서 | 같은 조직의 소유자 또는 명시적으로 허용된 동일 조직 사용자 | 타인/관리자 자동 열람 금지. 다른 조직 공유는 MVP에서 금지 |
| 조직 문서 | 해당 조직 활성 소속과 허용 조회 조건 | 해당 조직 관리자 등록/변경/삭제 |
| 조직 간 공유 문서 | 조직 문서의 특정 버전과 수신 조직 Grant, 원 소유 조직의 유효성 | 수신 조직은 조회만 가능하며 원본 변경·재공유 금지 |
| 대화/답변 | 같은 조직의 대화 소유자 | 관리자 자동 내용 조회·조직 간 이동·공유 제외 |
| Agent | 현재 조직에 허용된 고정 Agent, 실행 가능한 상태 | 설정/중지는 해당 조직 관리자 또는 허용 플랫폼 관리자 |
| Job/실행 | 현재 조직과 업무 권한, 본인 또는 허용 운영 범위 | 문서 본문을 상태 정보에 무단 포함하지 않음 |
| usage/한도 | 본인 또는 현재 조직 관리/프로젝트 운영 권한 | 원장은 시스템이 기록, 관리자가 임의 수정하지 않음 |

개인 문서 시험은 관리자가 합성 초기 자료를 지정 소유자로 등록하는 흐름으로 준비한다. 일반 사용자의 별도 파일 업로드 화면은 이번 필수 범위로 추가하지 않는다. 등록 과정의 관리 책임이 등록 이후 모든 개인 문서의 열람 권한을 뜻하지 않는다.

## 4. 자원별 권한표

표의 관리자 권한은 명시적으로 허용된 현재 조직에서만 유효하다. PADMIN 역시 조직별 관리 권한을 확인한다.

| 자원/행동 | 일반 사용자 | 조직 관리자 | 플랫폼 관리자 |
|---|---|---|---|
| 허용 조직 목록·선택 | 본인 활성 소속만 | 본인 활성 소속만 | 본인 명시적 관리 소속만 |
| 사용자 목록/소속·활성 상태 | 본인 최소 정보 조회 | 현재 조직 소속 조회·소속 활성/비활성 관리 | 허용 조직의 동일 관리, 전역 계정 정지는 별도 운영 권한 |
| 역할 변경 | 불가 | 일반 사용자 역할/소속 관리, 관리자 승격 불가 | 허용 조직의 조직 관리자 배정/회수, 자기승격/플랫폼 관리자 부여 불가 |
| 문서 검색·본문·원문/근거 | 자원 범위에 따라 조회 | 같은 자원 범위로 조회 | 같은 자원 범위로 조회 |
| 조직 문서 등록/내용 변경·삭제 | 불가 | 현재 조직 소유 문서 관리 | 허용 조직의 동일 관리 |
| 개인 문서 등록·색인 운영·삭제 | 등록 불가, 허용 문서 조회 | 지정 소유자/허용 대상 등록 및 상태 운영, 본문 재조회는 ACL 필요 | 허용 조직에서 동일, 본문 재조회는 ACL 필요 |
| 조직 간 공유 승인·회수 | 불가 | 현재 조직 소유의 조직 문서 버전만 공유/회수 | 허용 원 소유 조직에서 동일 |
| 수신 공유 자료 변경/삭제·재공유 | 불가 | 불가 | 원 소유 조직 권한으로 전환하기 전 불가 |
| Agent 목록·실행 | 허용 Agent만, 중지/한도 상태 검사 | 동일 | 동일 |
| Agent 설정·중지/재개 | 불가 | 현재 조직의 고정 Agent | 허용 조직의 고정 Agent, 공통 운영 중지는 플랫폼 권한 |
| 대화 생성·내용/기록 조회·본인 실행 취소 요청 | 본인/현재 조직 | 본인/현재 조직 | 본인/현재 조직 |
| 타인 대화 내용/프롬프트 조회 | 불가 | 불가 | 불가 |
| 색인 Job/오류 조회·실패 작업 재처리 요청 | 허용 문서의 최소 조회만 | 현재 조직 운영 상태, 재처리 시 현 권한/버전/한도 검사 | 허용 조직의 동일 운영 |
| Job 상태 임의 완료 변경 | 불가 | 불가 | 불가 |
| 본인 사용량 조회 | 본인 | 본인 | 본인 |
| 조직 사용량·한도 조회 | 본인 범위만 | 현재 조직 집계/최소 운영 정보 | 허용 조직 집계/최소 운영 정보 |
| 조직 한도 변경 | 불가 | 현재 조직의 더 제한적인 한도 적용, 상위 배정 초과 불가 | 프로젝트 잔여/상한 안에서 조직 배정 관리 |
| 프로젝트 합산 한도·운영 중지 | 불가 | 조회/변경 불가 | 기본 합산 조회·중지, 사용자 승인 예산 30,000원 임의 확대 불가 |
| usage 원장 삽입·수정 | 불가 | 불가 | 불가, 별도 시스템 정산 경로만 허용 |

사용자 계정 자체와 조직 소속의 상태는 구분한다. 조직 A 소속 비활성화가 동일 사용자의 조직 B 소속 또는 전역 계정을 자동 정지시키지 않는다. 플랫폼 관리자 초기 부여는 합성 초기화/운영 절차로 수행하며 화면의 일반 역할 변경으로 부여하지 않는다.

개인 문서 관리 상태/오류에는 업무상 필요한 문서 식별자·처리 단계·오류 코드만 표시하고 본문·청크·프롬프트·민감 제목을 노출하지 않는다. 개인 문서 내용 갱신은 자동 관리자 권한으로 열지 않고, 내용 접근 ACL이 있는 주체의 범위로 제한한다.

## 5. 변경·삭제·공유 회수

- 역할·소속·사용자 활성 상태 변경 후 신규 요청은 최신 권한을 검사한다. 오래된 화면/토큰만으로 이전 권한을 계속 사용하지 않는다.
- 기존 Job은 승인 당시 정보와 현재 소속·문서 권한을 실행/재시도 및 공개 단계에서 검사한다. 회수된 권한으로 새 자료 공개/새 호출을 허용하지 않는다.
- Agent 중지는 신규 실행/재시도를 차단한다. 실행중 요청의 중단 방식은 240 상태 설계에서 정하고 이미 발생한 비용을 0으로 처리하지 않는다.
- 공유 회수/문서 삭제 후 신규 검색·근거 조립·원문 접근은 차단한다. 과거 대화의 근거 링크/미리보기는 현재 문서 권한을 적용한다.
- 이미 전달된 답변을 사용자 기억/외부 복사에서 회수할 수 있다고 주장하지 않는다. 과거 대화에 저장된 인용 본문 표시 정책은 240에 전달한다.
- 자원 변경·권한 변경은 수행 주체·조직·대상·행동·결과를 기록한다. 개인 본문이나 API 키를 활동 기록에 포함하지 않는다.

## 6. 거부 시나리오와 검증 입력

아래 ACL ID는 이 문서의 검증 입력이다. R220-06에서 요구 ID 및 V 검증 ID에 연결하며 현재 실제 시험 결과가 아니다.

| ID | 사전 조건/행동 | 기대 결과 |
|---|---|---|
| ACL-01 | A 사용자로 B 조직 선택/문서 ID 직접 접근 | 조직 선택 거부, 본문/제목/청크/근거/파일 미반환 |
| ACL-02 | A 사용자로 A 내 타인 개인 문서/대화 접근 | 내용·검색 결과·원문 접근 거부 |
| ACL-03 | A 관리자로 타인의 개인 문서/대화 본문 접근 | 관리자 역할만으로 열람 불가, 운영 상태는 최소 범위 |
| ACL-04 | A 관리자로 B 사용자·Job·Agent 설정 변경 | 조회/변경 거부, B 상태 불변 |
| ACL-05 | USER가 역할 변경, TADMIN이 관리자 승격 요청 | 거부, 기존 역할 유지 |
| ACL-06 | PADMIN이 관리 소속 없는 조직 또는 전역 개인 콘텐츠 조회 | 거부, 조직/개인 ACL 우회 없음 |
| ACL-07 | A/B 겸임 사용자가 A 대화 ID를 B 활성 조직에서 요청 | 거부, 조직 전환으로 자원 소유 변경 없음 |
| ACL-08 | 역할/소속 회수 후 이전 화면/토큰으로 새 요청 | 최신 권한 거부, 신규 모델 호출 없음 |
| ACL-09 | A 조직 문서 특정 버전 공유 후 B 조회, 이후 Grant 회수 | 승인 버전만 조회, 회수 후 검색/근거 링크 접근 차단 |
| ACL-10 | B 관리자가 A 수신 공유 자료를 변경/재공유 | 거부, 원 소유 자료/Grant 불변 |
| ACL-11 | 개인 문서를 다른 조직 공유 대상으로 지정 | 거부, Grant 생성 없음 |
| ACL-12 | 문서/소속 회수 이후 색인 Job 재시도·완료 공개 | 현재 권한 재검사, 무권한 호출/자료 공개 차단 |
| ACL-13 | 중지 Agent 신규 실행 또는 한도 초과 요청 | 거부, 실제 모델 호출 없음 |
| ACL-14 | 동시 A/B 요청·실패·연결 풀 재사용 | 서로의 조회/쓰기/상태 결과 혼입 없음 |
| ACL-15 | 조직 관리자 또는 플랫폼 관리자가 타인의 질문을 usage에서 조회 | 원문 미반환, 허용된 최소 운영 정보/집계만 제공 |
| ACL-16 | 조직 관리자 한도를 상위 배정 이상 변경 또는 원장 직접 수정 | 변경 거부, 원장/상위 한도 불변 |

인증 실패는 로그인/인증 오류로 처리한다. 인증된 사용자의 자원 무권한은 다른 조직 자원의 존재·제목·내용을 오류에 노출하지 않는다. 정확한 HTTP 코드와 오류 계약은 240에서 정의한다.

## 7. 후속 문서 전달

사용자 요구는 위 권한을 로그인·조직 선택·Agent·대화·근거 화면 흐름에 적용한다. 관리자 요구는 역할 승격 제한·문서 운영/본문 접근 차이·공유 소유 조직·조직 한도 범위를 반영한다. 공통 요구는 상태 변경 후 재검사·Job·RLS·원장·최소 활동 기록을 반영한다.

240 전달 항목은 실제 세션/역할 저장 방식, 관리자 등록과 개인 문서 본문 ACL, 소속 회수/Job의 처리 상태, 공유 버전과 과거 인용 본문 표시, 한도 변경의 단위/원자성이다. 이번 문서의 요구 의미를 상세 설계로 구현하며 SQL/API 경로를 여기서 선확정하지 않는다.

## 자체 검토 결과
