# C06 합성 자료·Q20 통합 검증 결과

C01~C05 기능을 실제 API/DB에 연결해 합성7개 버전을 등록·색인하고 질문20개를 모의 공급자로 평가했다. 최종 **20/20개 기대 결과 통과**다. 답변12개·근거 부족4개·무권한 거부4개이며 모두 답변을 반환하는 것을 성공으로 삼지 않았다. 실제 RAG 모델 품질은 준비 미완료로 blocked 상태다.

## 구현·입력 분리

평가 도구 `src/backend/scripts/c06_evaluate.py`와 경계 시험 `tests/test_c06_evaluation.py`를 추가했다. 도구는 자기 소유 표식 DB/UUID원문 폴더에서 실행하며 원문은 정상 업로드→Job→게시 API로 처리한다. 개인 owner와 v1→B Grant도 기존 API를 사용했다. evaluator의 정답 관계/EV/금지목록을 DB Graph INSERT나 모델 문맥에 넣지 않았다.

질문 실행 후 원문·버전·quote·Unicode구간·행과 관계별 근거를 대조한다. source 다운로드의 bytes SHA/no-store/nosniff도 확인한다. runtime에는 일반 질문/현재 요청 버전/같은 접수ID만 전달한다. 기존 manifest/Q20 원본의execution.status=not_run과 작성 지문은 보존하고 실제 실행 판정은 신규 증거에 기록했다.

## 발견·수정한 문제

첫Q20 관측은11개 기대 결과 통과/9개 불일치였다.7개는 질문 해석의 역할/대상 누락이고2개는 조건이 서버 렌더링에 존재하지만 evaluator가 한 문장 일치만 요구한 판정 문제였다. 별도로 삭제 검사는 이력 행0개를 잘못 기대했으며 설계대로 payload 제거와 식별자 보존을 확인하도록 수정했다.

순수 코어가 담당 부서와 승인 부서를 함께 요구하는 표현, '며칠 보관'과 기록 보관 책임 표현을 다루도록 보완했다. 현재 허용된 단일 자료의 개인 리허설은 명시된 소유자 이름 없이도 그 자료의 유일한 대상에 연결한다. 여러 개인 대상/불명 책임은 추정하지 않는다. 금리·금액 상한·파기 승인 등 고정 관계 범위 밖 질문은 근거 부족으로 남긴다. 정답용 팀명·일정·Q번호를 제품 로직에 추가하지 않았다.

문제는 먼저 새 시험으로 재현(4실패/5통과)한 후 수정했다. 평가 조건은 요청 접수 후/기한/이내를 각각 실제 렌더링에서 확인하며, 관계마다 자기 근거가 없으면 실패한다. 수정·강화 후 최종 native 전체Q20를 재실행했다.
