# DP-03 대화 이력 관리 구현 결과

## 구현 범위

사용자 포털의 ‘내 대화’에 제목 변경, 핀 고정·해제, 제목 검색, 핀 필터, 삭제 확인을 추가했다. 핀을 고정한 대화부터 표시하며, 같은 조건에서는 생성 시각과 ID를 기준으로 최신순으로 정렬한다. 목록과 변경 요청 모두 서버에서 본인 및 현재 조직의 권한을 검사한다.

이번 검색은 제목의 부분 문자열 검색이다. 답변 본문 검색, 답변 피드백, 저장 내용의 물리 삭제는 후속 작업이다. 기본 제목에 사용자의 질문 본문을 자동으로 복사하지 않는다.

## 데이터와 API

`021_conversation_metadata.sql`에서 제목, 핀 여부, 메타데이터 버전, 삭제 시각과 목록 인덱스를 추가했다. 기존 000~020 변경 파일은 수정하지 않았다. 메타데이터 버전은 0부터 시작하며 기존 실행 버전과 구분한다.

- `PATCH /api/v1/conversations/{id}`: 제목·핀 변경과 현재 버전 검사를 수행한다.
- `DELETE /api/v1/conversations/{id}`: 삭제 시각을 기록하여 사용자 조회에서 제외한다.
- `GET /api/v1/conversations`: 제목 검색, 핀 필터와 서명된 다음 페이지 정보를 지원한다.

잘못된 필드·자료형·제목 길이·개행 문자를 거부하고, 세션·CSRF·소유자·버전을 검사한다. 같은 내용을 현재 버전 또는 직전 버전으로 다시 요청하면 안전하게 응답하며, 오래된 버전으로 다른 변경을 요청하면 409 오류를 반환한다. 페이지 정보는 사용자·조직·검색 조건·정렬 위치에 연결한다. 검색어는 SHA-256 지문으로 포함하여 120자 한글 검색에서도 페이지 정보 길이 제한을 지킨다. 기존 메시지 페이지 형식은 유지한다.

## 삭제와 보존

실행 중인 답변이 있으면 삭제를 차단한다. 삭제와 새 실행 접수는 대화 행 잠금으로 순서를 보장한다. 실행을 먼저 접수하면 삭제를 차단하고, 먼저 삭제하면 실행 접수를 차단한다.

삭제 이후에는 대화 목록, 메시지, 실행 결과, 재전송, 스트림, 해당 답변의 근거·출처 조회를 차단한다. 웹 애플리케이션의 직접 DB 조회도 행 수준 권한으로 제한한다. 원문 문서 자체는 독립된 자료 권한을 유지한다.

삭제해도 완료된 실행의 기록, 봉인된 근거, 비용·예약·감사 기록은 보존한다. 비용 환불이나 물리 삭제로 표시하지 않는다. 변경 감사에는 요청 ID, 대상과 버전만 기록하며 제목·질문·답변 본문을 복사하지 않는다. 감사 기록 저장에 실패하면 제목 변경도 함께 취소한다.

## 화면과 실패 처리

이력 조작 화면을 `ConversationHistory.tsx`로 분리하고 기존 조직 전환, 답변 스트림과 선택 상태를 재사용했다. 변경은 서버 성공 응답 이후에 반영한다. 삭제한 대화가 현재 선택된 대화라면 메시지·실행·입력·선택 상태를 초기화한다. 진행 중인 답변은 취소 또는 완료 후 삭제하도록 안내한다.

검색 결과가 없는 상태와 저장한 대화가 없는 상태를 구분한다. 검색 조건이나 조직을 바꾼 뒤 도착한 이전 요청의 응답은 화면에 반영하지 않는다. 휴대폰 화면에서도 목록을 열어 동일한 이력 기능을 사용할 수 있다.
