# 28 DP11-02a 구조화 프롬프트 버전 저장과 복제 구현 결과

사용자 “네 진행 바랍니다”에 따라 [[28 DP11 Agent Builder 프롬프트 RAG Playground 상세 개발 계획서]] Task2를 개발했다. Task2a 구조화 저장·조회·복제를 먼저 수용하며 Task2b 실제 RAG 검색 요구는 보존한다. 현재 QueryGateway는 VerifiedRun/worker·정산 권원을 요구하므로 검색 시험은 Task3 최소 시험 admission과 함께 연결한다. 비용 원장을 우회하거나 임의 mock 검색을 실제 시험이라고 표시하지 않는다.

## 구현 내용

- 관리 Agent Builder에서 시스템(기존 자산 지시문)·개발자·사용자 템플릿과 최대5개 읽을 수 있는 정확한 문서 버전을 저장한다. 기본 실행 방식 모델 참조만 허용하며 임의 모델/URL/key/credential 필드는 거부한다. 아직 모델 선택·답변 생성·검색 품질 시험이 아니다.
- 새 버전과 profile/hash·동일ID receipt를 단일 transaction에 저장한다. revision CAS, actor/tenant별 idempotency, 같은ID 다른전체profile409, 저장 중 profile 실패 시 자산/버전/감사/receipt 모두 원자 rollback이다. replay도 현재 제작·자료 권한을 확인한다.
- 과거 version_id를 조회·조합 검증한다. profile을 갖지 않은 과거 버전은 읽기 시 legacy-derived로 구성하며 DB에 소급 쓰지 않는다. 새 profile은 강제RLS·INSERT만 허용하며 수정/삭제하지 않는다.
- 정확한 원본 버전을 새 자산 초안으로 복제하고 parent_version_id를 저장한다. 이후 수정 버전에도 원본 lineage를 보존한다. 운영 게시/실행·개인 이용권한을 복제하지 않는다. 응답 유실 후 동일 요청 확인은 같은 receipt를 반환한다.
- 공개 기존 자산 append는 구조화 자산에서409 BUILDER_PROFILE_REQUIRED를 반환해 필드 유실을 막는다. 기존 registry 검증 함수는 private asset_registry_v029로 이동하며 ai_web 직접실행을 차단한다. 동적draft의 기존 사용자 실행404는 유지한다.
- 조합 preview는 역할별 messages/config_hash/profile_hash/자료binding/조합지문을 제공하며 provider_called=false다. 자료 회수 후 저장·clone replay·preview가404다. 개인 시험 변수값은 저장하지 않는다.
- 화면은 dirty 결과 제거·세션/조직 변경 폐기·충돌 시 최신 역할별 prompt와 편집값 비교, 복제 uncertain 상태 전체입력 잠금/같은요청 확인을 제공한다. 복제와 preview의 React key를 분리하여 stale DOM 잔류를 수정했다.

## API

POST `/api/v1/admin/builder/assets`, POST `/assets/{asset_id}/versions`, GET `/assets/{asset_id}/versions/{version_id}`, POST `/assets/{asset_id}/clone`, POST `/assets/{asset_id}/versions/{version_id}/preview`(각 경로 앞 `/api/v1/admin/builder`). 인증·CSRF·32KiB·current tenant/management 권한을 적용하며 읽기/preview는 기존 read window를 적용한다.
