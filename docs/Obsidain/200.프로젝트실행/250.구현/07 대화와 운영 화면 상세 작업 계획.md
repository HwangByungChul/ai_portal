# 대화와 운영 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan. 이 프로젝트의 사용자 승인에 따라 같은 대화에서 순차 수행한다. 새 에이전트·새 대화는 만들지 않는다.

**Goal:** 본인 대화 생성·실시간 응답·저장 재조회·취소와 권한별 Agent·사용량·한도·플랫폼 운영 화면을 실제 서버 API에 연결한다.
**Architecture:** 기존 React/Vite + FastAPI + PostgreSQL의 27 API를 사용한다. 요청별 조직 헤더와 세션 선택 세대, 컴포넌트 해제 시 취소 신호를 함께 검사한다. 작성 중 답변은 메모리에만 두고 저장 답변은 현재 권한 GET으로 확정한다.
**Tech Stack:** 기존 React19.3/TypeScript7/Vite8.3/Playwright1.63, Python3.13/FastAPI/PostgreSQL15. 의존성과 DB migration000~008은 변경하지 않는다.
**Spec:** [[200.프로젝트실행/240.설계/07 사용자와 관리자 화면 설계]], [[200.프로젝트실행/250.구현/04 일반 대화와 중앙 AI 구현 결과]] 19절. 2026-10-05 “다음 작업 계속 진행 바랍니다”로 B05 실행 승인.

## Global Constraints

- 기존 합성 원문·평가 Q20·원본 GraphRAG/BNK 자산·과거 공개 증거·비공개 키/인증 설정을 보존한다. Q20은 미수행 유지.
- 유료 OpenAI 호출0, 모의 실행만 사용한다. 실제 모델·임베딩 시험은 B06이다. rules_rag는 C 전까지 준비 중으로 표시한다.
- 일반 USER는 본인 업무만 사용한다. TADMIN은 현재 조직만 관리한다. 플랫폼 조회/변경 capability는 독립이며 상위 배정은 명시적 관리 소속 PADMIN만 편집한다.
- 실행 ID는 crypto.randomUUID()로 전송 시 한 번 생성한다. 접수 응답 불명 → 동일 ID GET → 실제404인 경우에만 동일 payload 1회 재전송. 이후 불명은 GET 확인만, 새 호출 금지.
- SSE sequence/epoch/run/org 검사, 최대64KiB 프레임·작성 본문; 초과/간격/종료는 저장 상태 재조회. 숨김 탭의 반복 GET 중단. GET 일시 오류만1초/3초 최대2회 재시도. 변경 API 자동 재시도0.
- 완료 이벤트나 EOF는 저장 성공 자체가 아니다. canonical GET의 final 본문만 확정한다. unknown 사용량은0원/무료로 표시하지 않는다. 요청/본문/CSRF의 영구 저장 및 로그 복제0.
- 모의 시연 초기화는 소유 표시가 있는 합성 DB의 누락 mock budget만 운영 상한의 남은 배정 안에서 A/B 각 최대12,500원으로 최초 생성하고 일반 Agent를 관리 API로 준비한다. 기존 account/reserve/real 행을 reset하지 않는다. 실행 설정 추가 시 키·web DSN·HMAC의 원문은 보존한다.

- [x] Run은 run_id/tenant_id/conversation_id/state/revision/is_terminal/content_status/usage_status/result를 사용한다. MessagePage/ConversationPage는 items/next_cursor를 사용한다.

## 실행과 자체 점검

예상180~240분은 개인 학습을 포함한 배정값이며 실제 인력 공수 측정값이 아니다. 역할/두 탭/유실/충돌/불명 비용의 테스트가 각 구현 책임에 대응하고, RAG·실제 모델은 후속 단계로 남는다. 변경 성공은 서버 응답으로만 표시한다. 진행 중 실패는 수정 후 필요한 시험을 반복하며 미수행을 합격으로 기록하지 않는다.

모의 시연 최초 준비 보완: 기존 API는 누락 budget의 INSERT 권한을 제공하지 않는다. 따라서 소유 표시와 고정 합성 A/B UUID를 검증한 준비 명령만 최초 mock 배정을 만들고 감사 기록을 남긴다. 이미 있는 행은 변경하지 않으며 프로젝트 lock 안에서 기존 배정 합계를 빼 각 신규 행을 최대12,500원으로 제한한다. 이는 모의 금액이며 real 배정/사용·예약을 초기화하지 않는다. 이후 운영 변경은 기존 관리 API를 사용한다.
