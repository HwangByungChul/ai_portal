# 사용자 관리자 포털 A안 Soft Space UI 반영 결과

관련: [[200.프로젝트실행/240.설계/23 포털 UI UX 확정과 사이트 분리 검토]], [[200.프로젝트실행/240.설계/2026-10-22 사용자 관리자 포털 UI UX 트렌드 적용 시안 제안]], [[400.프로젝트관리/02 포털 UI UX 작업 기록]].

## 요청과 결정

사용자는 A안(Soft Space)을 선택하고 전체 작업이 완료된 뒤 알림을 요청했다. 화면 작업 전 확정 UI 설계, 실제 사용자/관리자 차이 검토, 승인·검증 상세를 읽었다. 선택된 A안은 기존 실제 홈(A), 관리자 운영 홈(A), 관리자 승인·검증(B) 기능과 데이터 흐름 위에 시각 체계로 적용한다. 사용자 인디고와 관리자 틸은 의도된 사이트 차이로 유지하며, 로그인은 별도 승인 설계를 계속 따른다.

## 변경 파일

- `src/frontend/packages/ui/src/portal.css`: 사용자 포털 인디고 토큰, 관리자 틸 토큰, 업무 홈/운영 카드의 절제된 소프트뎁스, 승인 선택 상태·포커스 표시, 넓은 화면/모바일의 카드 정렬, reduced-motion 규칙을 추가했다. 독립 user/admin 앱이 공유하는 정식 UI 원본이다.
- `src/frontend/src/HomePage.tsx`: 최근 업무의 이어서 대화 링크를 스코프 색상 변수를 따르는 CSS 클래스로 변경했다.
- `src/frontend/src/AdminHomePage.tsx`: 호출 막대 색상을 관리자 틸 계열 CSS 변수로 분리하고 전환 시간을 짧게 조정했다.
- 이 문서, 제안 노트 및 작업 기록: 선택·구현·검증 범위와 미완료 범위를 기록했다.

화면 데이터, 로그인, 권한·테넌트 범위, API, 승인/게시 상태 전이는 변경하지 않았다. 목업의 합성 숫자나 가짜 AI 매칭률을 실제 화면에 옮기지 않았다.

## 실제 검증

- `npm run build` (`src/frontend`): TypeScript 검사 통과, user Vite build 통과, admin Vite build 통과, `verify-portal-builds.mjs` 통과. 경계 결과: user 28 modules / admin 56 modules, 양쪽 `boundary_verified: true`.
- `git diff --check`: 통과.
- 첫 sandbox 빌드는 Vite 임시 파일을 `node_modules/.vite-temp`에 쓰는 단계에서 EPERM으로 중단됐다. 권한 승인 실행으로 같은 공식 분리 빌드를 다시 수행해 완료했다.
- 관리자 번들은 minification 뒤 500 kB 초과 경고가 있다(744.93 kB JS). 빌드는 성공했으며 이번 UI 작업에서 번들 분할은 수정하지 않았다.
- 로컬 앱 HTTP 확인은 127.0.0.1:5173, :5174 서비스가 실행 중이지 않아 확인되지 않았다. 실제 로그인 세션으로 인증된 화면을 직접 확인하지 않았다.

## 상태·제약

코드 변경과 사용자/관리자 분리 빌드 검증은 완료했다. 제안·승인·게시·실행·운영 배포 상태를 혼합하지 않는다. 이 UI 작업은 실제 앱 코드에 적용됐으나 기관 UAT나 운영 배포가 아니다. 실제 인증 사용자 수용, 브라우저 폭별 로그인 상태 화면 확인, 기관 UAT와 운영 배포는 미실행이다. 기능/API/DB 시험은 화면 스타일 작업 범위로 수행하지 않았다.

## 다음 작업

실제 개발 서버와 승인된 테스트 계정이 준비된 상태에서 데스크톱·태블릿·모바일 폭별 사용자 홈/관리자 운영 홈/승인 상세를 확인하고, 필요 시 시각 조정을 한다. 현재 상태의 서비스는 시작하거나 중지하지 않았다.
