# Gateway 모의 등록 격리 및 라우팅 경계 보강 구현 결과

## 요청·범위

사용자는 [[100.프로젝트계획/38 금융 특화 MCP Tool Gateway 상세 구현 계획안]]을 기준으로 개발 구현하고, 작업 중 생성 문서와 이력을 `MCP Tool Gateway 상세 구현` 폴더에 기록하도록 요청했다. 이 단계는 전체 계획의 완료가 아니라 기존 자동변환 시연 경로의 권한·tenant 경계와 완료 표시를 먼저 바로잡은 수직 단위다.

## 확인한 기준선

- 기존 코드에는 일반 고정 Tool용 durable `tool_approvals`/`tool_receipts` 실행 gate가 있다. 자동변환 wizard는 아직 해당 gate에 연결되지 않았다.
- migration 052에는 `portal.mcp_tool_definitions`, `mcp_tool_versions`, `mcp_tool_endpoint_profiles`, `mcp_tool_audit_logs` 테이블 정의가 있으나, `DynamicToolGateway`의 자동변환 등록/목록/프로파일/감사 기록은 process memory를 사용한다.
- `_execute_protocol`은 REST/SOAP/JDBC/금융전문 결과를 fixture 형태로 구성한다. 실제 기관 endpoint 통신은 수행하지 않는다.

## 구현 변경

- `src/backend/app/tools/autowrap_routes.py`
  - 관리자 등록·목록·모의 호출 API에 현재 tenant의 TADMIN/PADMIN 권한 확인을 적용했다.
  - 등록·목록·호출 시 인증 컨텍스트의 tenant/user ID를 gateway namespace로 넘긴다.
  - `publication_status` 및 `asset_id`를 클라이언트 요청 계약에서 제거하고 호출은 항상 `draft`/개발 프로파일 모의 경로로 고정했다. 구형/조작 client body는 `extra=forbid`로 거부된다.
  - endpoint profile에 inline `credential` 필드를 허용하지 않는다.
- `src/backend/app/tools/dynamic_gateway.py`
  - memory 등록소 key를 `(tenant_id, tool_id)` 조합으로 분리했다. 같은 Tool ID를 다른 tenant에서 사용해도 덮어쓰거나 목록을 교차 노출하지 않는다.
  - idempotency key를 tenant/user/tool/request 단위로 격리했다.
  - 목록의 Dev/Prd profile 표시를 tenant key와 일치시켰다.
  - 모의 기본 endpoint를 `.invalid` 예약 도메인으로 바꿨다.
- `src/frontend/src/ToolAdminPage.tsx`
  - 프런트엔드 상수로 들어 있던 예시 API key와 운영 라우팅 선택 버튼을 제거했다.
  - example.invalid endpoint를 사용하고 등록·실행·결과가 개발 프로파일의 모의 상태임을 표시한다.
  - 영구 저장/실제 MCP 연결이 된 것처럼 보이던 완료 문구를 수정하고 모의 등록 응답 실패 시 실행을 진행하지 않게 했다.
- `src/backend/tests/test_mcp_tool_autowrap.py`
  - publication status 위조와 inline credential 입력 거부, tenant별 Tool ID 격리/다른 tenant 거부 시험을 추가했다.

## 실제 검증

- `src/backend/.venv/bin/pytest src/backend/tests/test_mcp_tool_autowrap.py -q`: **9 passed**.
- Codex bundled Node 런타임으로 `npm run build:admin`: **통과**, 52 modules, `boundary_verified: true`. 번들 500 kB 초과 경고는 남았다.
- 같은 런타임으로 `npm run build:user`: **통과**, 28 modules, `boundary_verified: true`.
- 기본 Node 21.4.0으로 관리자 빌드를 시도했을 때 Vite/Rolldown이 `node:util.styleText` export를 찾지 못해 실패했다. Codex bundled Node를 선택해 재검증을 통과했다.
- 활성 DB migration, 새 migration, HTTP 인증 사용자 round-trip, browser 시나리오, 실제 MCP Streamable HTTP, 기관 sandbox 통신은 수행하지 않았다.

## 미완료·한계

- 자동변환 등록은 여전히 process memory라 서버 재시작 시 보존되지 않는다. 추적/감사도 영속 원장이 아니다.
- 임의 URL 형식과 SSRF-safe egress allowlist, redirect/DNS/IP 검증은 아직 구현하지 않았다. 현재는 실제 outbound dispatcher가 없는 mock 경로만 시험했다. 실제 connector를 붙이기 전 URL 검증과 egress 정책이 선행돼야 한다.
- 기존 Tool approval/version/receipt gate, 승인 후 exact revision 재검증, Secret Manager/OAuth/MFA, 실제 MCP `tools/list`·`tools/call`, rate limit/circuit breaker, metadata provenance, prompt injection·DLP, hybrid routing은 미완료다.
- production profile 값 자체는 관리자가 등록할 수 있지만 이 mock API로는 호출할 수 없다. 이를 실제 운영 endpoint 연결로 보고하지 않는다.
