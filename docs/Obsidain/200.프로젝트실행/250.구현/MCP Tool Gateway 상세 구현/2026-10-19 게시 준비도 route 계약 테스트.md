# 게시 준비도 route 계약 테스트

## 요청·범위
사용자가 `subagent-driven-development` 방식으로 남은 MCP Gateway 작업을 진행하도록 요청했다. 이전 단계에서 추가한 publication readiness advisory를 실제 관리자 approval detail route 응답으로 검증하는 단위 테스트를 추가했다.

## 변경
- `src/backend/tests/test_mcp_tool_publication_gate_routes.py` 신규.
- 실제 `tool_detail` async endpoint, readiness helper, response serializer를 호출하고 context/repository/descriptor 의존성만 fake로 격리한다.
- 일치하는 동적 descriptor도 `publishable=false`, `execution_ready=false`인지, revision 불일치 시 blocker가 노출되는지, 정적 Tool 응답에는 `publication_gate` 키가 추가되지 않는지 검증한다.
- 애플리케이션 코드는 변경하지 않았다. 기존 미커밋 코드에 의존하는 테스트이며 단독 clean checkout 통합 증거가 아니다.

## 실제 검증
- `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest --noconftest -p no:cacheprovider tests/test_mcp_tool_publication_gate_routes.py -q` — `3 passed in 0.92s`.
- 신규 테스트 파일 `git diff --check` 통과.
- 독립 task review: spec PASS, quality PASS, finding 없음.
- DB/fixture/HTTP 서비스/IdP/connector는 사용하지 않았다.

## 상태·한계
이 테스트는 mock으로 의존성을 격리한 endpoint 호출이지 실제 인증 HTTP 왕복이나 DB authorization 검증이 아니다. publication readiness는 정보용이며 게시·실행 gate가 구현되지 않아 운영 dispatch는 닫혀 있다. 변경은 공유 pre-dirty working tree에서 미커밋 상태다.

## 다음 작업·선행조건
다음 데이터베이스 구현은 새 additive migration으로만 진행한다. 현재 기록된 `.runtime/backups/mcp-gateway-20261018/active-fixture.dump` 백업 artifact를 저장소에서 확인하지 못했다. 활성 개발 DB는 stopped 상태이며 임의 기동하지 않는다. 백업을 복구·검증하고 별도 disposable clone을 준비하기 전까지 migration 적용 검증을 수행하지 않는다. IdP/MFA/Secret Manager 값도 미확정이므로 positive publication/call authorization을 활성화하지 않는다.
