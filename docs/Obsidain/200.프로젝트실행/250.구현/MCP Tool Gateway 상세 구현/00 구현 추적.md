## 다음 작업

1. 기관 issuer/metadata, immutable subject claim, MFA assurance allowlist/freshness/replay 및 키 회전 계약을 확보한다. 그 전까지 실제 verifier backend/evidence issuer는 미활성이다.
2. 승인된 crypto backend와 Secret Manager 연동·키 rotation을 구현하고, evidence 발급 및 subject mapping 성공·replay·revocation·tenant 분리를 disposable clone에서 검증한다.
3. exact revision 게시 준비도 API와 route 단위 계약 테스트를 추가했으며 항상 `publishable=false`, `execution_ready=false`다. 승인·게시 ledger/RPC 신규 migration은 준비 대상이지만 기록된 PostgreSQL backup을 disposable clone 기준으로 복원하고 056–064를 검증했다. 활성 fixture/native DB에는 미적용. IdP/MFA·승인 gate 미완성 동안 positive authorization은 열지 않는다.
4. Secret Manager reference·credential lifecycle, tool poisoning 대응 및 SSRF/egress allowlist 계약을 구현한다.
5. schema 적용·API code 배포 뒤 관리형 backend 재기동과 인증 브라우저 왕복을 확인한다. 현재 backend는 --reload이 아니며 service_control 소유 기록이 없어 임의 재시작하지 않는다.
6. 승인/보안 계약이 확정된 뒤 Streamable HTTP와 제한된 connector를 별도 단계로 추가한다.
