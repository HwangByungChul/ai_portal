# 동적 Tool 승인 gate 계약 조사 결과

## 요청·범위
사용자의 “다음 진행” 지시에 따라 자동 생성 MCP Tool을 기존 승인·게시·receipt gate에 연결하는 다음 구현 단계를 조사했다. 이번 회차는 계약 점검과 안전한 구현 경계 확정까지 수행했으며 DB/API 승인 연결은 아직 구현하지 않았다.

## 확인한 코드 계약
- `src/backend/migrations/046_tool_approvals_and_receipts.sql`의 `security.tool_approval_control`은 submit 시 `financial_product_lookup`, `kb_rule_query`, `data_view_reader`만 허용한다. 자동 생성 Tool ID는 현재 승인 접수될 수 없다.
- `src/backend/migrations/050_tool_workflow_approval_reviews.sql` wrapper는 기존 타인 PADMIN 결정, 자기승인 금지, CAS와 append-only `approval_reviews` 이력을 보강한다. 기존 함수를 직접 바꾸지 않고 새 additive migration으로 확장해야 한다.
- `src/backend/app/tools/routes.py`는 descriptor를 기존 정적 실행 서비스에서 가져오고, 승인 상세도 현재 descriptor와 제출 descriptor의 일치 여부를 정적 registry 기준으로 검사한다.
- `src/backend/app/tools/execution.py`는 실행 handler를 정적 `GLOBAL_TOOL_REGISTRY`에서 가져오고 `tool_execution_control` receipt를 쓴다. 동적 Registry 도구는 현재 실행 가능한 handler가 아니므로 승인 처리만 추가해도 실제 호출 가능한 상태가 되지 않는다.
- Registry의 `revision_number`는 있지만 현재 표준 tool-approval descriptor에 revision-bound digest와 위험 분류가 없다. 클라이언트의 publication state나 endpoint profile을 실행 권한으로 사용할 수 없다.

## 결정 및 구현 순서
1. 신규 migration(057 이상)에 동적 승인 접수/결정용 제한 RPC를 추가한다. tenant/session/RBAC, PADMIN 타인 승인, 재신청/CAS, audit/approval_reviews 기록은 기존 계약과 같게 적용한다. 기존 migration checksum은 변경하지 않는다.
2. RPC가 tenant 내 활성 Tool의 최신 `tool_id + revision_number + canonical schema/name/description + mode + risk_class`로 descriptor와 digest를 서버 계산한다. 원본 endpoint URL과 secret은 승인 화면 descriptor에서 제외한다. 제출 후 revision이 바뀌면 승인 불가로 처리한다.
3. 관리자 B 요청 목록·상세에서 `동적 Tool 등록 검토`와 승인 상태를 보여준다. 이 approval은 운영 게시나 실행 허가와 구분한다.
4. 별도 후속 단계에서 동적 execution adapter가 실제 연결되기 전까지 동적 Tool의 `tools/list` 노출·`tools/call`은 계속 fail-closed 한다. 추후 연결 시 승인 head digest, 현 사용자/tenant 권한, 실행 전 revision과 endpoint policy를 다시 검사하고 기존 receipt 원장을 사용한다.
5. 적용 전 active fixture backup, private clone restore/apply/권한·CAS·cross-tenant 검증, source checksum/기존 row 보존을 수행한다. fixture harness는 순차 실행한다.

## 변경 파일·검증
- 조사 기준 파일: `src/backend/migrations/046_tool_approvals_and_receipts.sql`, `src/backend/migrations/050_tool_workflow_approval_reviews.sql`, `src/backend/app/tools/routes.py`, `src/backend/app/tools/repository.py`, `src/backend/app/tools/execution.py`, `src/backend/app/tools/dynamic_repository.py`.
- 이번 회차에는 애플리케이션 코드와 migration을 수정하거나 새 시험을 실행하지 않았다.

## 현재 상태·미완료
- 동적 registry 등록/조회와 개발 fixture simulation은 이전 단계에서 구현·확인되었다.
- 승인 request 접수, PADMIN 결정, publication, 동적 execution receipt 연계는 미구현이다.
- 현재 backend 프로세스는 `--reload` 없이 구동 중이며 service-control 소유권이 확인되지 않아 재시작/브라우저 왕복은 수행하지 않는다.
