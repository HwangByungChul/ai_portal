# 062 backup clone 검증 결과

## 범위와 결정
사용자 승인에 따라 062 migration을 백업 복원본인 disposable PostgreSQL 15 clone에 적용했다. 개발 fixture나 공유 DB에는 적용하지 않았다. 기존 migration source는 변경하지 않았다.

## 검증 결과
- backup baseline에서 056–062를 적용했고 migration head는 `062_mcp_tool_version_integrity.sql`이다. source checksum mismatch는 0건이다.
- 기존 업무 테이블 74개, 총 322행의 테이블별 row count가 migration 전후 동일했다.
- `portal.mcp_tool_versions`의 기존 행은 0개였다. digest 누락 0, 길이 오류 0이며 backfill 대상 행은 없었다.
- integrity trigger가 enabled 상태이며 `mcp_tool_versions` RLS와 FORCE RLS가 모두 켜져 있음을 확인했다.
- 합성 revision을 clone 안에서 transaction으로 INSERT해 저장 digest와 DB 재계산 digest의 일치(true)를 확인했다. UPDATE와 DELETE는 모두 SQLSTATE `23514`로 차단됐다. 합성 definition/version은 transaction rollback으로 제거했다.
- ACL 포함 복원 clone에서 `ai_web/ai_index/ai_meter`의 Registry 직접 table privilege는 모두 false, `ai_web`의 `mcp_tool_registry_control` EXECUTE만 true(외 함수 false), PUBLIC의 registry/trigger function EXECUTE는 false였다. `ai_policy_executor`는 definitions SELECT/INSERT/UPDATE, versions SELECT/INSERT, endpoint profiles SELECT/INSERT/UPDATE, audit SELECT/INSERT였으며 versions UPDATE/DELETE는 false다.
- 첫 ACL 제외(`--no-acl`) restore의 권한 결과는 baseline ACL이 제거된 상태라 판정 근거로 사용하지 않았다. ACL 포함 fresh clone으로 재검증해 위 결과를 얻었다.
- 임시 clone은 종료 후 정리했다.

## 제한 및 다음 작업
이 결과는 clone 적용 검증이다. 실행 role privilege catalog는 clone에서 검증했다. HTTP 왕복 및 통합 실행은 미수행이다. pytest, API 통합, active fixture 적용, 기관 sandbox 및 운영 검증도 미완료다. API source 대조 결과 `context()`가 세션·단일 tenant·쓰기 CSRF를 검증하고, 동적 변경은 TADMIN/PADMIN 제한 및 tenant transaction을 거친다. invoke는 draft 상태의 fixture simulation으로 고정되어 있다. `tests/test_mcp_tool_autowrap.py`는 DB를 사용하지 않는 단위 테스트 9개가 통과했다. HTTP 왕복은 미검증이다. 앱 DB pool 및 HTTP test fixture가 127.0.0.1:55432에 고정되어 있으며 현재 native devdb가 stopped 상태라 실행하면 해당 DB를 기동/사용하게 된다. 이번에는 기동하지 않았다. API 오류 변환은 입력 SQLSTATE 22xxx→REQUEST_INVALID 및 tenant DB A0401/A0403/A0404/A0409/A0422 변환을 source로 확인했다. owner/ACL을 보존한 disposable backup clone에서 실제 HTTP/auth/repository 왕복을 확인했다. native app pool은 55432 고정 검증이 있어 테스트에서만 custom `open_web_pool` adapter를 주입해 clone port 55433의 실제 `ai_web` 계정으로 연결했다. 세션 검증·tenant transaction·RPC SQL은 실제 코드/DB였다. 무인증 GET 401 `AUTH_REQUIRED`, TADMIN register 200 revision 1, list 200 및 등록 항목 확인, 잘못된 registry tool id 422 `REQUEST_INVALID`, 타 tenant 조회 403 `TENANT_FORBIDDEN`, 일반 USER register 403 `TOOL_NOT_PERMITTED`가 통과했다. 이 결과는 외부 endpoint 실행을 포함하지 않으며 native pool port/marker verifier 자체도 통과 증거가 아니다. 임시 clone을 종료·삭제했고 native devdb 상태는 stopped를 재확인했다. Active fixture 적용은 하지 않았다.
