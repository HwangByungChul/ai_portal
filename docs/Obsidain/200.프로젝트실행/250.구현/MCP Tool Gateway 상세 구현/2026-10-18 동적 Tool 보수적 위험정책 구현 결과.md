# 동적 Tool 보수적 위험정책 구현 결과

## 요청과 범위
사용자의 “네 진행 바랍니다” 지시에 따라 T035의 다음 단계인 동적 Tool 위험 분류와 승인 정책을 구현했다. 동적 connector의 실제 읽기 전용 동작과 부작용을 서버가 검증하지 못하는 현재 상태에 맞춰 분류를 보수적으로 고정하고, 등록 검토 승인과 게시·실행 권한을 분리했다.

## 결정
- 모든 동적 connector source type에 서버 기본 정책 `dynamic-default-v1`을 적용한다. connector 동작/부작용을 신뢰 가능한 증거로 확인하지 못하므로 `risk_class=financial_side_effect`, `data_classification=restricted_or_unknown`으로 분류한다.
- 분류 근거, policy id/revision, scope와 실행 준비 여부를 서버가 descriptor에 봉인하고 revision digest에 포함한다.
- 동적 Tool 검토 요청은 기존 PADMIN 승인 원장 목록·상세로 접수한다. 하지만 기존 승인 RPC는 승인 시 현재 head를 활성화할 수 있으므로, `registration_review_only` 상태인 동적 요청의 승인 전이는 API와 DB trigger 양쪽에서 계속 거부한다. 제출/검토 요청은 게시·실행 권한이 아니다.
- 정확한 Tool revision/payload를 대상으로 하는 다중 승인/MFA, 게시 및 receipt 실행 gate는 별도 구현 전이다. 이번 기본 정책은 편집 가능한 위험정책 관리 기능이 아니며, `dynamic-default-v1` 서버 정책으로 제한된다.

## 검증 및 이행 상태
- Python 4개 파일 내장 `compile()` 구문 검증과 `git diff --check` 통과. `npm run build:admin` 통과(227 modules, `boundary_verified: true`); 번들 500 kB 초과 경고 유지. 첫 빌드는 Vite 임시 파일 쓰기 `EPERM`으로 실패했고 승인된 elevated 재실행에서 통과했다.
- Migration 056~058을 백업 dump로 복원한 별도 disposable PostgreSQL clone(port 55433)에 적용했다. 적용 후 migration head 058, 59 entries, 적용 migration source checksum mismatch 0건을 확인했다. 74개 app table의 총 322행 및 정규화 지문 SHA-256 `f018867b687531db5ad815aaa39f92ba4b4f26d4b75fc857d09a5b142b5c276c`가 적용 전후 동일했다. `ai_web` RPC 실행 가능, approval/definition 직접 SELECT 거부, trigger 소유자 `ai_policy_executor`, trigger 활성 상태를 확인했다. 합성 approval 직접 승인은 SQLSTATE A0403 / `TOOL_DYNAMIC_REVIEW_ONLY`로 거부됐고 probe row는 rollback했다. clone은 소유권 marker 확인 후 종료·삭제했다.
- Migration 058은 active fixture에 미적용이다. pytest는 실행하지 않았다. 기존 활성 DB 및 checksum·row는 변경하지 않았다.
- 기존 활성 개발 DB·기존 migration checksum·row 지문은 이번 변경으로 수정하지 않았다.
- 관리자 화면은 관리 B 승인·검증의 요청 목록·상세 기준에 맞춰 분류값/근거/정책 식별자/승인범위를 표시하도록 수정했다. UI 노트 23의 구조(목록/상세 패널)는 변경하지 않았다.
- 실제 connector, IdP/MFA, 게시, tools/list 공개 또는 tools/call 실행은 구현·수행하지 않았다.

## 미완료·다음
1. Python/API 회귀 시험과 정확한 동적 descriptor/RPC tenant 경계를 별도 fixture clone에서 추가 검증한다. 필요한 백업·복구 gate를 검토하기 전에는 active fixture에 적용하지 않는다.
2. 편집 가능한 조직별 위험정책/승인단계 UI와 immutable policy revision은 미구현이다.
3. exact revision 승인 request, 타인 2인 승인·IdP MFA assurance, publication head, 동적 execution adapter 및 durable receipt/audit 연계가 남아 있다.
