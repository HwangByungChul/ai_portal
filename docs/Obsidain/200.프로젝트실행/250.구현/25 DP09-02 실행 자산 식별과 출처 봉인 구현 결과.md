# DP09-02 실행 자산 식별과 출처 봉인 구현 결과

## 요청과 구현 범위

사용자가 다음 작업의 상세 계획을 Obsidian에 저장한 후 개발하도록 지시했다. [[26 DP09-02 실행 자산 식별과 출처 봉인 상세 작업 계획서]]를 먼저 저장하고 고정 Agent/UUID 호환, 신규 run 바인딩, API/worker/React 상세를 구현했다. 이번 완료 여부는 아래 최종 검증 기록을 따른다. 전체 F/동적 승인 실행/기관 UAT·운영 배포 완료를 의미하지 않는다.

## 실제 변경

- `src/backend/migrations/028_run_asset_binding.sql`: 기존 runs에 nullable asset_id/asset_revision/asset_version_id/asset_config_hash 추가. old row backfill 없음. INSERT snapshot 기반 서버 계산, UPDATE 변경 거부, 완전성 constraint, owner run_view metadata, 세션 검증 resolver. 기존37표/forced RLS·예산/ACL/정산 계약 유지.
- `app/conversations/routes.py`, `repository.py`: optional asset_id strict UUID, 조직별 고정 연결 alias만 수용. 생략·동일 alias는 동일 의미/재시도 지문, draft·타조직·타Agent·random UUID는 공통404. 신규 version/hash 주입422. 기존 p_agent SQL admission gate 유지.
- `app/ai/repository.py`: frozen RunAssetBinding을 RunTicket에 전달, 신규 바인딩 revision과 claim 설정 버전 대조. old run은 None 지원.
- `src/frontend/packages/api-contract/src/types.ts`, `src/RunAssetInfo.tsx`, `src/ChatPage.tsx`, `src/DocumentSummaryPage.tsx`: 실제 실행에 접힌 실행 버전 정보, 설정 버전·확인용ID/지문, old run 미기록 안내. 관리자 초안 관리와 승인 화면의 기존 탐색 유지.
- `tests/test_run_assets.py`, `test_run_assets_migration.py`, 기존 migration/catalog 시험 보정, `src/frontend/tests/run-assets.spec.ts`: 출처/불변·호환·권한·draft 차단·과거 보존·실행 상세 수용 시험.

## 지문 해석과 이전 결정 보존

027 등록 view는 현재 설정을 투영한다. 신규 run은 저장 당시 config_snapshot에서 자산 메타데이터·실효 지시문을 정규화해 SHA256을 계산한다. 명시적인 nonempty 지시문에서는 등록 지문과 같지만 기존 run_prepare의 기본 지시문은 등록 view 기본값과 다르므로 기본값 상황에는 다를 수 있다. SQL000~027 및 기존 default 동작은 변경하지 않았다. 이는 실효 Agent 설정의 식별 지문이며 전체 모델 입력이나 문서/질문/요약 정책의 지문은 아니다. RAG 추가 정책·요약 policy_revision·실제 모델 입력/사용량 추적은 기존 source/policy/호출 원장이 계속 담당한다. 결정적 legacy version UUID는 draft asset_versions 행으로 표현하지 않는다.

## 검증 및 local 이행

서버 300개 고유 case의 최신 결과가 통과했다(최초231건 + 순차 재검증159건 집계). 브라우저48/48와 보강 문서요약1/1, 두 앱 빌드/경계 검사, local37표 기존행·28개 prior migration 보존과 재적용 무변경·health를 확인했다. 최종 시험/보존 결과와 안전한 증거는 [[26 DP09-02 실행 출처 호환과 보존 검증 결과]]에 기록한다. primary local DB에는 모의 질문/자산을 생성하거나 reset하지 않으며 백업·marker/port/name 검증 후 additive migration을 적용한다. Obsidian은 Markdown 파일 저장 대사를 수행하고 GUI 렌더링은 미검증이다.

## 남은 범위와 다음 작업

신규 draft를 게시/승인/실행할 수 없다. 다음 순서 DP10 카탈로그·My Agent/이용 권한 → DP13 모델 관리 → DP11 Builder → DP12 일반 자산 승인·게시/회수·rollback 이후 동적 실행을 연결한다. Entra ID는 선정·테스트 환경 준비 예정 상태이며 실제 연동은 별도다. 전체 기능명세 완료 판정은 기존 검토와 분리한다.
