# 잔여 기능 개발 중간 보고서

## 요청과 범위

사용자가 미완료 기능 잔여 개발을 요청했다. 통합 범위와 gate는 [[100.프로젝트계획/37 미완료 기능 잔여 개발 통합 상세 계획]]을 따른다. 이 보고서는 2026-10-16 현재 실제 수행한 개발과 수용 상태만 기록한다.

## DB migration 051~053

- 적용 전 활성 DB fixture 표식을 확인하고 적용 기록 000~050 및 각 원본 checksum을 대조했다.
- 비공개 runtime 경로에 전체 DB custom-format 백업을 생성하고, 별도 fixture DB로 복원해 67개 테이블의 기존 행 digest, 컬럼/권한/RLS, 정책 및 함수·trigger·constraint를 비교했다. 정책 predicate는 PostgreSQL deparse의 괄호/공백 표현 차이를 정규화해 비교했다. 비밀정보와 원문 자료는 이 Vault에 복사하지 않았다.
- migration 051 적용 때 기존 000~050 checksum과 별도 복원 검증을 확인했다. `meeting_run_contexts`, `meeting_quality_reviews`는 빈 상태이고 FORCE RLS가 적용됐다.
- 이후 초안 저장 기능을 위해 기존 pending 052와 신규 053을 함께 별도 복원 DB에서 순차 적용하고, 그 후 활성 개발 DB에 적용했다. 기존 migration 수 52에서 신규 2개가 적용됐으며 기존 데이터 표 digest 및 000~051 checksum은 유지됐다. `workflow_studio_drafts`는 0행, FORCE RLS 적용이다.
- 첫 clone 적용에서 신규 SQL 조건식 문법 오류가 발견되어 해당 clone의 전체 migration transaction은 rollback됐다. 활성 DB는 그 실행에서 변경되지 않았다. 조건식을 보정한 뒤 새 별도 복원 DB 적용이 통과하여 활성 이행을 진행했다.
- 052 checksum: `e8663b23e121343ba644ec7f44dda1ca194e67f3751d9ba66056ea0bb72d867e`; 053 checksum: `62b8624d036d3b8d823585ec4d6754157683ab72bd16c101fe98c5118fdaf288`.
- 052·053 적용용 백업 SHA256은 `4b5a670d961cb521aae2ae2291da95e8914ad057b65dfba338d49e9b4a073963`이며 전체 backup/restore/application proof는 비공개 `src/backend/.runtime/backups/workflow-drafts-20261016/`에 보존했다. Obsidian에는 백업 파일이나 데이터 digest 목록을 복제하지 않았다.
- API8000 health HTTP 200, `/api/v1/workflows/drafts` 익명 요청은 예상한 401 AUTH_REQUIRED로 route와 인증 gate를 확인했다. 사용자5173 `/user/home`, 관리자5174 `/manage/admin` HTTP 200. 기존 계정 로그인·문서·대화·승인·실행 회귀와 인증된 초안 API 권한/CAS 시나리오를 실행하지 않아 DB/서비스 통합 수용 완료는 아니다.

## Workflow Studio 초안 저장 및 실행 표시

변경한 실제 코드: `src/frontend/src/workflow/WorkflowStudio.tsx`, `src/frontend/src/workflow/workflowAdapter.ts`, `src/frontend/src/CanvasWorkflowApprovalRequest.tsx`.

- 실행할 승인 Workflow 버전을 선택하는 컨트롤을 추가했다. 선택 가능한 승인 버전이 없으면 실행 버튼이 비활성화된다.
- 버튼을 `승인 버전 실행`으로 명확히 하고, 실행 실패 시 노드를 완료로 표시하던 지연 모의 폴백을 제거했다. 실패는 오류로 표시하고 노드 상태를 초기화한다.
- `저장된 초안`, `새 초안`, `초안 저장`을 추가했다. 최신 초안 목록/복원과 revision CAS 저장을 호출한다.
- `src/backend/app/workflows/routes.py`에 owner scope의 초안 목록·상세·저장 API를 추가했다. 저장 request ID replay, expected revision, Pydantic graph/text/size/secret-key 검사와 기존 management authorization을 사용한다.
- `053_workflow_studio_drafts.sql`은 테넌트·owner별 immutable revision rows, 유일 idempotency key, audit event, FORCE RLS를 추가한다. 초안은 승인 제출 및 실행 API가 소비하지 않는다.
- UI 안내는 개인 초안 저장/불러오기와 승인·실행 버전의 차이를 표시한다. 실행은 계속 선택한 승인 exact version에만 적용된다.
- 저장 성공 당시 그래프·메타데이터 지문을 보존하고, 현재 편집이 저장 revision과 다르면 승인 요청 준비를 비활성화한다. 패널이 열린 중 편집이 바뀌어도 닫혀 오래된 revision을 제출하지 않는다.
- Adapter는 캔버스 좌표·편집 설정을 승인 config로 복사하지 않는다. 입력→(선택된 현재 승인 Tool)→정확한 게시 Agent→출력의 단일 선형 흐름만 변환한다. 분기/병합, knowledge·prompt·logic 등 미지원 범주는 명시 오류로 막는다. 게시 Agent와 Tool의 exact version/digest를 선택하며 각 Agent 변수는 Workflow 입력·선행 Tool 결과·고정 문자열 중 사용자가 명시 선택해야 한다.
- 서버 `/workflows/approved/validate`로 strict 검증하고 기존 `/admin/workflow-approvals`에 타인 승인 요청으로 제출한다. 접수 receipt는 기존 승인 B 상세로 이동한다. 제출은 승인·게시·실행 완료를 뜻하지 않으며 Studio 실행은 계속 승인 exact version에만 적용된다.

## 검증 및 제한

- `npm run build:admin` 통과: 52 modules, `boundary_verified: true`; `npm run build:user` 통과: 28 modules, `boundary_verified: true`. pagination 응답 타입을 명시 보정한 뒤 admin→user 순서로 빌드했다. 최종 admin 번들은 705.78 kB 경고가 있었지만 빌드와 경계 검사는 통과했다.
- API health 200 및 초안 endpoint 익명 요청 401 AUTH_REQUIRED 확인. 인증된 저장/복원, 권한거부, CAS 충돌, browser round-trip은 아직 검증하지 않았다. 자동 테스트와 브라우저 상호작용 검증은 실행하지 않았다.
- 승인 지원 범위는 단일 선형 graph와 현재 strict schema에 한정된다. Agent 변수 의미 적합성은 요청자가 확인해야 하며 자동 변환은 업무 품질 승인이 아니다. draft revision 자체에 approval receipt backlink를 저장하는 기능도 없다.
- 실제 승인 PADMIN 왕복, 인증된 초안 저장·복원/CAS, 브라우저 상호작용, 승인 후 실행 trace는 검증하지 않았다. 실제 회의 업무 품질, 모델 제공자, 기관 Tool, SSO, 운영 환경, 전체 기능명세 수용도 미검증이다.
- 서비스는 프로젝트 service control이 관리하는 로컬 개발 API8000/사용자5173/관리자5174로 기동 중이다.

## Workflow 중단 실행 수동 복구

`054_workflow_manual_recovery.sql`과 보완 migration `055_workflow_recovery_retry_guards.sql`로 중단된 승인 Workflow에 대해 신청자→다른 PADMIN 검토→소유자 재개 확정의 수동 흐름을 추가했다. 새 엔드포인트는 `GET/POST /api/v1/workflows/runs/{run_id}/recovery-requests`, `POST /runs/{run_id}/resume`, `GET /api/v1/workflows/admin/recovery`, `POST /admin/recovery/{request_id}/decision`이다. 관리 캔버스에 신청·검토 큐·재개 UI를 연결했다.

- 재개는 저장된 exact version 및 run revision을 확인하고, 현재 게시 head 불일치/실행 권한 변경은 차단한다. 성공한 checkpoint 결과만 재사용해 이미 완료된 단계를 건너뛴다.
- 불명확한 Tool 외부 side effect나 끝나지 않은 Agent child는 자동 호출하지 않고 수동 조정 전까지 재개를 막는다. 재시도 키는 요청 내용과 digest를 대조한다. 재개 요청 replay는 현재 run 상태를 돌려주며, 이미 재개/재시작된 작업을 중복 enqueue하지 않는다. 이벤트는 append-only이며 개인 실행/자료 ACL과 비용 원장을 유지한다.
- 실제 변경 파일: `src/backend/migrations/054_workflow_manual_recovery.sql`, `055_workflow_recovery_retry_guards.sql`, `src/backend/app/workflows/repository.py`, `service.py`, `routes.py`, `src/frontend/packages/api-contract/src/types.ts`, `src/frontend/src/WorkflowCanvasPage.tsx`.
- migration 055 적용 전 private backup 생성·별도 fixture clone 복원 및 clone 우선 적용을 수행했다. 기존 74개 테이블 행 digest와 기존 migration 55개 checksum이 clone과 활성 DB에서 유지됐다. 055 SHA256 `b4b23c6cde5d27cd2640b51fa8ea93b8698c89b11e30871d0468aa4bddf8e958`; backup 1,177,453 bytes, SHA256 `e50a873323ec37df56f9f5ac70aa6f4d7d4d4a3ad9837922be209d5e5bf7aead`. 비공개 proof는 `src/backend/.runtime/backups/workflow-recovery-guards-20261016/apply-proof.json`에 있다. migration 054/055 원본 checksum과 백업 메타데이터는 애플리케이션 DB 및 로컬 증거를 기준으로 유지한다.
- `python3 -m compileall -q src/backend/app/workflows`, `npm run build:admin`(227 modules, portal 52 modules, boundary true), `npm run build:user`(48 modules, portal 28 modules, boundary true) 통과. Admin 번들 712.24 kB 경고가 남았다. migration 직후 stale service-control 기록으로는 listener가 응답하지 않아 소유 프로세스를 정상 재시작했다. 최종 API8000 health, 사용자5173 `/user/home`, 관리자5174 `/manage/admin` HTTP 200을 확인했다. 인증된 두 사용자 승인·재개 왕복, 브라우저 운영 상호작용, 외부 Tool receipt 조정은 실행하지 않아 기능 수용 완료로 표시하지 않는다. 자동 테스트는 실행하지 않았다.
