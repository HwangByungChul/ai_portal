# 사용자 관리자 독립 앱과 빌드 분리 구현 결과

사용자의 “네 진행 바랍니다” 지시에 따라 [[100.프로젝트계획/13 사용자 관리자 독립 앱과 빌드 분리 실행 계획]]을 먼저 저장하고 계획12의 2단계를 실행했다. 화면 결정은 사용자 A/관리 A 홈과 관리 B 승인·검증으로 유지했다. 기존 UI11 실제 앱 구현과 별도의 후속 단계다.

## 구현 경계

| 영역 | 실제 파일·산출물 | 동작 |
|---|---|---|
| 사용자 앱 | `src/frontend/apps/user-web/{index.html,src/App.tsx,src/main.tsx}` | 사용자 홈·AI 업무·문서 요약·개인 자료·개인 사용량 |
| 관리자 앱 | `src/frontend/apps/admin-web/{index.html,src/App.tsx,src/main.tsx}` | 운영 홈·승인·Agent/문서/사용자/사용량/평가·capability 기반 플랫폼 운영 |
| API 공통 원본 | `packages/api-contract/src/{types,api,session}.ts` | 기존 타입·요청·세션/세대·같은 출처 로그아웃 계약 재사용 |
| UI 공통 원본 | `packages/ui/src/{scoped,LoginPage,TenantHeader,PortalShell,styles,portal}` | 인증 상태·조직 헤더·범위·레이아웃·스타일 |
| 기존 호환 | `src/App.tsx`, 기존 main/주소·공통 원본 re-export | 과거 `/home`·`/workspace`·`/admin` 유지, 중복 SessionStore 생성 방지 |
| 공통 기능 제약 | `DocumentsPage.tsx`, `UsagePage.tsx`, `DocumentJobsPage.tsx` | 사용자 빌드의 관리 분기를 컴파일 시 제거 |
| 독립 빌드 | `vite.config.ts`, `scripts/verify-portal-builds.mjs`, package/tsconfig | `dist/user`, `dist/admin`, 자체 index/assets/manifest·모듈 지문·경계 검사 |

업무별 기존 기능 컴포넌트는 `src`에서 재사용하며 앱 진입·화면 import 그래프를 분리했다. 공통 인증/API/UI 구현은 실제 packages 원본으로 이동했다. 각 앱에 lock을 복제하지 않고 현재 frontend lock과 Node22.23.1을 사용한다. runtime 의존성·lock 버전·backend 업무 코드·DB migration·쿠키/Origin/CSRF는 이 단계에서 변경하지 않았다.

## 접근과 탐색

- 새 사용자 앱: [업무 홈](http://127.0.0.1:5173/user/home).
- 새 관리자 앱: [운영 홈](http://127.0.0.1:5173/manage/admin), [승인·검증](http://127.0.0.1:5173/manage/admin/approvals).
- 실제 관리 조직 권한이 없으면 관리자 업무를 렌더링/조회하지 않는다. 조직 미선택은 먼저 선택하도록 안내한다. 전역 capability만 있는 사용자는 플랫폼 운영을 사용할 수 있고 조직 관리자 권한으로 승격되지 않는다.
- 앱 이동은 전체 페이지 이동과 인증 재확인이다. 선택 조직을 URL 힌트로 전달하되 현재 서버 응답의 소속 목록과 대조하고 선택을 끝내기 전 업무 화면을 보이지 않게 한다. 힌트는 처리 후 URL에서 제거한다. 허용하지 않은 조직·임의 문자열은 권한을 만들지 않는다.
- 같은 출처의 다른 탭은 각자의 조직을 유지한다. 기존 BroadcastChannel 로그아웃은 두 앱 모두에 적용된다. 다른 도메인의 로그아웃/SSO는 별도 단계다.

## 사용자 빌드 경계

실제로 남은 Rollup 모듈(renderedLength>0)과 최종 JS를 검사한다. 사용자 bundle에는 AdminHome/Approvals/AgentSettings/Members/Platform/FeedbackSummary/DocumentSharingPanel과 승인·Job 재시도·문서 공유·한도 변경 실행 코드가 없다. 관리자 bundle에는 사용자 Home/Chat 화면이 없다. 타입과 오류 메시지 공유는 관리 권한을 부여하지 않는다. 권한의 최종 경계는 기존 API/DB다.

`npm run build:user`와 `npm run build:admin`은 각각 typecheck·한 앱 빌드·그 앱 경계 검사까지 수행한다. 한 앱 빌드 전후 상대 산출물의 모든 파일 SHA가 같음을 검증했다. `npm run build`는 두 앱과 양쪽 경계를 함께 검사한다. `build:combined`는 기존 호환 앱을 위한 별도 명령이다.

현재 생성 산출물은 `/user/`·`/manage/` 하위 경로용이다. 정적 서버는 각각의 history fallback을 각 index.html로, `/api`를 기존 서버로 연결해야 한다. 배포 파이프라인에서 두 산출물을 각각 릴리스할 수 있으나 실제 CI/도메인/TLS/외부 릴리스는 연결하지 않았다.
