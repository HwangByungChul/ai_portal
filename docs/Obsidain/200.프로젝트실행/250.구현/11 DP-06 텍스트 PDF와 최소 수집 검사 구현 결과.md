# DP-06 텍스트 PDF와 최소 수집 검사 구현 결과

작성일: 2026-10-07. 검증 소스: `00e31a51cf143f47ebb00ea71b13991f0a75ce94`. [[11 DP-06 수집 검사와 텍스트 PDF 수용 기준]], [[04 DP-06 PDF 원본과 수집 검사 변경 영향 분석]], [[14 DP-06 수집 검사와 텍스트 PDF 상세 설계 및 구현 계획]]의 첫 묶음을 구현했다.

## 화면에서 가능한 흐름

1. 사용자 **내 자료** 또는 관리자 **문서 관리**에서 제목과 텍스트 PDF를 선택한다.
2. 문서 접수 전에 현재 권한·분당10회 시도 제한·파일 구조·최소 수집 검사를 적용한다. 거부된 시도도 검사 요청 제한에 포함한다.
3. 접수 후 색인·게시 상태를 확인한다. 아직 게시되지 않은 파일은 질문 자료로 사용할 수 없다.
4. **AI 업무 → 규정 질의**에서 게시된 문서를 선택하고 질문한다.
5. **근거 보기**에서 인용문과 PDF 페이지 범위를 확인하고 **원문 내려받기**로 등록한 PDF 원본을 받는다.
6. 삭제는 즉시 접근을 차단하고 백그라운드 작업이 원본·추출 텍스트·색인 내용을 정리한다.

기존 UTF-8 TXT/Markdown과 개인 권한·관리자 버전/공유는 유지한다. PDF 원본128KB, 추출40,000자/128KB,20페이지 이하. 스캔·텍스트 없는 페이지·암호화·첨부·폼·외부/수동 링크·자동 실행은 지원하지 않는다. PDF의 시각적 표/다단 레이아웃을 완벽 재현하는 기능은 아니다.

## 변경 내용

| 영역 | 구현 |
|---|---|
| 최소 수집 정책 | 제목+원본 TXT/Markdown 전체 또는 PDF 추출 전체에서 주민번호·휴대전화·이메일·계좌 라벨 뒤 숫자·명시적 지시 무시/시스템 프롬프트 공개 후보 검사 |
| 정책 재확인 | 색인 송신 전 및 검색의 생성 문맥 구성 전 재검사; 알려진 차단은 failed, 검사 장애는 차단 |
| 접수 전 권한/제한 | 신규024 고정 함수; 확인된 동일 접수는 재파싱·쓰기·추가 작업 없이 기존 결과 반환 |
| PDF 격리 | 별도 프로세스, 비밀 환경 미전달, 프로젝트 읽기·쓰기·통신·하위 실행 차단 |
| 자원 제한 | CPU2초·실행5초·펼친 페이지 스트림 합계4MB; 부모 RSS512MB 초과 감시/종료 |
| 원본과 출처 | source=canonical UTF-8, original=원본 PDF, 불변 origin에 각 SHA-256·페이지 맵·파서 버전 |
| GraphRAG | 기존 텍스트 DB와 봉인된 위치 네 필드 유지; 페이지는 현재 권한의 조회 응답에서만 파생 |
| 내려받기/삭제 | 원본·텍스트 지문 확인 후 정확한 PDF 바이트 반환; 삭제/고아 정리 시 두 파일 제거 |
| 화면 | PDF 선택/지원 안내/페이지/형식 확인/안전한 한글 오류; 기존 TXT 다운로드 유지 |

`RLIMIT_AS(512MB)`는 이 macOS Python에서 설정을 거부하여 실제 RSS 감시로 보정했다. 종료 기준을 50ms 간격으로 확인하므로 순간 초과를 금지하는 하드 상한이 아니다. 격리나 감시를 사용할 수 없으면 PDF 접수를 차단한다. 다른 운영체제는 별도 격리 구현·검증이 필요하다.

pypdf6.19.0의 공식 휠 SHA-256을 확인하고 requirements.lock 및 BSD-3-Clause 라이선스를 보존했다. 원본/추출 파일은0600, 디렉터리는0700으로 유지한다. 같은 ID의 동시 최초 요청은 파싱이 중복될 수 있지만 DB 작업/색인 호출은 하나로 유지한다.
