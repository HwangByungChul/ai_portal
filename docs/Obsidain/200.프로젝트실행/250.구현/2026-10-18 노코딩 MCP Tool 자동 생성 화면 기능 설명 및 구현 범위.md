# 노코딩 MCP Tool 자동 생성 화면 기능 설명 및 구현 범위

사용자가 관리자 `/manage/admin/tools`의 ‘노코딩 MCP Tool 자동 생성 & 환경 분기 설정’ 화면이 어떤 기능인지 질문했다. 이번 확인은 코드 읽기이며 실제 API 호출이나 시스템 연동 시험을 수행하지 않았다.

## 의도된 기능

기존 시스템의 OpenAPI/Swagger, WSDL, JDBC 조회 명세, 금융 전문 규격을 입력하여 AI Agent가 사용할 도구 이름·설명·입력 schema를 생성하고 환경별 접속 정보를 연결하는 관리자 기능이다. 예: 대출 한도 조회 API의 필수 입력을 도구 정의로 변환한다. 명세 변환은 기존 시스템 구현이나 실제 업무 연동 완료와 구분한다.

## 확인된 실제 코드 범위

- 화면: `src/frontend/src/ToolAdminPage.tsx`의 명세 선택·입력·parse·등록·시험 호출 및 Dev/Prd 주소 설정.
- API: `src/backend/app/tools/autowrap_routes.py`에 4종 parser 분기, 자동 등록, 목록 및 동적 호출 경로가 있다. 앱 `main.py`에 router가 포함되어 있다.
- 실행: `src/backend/app/tools/dynamic_gateway.py`의 `_execute_protocol`은 현재 모의 결과를 구성한다. 실제 HTTP/SOAP/JDBC/TCP 업무 통신 성공으로 주장할 수 없다.
- 보관: 해당 gateway의 register는 프로세스 메모리 dict에 등록한다. 주석의 DB 보관 언급만으로 실제 영속 저장을 증명하지 않는다.
- 환경: 이 마법사의 요청은 dev_profile/prd_profile 두 종류다. 기존 사용자 결정인 local/dev/tb/prd 전체 구분과 동일하게 구현되었다고 표현하지 않는다.

미검증: 브라우저 parse/등록 응답 연결, 권한·조직 격리·승인 상태 판정, 실제 서비스 통신·인증·영속 저장·4환경 설정 통합. 이번 질의에서 해당 기능의 추가 수정 개발은 수행하지 않았다. 별도 상세 검토 시 기존 승인·저장·실행 원장과의 통합 및 실제 연동 수용 기준을 확인해야 한다.
