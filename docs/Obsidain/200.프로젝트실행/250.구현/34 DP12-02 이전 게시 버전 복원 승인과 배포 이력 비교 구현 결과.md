# 이전 게시 버전 복원 승인과 배포 이력 비교

사용자의 “네 진행 바랍니다”와 중단 후 “계속 진행 바랍니다”에 따라 [[33 DP12-02 이전 게시 버전 복원 승인과 배포 이력 비교 계획]]을 먼저 저장하고 추가 DB/API/React 및 격리 수용·local 이행을 수행했다. [[33 DP12 동적 Agent 승인 게시와 사용자 실행 구현 결과]]의 사용자 A/관리 A/승인 B, 제품 명칭·사이트 분리·기존 권한/예산/실행/정산은 유지했다.

## 실제 기능

- 같은 자산의 과거 approved request/version을 선택하여 별도 rollback 요청을 제출한다. source_request_id·현재 게시 revision·복원 목적·client_request_id를 받으며 임의 초안/다른 자산·조직 source는 불가하다. 원장에 deployment_kind/source_request_id와 historical exact snapshot을 봉인한다. 현재 공개 대상·회원 목록을 복원 요청에 서버가 복사하여 과거 넓은 대상이 자동으로 복원되지 않는다.
- 복원 요청은 요청자와 다른 현재 조직 PADMIN이 품질·보안 체크와 의견으로 승인/반려한다. historical latest-version 차이는 복원의 의도이므로 허용하되 old exact immutable version/profile/config hash와 최소 shared snapshot을 대조한다. 공유 증적 철회, 시험 당시 정책 또는 실행 모드 변경, 승인자의 현재 자료 권한 부족은 승인 불가다. 현재 대상 회원의 비활성·게시 CAS 변화도409다. 승인 불가 요청도 반려할 수 있다.
- 승인 결정과 exact 이전 version/profile 게시를 한 transaction에 저장하고 publication revision을 증가시킨다. 기존 current 공개 대상은 유지한다. 게시 중 동일 version 복원은409, 철회 상태에서 과거 승인 version 재게시는 가능하다. 같은 ID/같은 body receipt와 다른 body409, 동시 동일 결정의 단일 저장/receipt를 검증했다. 기존 직접 v1 capability 실행을 ai_web에서 제거하고 public wrapper가 rollback 결정을 새 capability로 전달하여 일반 승인 경로 우회를 막는다.
- 사용자 실행은 복원된 publication version과 새로운 publication revision으로 기존 owner·문서 ACL·중지·예산·Gateway·dispatch/meter를 사용한다. 복원 전 run은 기존 current publication fence 대상이며 과거 비용 원장은 수정하지 않는다. source/공유 proof가 승인되었다고 일반 사용자의 독립 문서 권한이 넓어지지 않는다.
- append-only asset_publication_events에 신규 게시·복원·철회별 publication revision/request/version/hash/status/actor/time metadata를 저장한다. ai_owner/forced RLS·manage scope, raw web/index/meter 접근 금지·UPDATE/DELETE trigger 금지다. 신규 요청 원장의 기존 불변 trigger도 새 kind/source 열을 보호한다.
- 기존 승인 원장에서 원자 게시가 확인된 revision은 approval_record로 이행하고 현재 게시/철회 상태는 current_state로 기록한다. 관찰된 현재 상태의 actor는 NULL이며 과거 누락 철회 시각/담당자를 만들어 넣지 않는다. history_complete는 전체 revision 구간 확인 여부를 표시한다. 과거 이력 있는 별도 DB에서 [1,2,4,5] 이행과 누락3 비추정, 기존 모든 열 값 보존을 검증했다.
- 관리 B 요청 상세에 이력20건/cursor, 비교 기준·대상 선택, 이름/설명/system/developer/user template/model/자료 선택 before/after/changed, 복원 목적·신청·같은 receipt 재확인을 연결했다. 비교는 양쪽 exact version을 현재 own ACL로 재검사한다. 개인 trial 질문/답변/평가기대조건/claim은 반환하지 않는다. 비교 상세를5초마다 재확인하고 실패 시 숨긴다. parent current publication revision 변경 시 이력을 다시 읽는다.

API: POST /admin/asset-deployments/rollbacks, 기존 /{request}/decision, GET /publications/{asset}/history?cursor 및 /compare?left_revision&right_revision. strict extra/UUID/int/query 중복·CSRF·no-store/read window/기존32KiB 경계를 유지한다. 일반 승인 list/detail에는 kind/source/rollback_ready가 추가된다.

## 미완료·다음

이번 범위는 이전 승인 버전 복원/반려·현재 공개 대상 보존·이력/비교·사용자 exact 복원 실행이다. 전체 DP12/F 기능 개발 완료가 아니다. 다음은 동적 Agent 사용자의 전역 실행 이력과 철회된 Agent의 최소 기록 탐색을 정리하고 기존 대화 화면의 독립 실행 탐색을 연결하는 단위다.
