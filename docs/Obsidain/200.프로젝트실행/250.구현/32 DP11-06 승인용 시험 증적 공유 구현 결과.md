# 승인용 시험 증적 공유 구현 결과

사용자 진행 승인에 따라 [[31 DP11-06 승인용 시험 증적 공유 상세 계획]]을 먼저 Vault에 작성하고 DB/API/React·격리 수용시험·소유 local 이행을 수행했다. [[31 DP11-05 업무 평가 사례와 자동 조건 검증 구현 결과]]의 개인시험/평가 owner RLS는 유지했다.

## 실제 구현

- 작성자가 공유 범위를 확인하고 명시 동의하여 본인의 완료 trial과 정확한 evaluation_id를 제출한다. 서버는 같은 run/result hash, 현재 exact version/profile/자료 ACL, 실행 모드를 확인한다. 최신 버전이 아니면 제출409. 타인 개인 증적/평가에는 접근하지 못한다. 미충족 평가도 미충족으로 보존하며 성공으로 바꾸지 않는다.
- 별도 builder_evidence_shares에 approval-evidence-v1 snapshot을 봉인한다. asset/version/revision/config/profile/composition/result/question hash, run/model/mode/purpose/정책 revision, 자료 document/version/index, 평가ID/case hash/engine/pass·규칙명과 Boolean만 담는다. 결과 텍스트/인용, 질문/messages/values, 기대 문구/spec, 개인 수동 평가/의견/가격/credential은 공유하지 않는다. 지문은 현재 조직 내부 증적이며 공개 자료가 아니다.
- 같은 작성자/client_request_id와 같은 body는 같은 receipt로 재확인한다. 다른 body409, 제출/replay는 현재 개인 권한/자료를 재확인한다. 작성자별 미철회 제출20개 한도, metadata20건 keyset 조회. 원장은 ai_owner·forced RLS이고 ai_web/index/meter raw 읽기/쓰기가 금지된다. 증적/작성자/식별자 변경·DELETE 금지 trigger, executor도 철회 status/revision/time 열만 UPDATE.
- 본인 또는 현재 조직의 유효한 PADMIN만 shared row를 읽는다. 같은 조직의 일반 관리자도 다른 작성자의 공유 row404. 일반 사용자403·타조직404. PADMIN의 개인 trial/case 조회404는 유지한다. 검토자가 자신의 실제 현재 세션과 document/version/index ACL로 snapshot 상세를 읽으며, 작성자로 identity를 바꾸지 않는다.
- 제출 당시 snapshot은 수정하지 않는다. 현재 최신 자산 버전/profile/실행 모드/고정 runtime 정책 revision의 차이를 current_conditions로 표시한다. 자료 권한 부족/자료 삭제 시 상세404. 제출 metadata에는 source·snapshot 본문이 없다. 원본 재변조 전 범위 수용은 이전 잔여로 유지한다.
- 작성자만 expected_revision CAS로 철회한다. 같은 철회는 replay·audit1회. 자료 삭제 이후에도 본인 철회 가능하며, 철회 뒤 검토자에는 최소 처리 metadata만 반환하고 snapshot/hash/current_conditions는 NULL이다. 현재 관리 권한 회수 시 철회403. 개인시험이나 원문을 타인에게 자동 공개하지 않는다.
- Builder 시험 증적에서 자동 검증 선택·공유 범위 설명·명시 동의·제출·동일 접수 확인을 실제 API에 연결했다. 승인·검증 메뉴 안에 기존 운영 설정 요청과 별도의 Builder 시험 증적 B안 목록·상세 패널을 연결했다. 작성자 철회 버튼과 5초 현재권한 상세 재검사를 제공한다. 늦은 응답/조직scope 변경/상세 실패 시 이전 snapshot을 숨긴다.

API: /api/v1/admin/builder/evidence-shares POST/GET, /{share_id} GET, /{share_id}/withdraw POST. strict UUID/consent=true/extra·중복query 거부, CSRF/write context, read_window, no-store, 기존 builder body32KiB 경계를 사용한다. 대기 한도는 DEPLOYMENT_QUEUE_FULL409다.

## 미완료·다음

이번 단위는 정확한 승인용 최소 증적의 명시 제출/조회/철회다. 승인·반려·재신청/공개 대상/동적 실행 활성화·폐기·rollback은 아직 미구현이며 다음 DP12 단위다. 승인 메뉴의 기존 고정 운영 설정 승인만 실제 설정에 반영한다. Builder 증적 제출을 승인/게시/배포 완료로 표현하지 않는다.
