## 4. 첫 migration의 구체 범위·권한

첫11개는security 7개(accounts/tenants/memberships/platform_access/managed_tenants/sessions/login_windows), portal 2개(agent_configs/conversations), ops 2개(project_budget/audit_events)다. 일반대화API는B까지개방하지않지만 **운영대화테이블 자체**를A의실제RLS시험에사용한다. RLS통과용별도장난감테이블을만들지않는다.

B migration은portal.messages/runs와ops.tenant_budgets/call_attempts/usage_events의5개를추가한다. C migration은security.operation_receipts/document_access/private_readers/publications/share_grants/job_authorizations(6),rag.document_versions/index_builds/jobs/chunks/entities/relations/evidence/relation_evidence(8),portal.answer_evidence(1)의15개를추가한다. **11+5+15=31**. 아직없는문서helper를항상true로만들지않는다. migration실행기의 `infra.schema_migrations(version,sha256,applied_at)` 1개는도구메타데이터이며업무31개와별도로표기한다.

| DB역할 | 접속/권한 |
|---|---|
| mvp_bootstrap | 전용클러스터초기관리·migration/합성초기화. 앱실행환경금지 |
| ai_owner | NOLOGIN,업무schema/portal/ops 소유. runtime상속없음 |
| ai_policy_executor | NOLOGIN,security정본+고정함수소유;project_budget 지정열SELECT/audit제한INSERT만추가 |
| ai_web | LOGIN/NOSUPERUSER/NOBYPASSRLS/NOINHERIT/NOCREATEDB/NOCREATEROLE;고정인증/관리함수EXECUTE·RLS portal SELECT/INSERT·허용열UPDATE |
| ai_index / ai_meter | 같은비우회LOGIN조건;A에는portal/security raw읽기/원장직접쓰기/function권한없음. B/C 자기책임함수만추가 |

runtime에는CONNECT/필요schema USAGE만부여하고PUBLIC의DB CREATE/TEMP·schema CREATE·함수EXECUTE를회수한다. ai_web은owner/policy_executor/index/meter로SET ROLE할수없다. 모든고정함수는 `SECURITY DEFINER SET search_path=pg_catalog,security,pg_temp`와schema-qualified SQL,현재 `session_user` 검사,정확signature EXECUTE grant를사용한다. policy_executor에게대화본문SELECT를주지않는다. ### 4.1 RLS와요청문맥

`security.can_read_own_conversation(row_tenant uuid,row_owner uuid)->boolean`은transaction-local `app.user_id/app.tenant_id/app.session_id`를읽어형식이유효하고현재account/session/membership/tenant가활성일때만true를반환한다. session.auth_revision=account.auth_revision,revoked_at NULL,DB시각<expires_at/last_activity+30m도검사한다. 관리역할예외가없다. `security.can_read_agent(row_tenant uuid)->boolean`은같은현재문맥/활성소속을검사한다. `security.can_manage_current_tenant(row_tenant uuid)->boolean`은TADMIN 또는PADMIN+명시관리소속만허용한다. 이helper들은security만읽고자기portal정책을재귀조회하지않는다.

```sql

ALTER TABLE portal.conversations FORCE ROW LEVEL SECURITY;
CREATE POLICY conversation_owner ON portal.conversations TO ai_web
 USING (security.can_read_own_conversation(tenant_id,owner_user_id))
 WITH CHECK (security.can_read_own_conversation(tenant_id,owner_user_id));

 USING (scope_kind='tenant' AND security.can_manage_current_tenant(tenant_id));

 WITH CHECK (scope_kind IN ('auth','platform') OR
             (scope_kind='tenant' AND security.can_manage_current_tenant(tenant_id)));
```

A에는 활동 기록 목록 API가 없다. audit의 web SELECT를 부여할 때도 허용된 최소 열만 부여한다. project_budget는 raw 권한 회수로 전역 제어를 보호하며 콘텐츠 RLS와 구분한다. RLS는 superuser/BYPASSRLS를 제한하지 못하므로 실제 접속 역할 검사가 완료 조건이다. [PostgreSQL RLS](https://www.postgresql.org/docs/15/ddl-rowsecurity.html).

매 요청은 BEGIN→세션/현재 권한 검사→`set_config(...,true)`→업무 SQL→성공한 사용자 행동의 idle 갱신→commit 순서다. 실패/취소는 rollback하며 세션 범위 SET·전역 active_tenant는 금지한다. 기본 조회 격리는 READ COMMITTED, 변경은 현재 주체/대상 행을 잠근 뒤 재검사한다. DB 잠금을 네트워크/브라우저 대기 동안 유지하지 않는다.

```python
from contextlib import asynccontextmanager
from dataclasses import dataclass, field
from uuid import UUID
from psycopg import AsyncConnection
from psycopg.rows import dict_row
from psycopg_pool import AsyncConnectionPool

@dataclass(frozen=True)
class AuthContext:
    session_id: UUID
    user_id: UUID
    tenant_id: UUID | None
    effective_role: str | None
    csrf_secret: str = field(repr=False)

def make_web_pool(dsn: str, size: int = 4) -> AsyncConnectionPool:
    return AsyncConnectionPool(dsn, min_size=1, max_size=size, timeout=5,
        open=False, kwargs={"autocommit": True, "row_factory": dict_row,
        "options": "-c timezone=UTC -c statement_timeout=5000 -c lock_timeout=2000"})

@asynccontextmanager
async def tenant_transaction(pool: AsyncConnectionPool, ctx: AuthContext):
    if ctx.tenant_id is None:
        raise ValueError("tenant context required")
    async with pool.connection() as conn:
        async with conn.transaction():
            for key, value in (("app.user_id", ctx.user_id),
                               ("app.tenant_id", ctx.tenant_id),
                               ("app.session_id", ctx.session_id)):
                await conn.execute("SELECT set_config(%s,%s,true)", (key, str(value)))
            yield conn
```

실제 요청에서는 쿠키 검증으로 얻은 내부 값만 context에 전달하고, user/role을 요청 본문에서 만들지 않는다. Pool은 lifespan open/wait/close를 사용하고 반환 시 로컬 GUC 제거를 검증하며 깨진 connection은 폐기한다. 정상/rollback/취소 후 size1 풀에서 같은 connection을 재사용하는 시험이 필수다. 위 코드 조각은 실제 세션 검증을 생략하는 dependency가 아니다. [psycopg pool lifecycle](https://www.psycopg.org/psycopg3/docs/advanced/pool.html).

### 4.2 초기화·재현 계약

- A/B UUID는240.03의`10000000-0000-4000-8000-00000000000a/b`를사용한다. actor/user/membership UUID는`uuid5(UUID('4c9e4258-a883-4e35-9458-6736a31a0c11'), actor_id)`와`tenant_label+':'+actor_id`로재현한다. 평가actor ID는정책증표가아니다.
- 기존 manifest의 액터 9명과 소속을 읽는다. ACT-PADMIN은 USER 소속+platform_access+managed_tenants로 변환한다. managed_tenants는 PADMIN에게만 기록하고 TADMIN 관리는 memberships.role에서 얻는다.
- login_id는 actor_id.lower(), display_name은 합성 액터 라벨이다. 각 비밀번호는 `secrets.token_urlsafe(24)`로 생성하고 Argon2id 해시한다. 원문은 0600 fixture-secrets 파일에만 보관한다. NO_MEMBERS/P_READ_ONLY/P_WRITE_ONLY/P_NONE는 런타임 시험용 추가 fixture로만 생성하며 원본 manifest는 보존한다.
- 조직별 고정 Agent 2행은 A에서 enabled=false/settings={}로 둔다. 대화 시험은 A-U1/A-U2/B-U1/DUAL의 소속별 대화 행을 seed하고 DB RLS 검증에만 사용한다. 질문/답변 본문은 아직 없다.
- project_budget는 2026-10-01의 mock/real 2행을 seed한다. 각각 approved=30000/operational=25000/reserved=0/accounted=0/stopped=false다. A 앱 mode는 mock이며 API-03은 실제 행을 읽는다. 상태 행이 없으면 503이며 가짜 enabled/revision을 반환하지 않는다.
- 테스트 DB는 `ai_portal_mvp_test_` 접두+생성 UUID로 전용 클러스터에 suite별 새로 만든다. DB comment의 fixture marker와 클러스터 소유 경로가 모두 맞아야 reset/drop한다. real DB/원장과 기존 5432 DB는 seed/reset 대상 밖이다. 앱은 ai_web, 초기화는 관리자 전용 자격으로 분리한다.

## 5. API와제어함수의정확한인계

모든 경로는 `/api/v1`로 시작한다. 성공 응답은 `data`와 `meta={request_id,tenant_id,server_time}`, 오류는 `error={code,message,field_paths,retryable}`+meta다. no-store/X-Request-ID를 적용하고 개인 입력값을 되돌려 주지 않는다. UUID/중복 헤더/알 수 없는 JSON 필드는 422/400의 안전한 메시지로 처리한다. DB 실패는 503 STORAGE_UNAVAILABLE, 인증 401, CSRF/권한 403, revision 409, 창 초과는 429+Retry-After다. 401에는 `WWW-Authenticate: Session realm="ai-portal"`을 쓴다.

| API | 입력 | data 최소응답/행동 |
|---|---|---|
| GET /health | 공개 | `{status:'ok'}`;내부주소/DB구성없음 |
| POST /auth/login | JSON login_id/password;정확Origin/X-Requested-With | user_id/display_name/session_expires_at/csrf_token;Set-Cookie만session token |

API03 capability는 현재 is_padmin/active/permission으로 독립 계산한다. reader-only는 합산 권한 true/중지 권한 false/availability 없음, writer-only는 반대이며 실제 availability를 반환한다. P_NONE은 둘 다 false다. 이 capability가 개인/타 조직 콘텐츠 조회나 아직 미구현인 API39/40을 허용하지 않는다.

touch_session과 소속 함수는 session_id를 HTTP 본문으로 받는 API가 아니다. 현재 쿠키 해시 검증에서 얻은 내부 ID만 전달한다. 세션 생성/credential 함수는 신뢰된 인증 모듈의 책임이며 web DB 자격 유출까지 막는 독립 인증 경계로 주장하지 않는다. parameterized SQL과 고정 grants는 별도로 검증한다.

### 5.1 DTO와 실행 설정

`src/backend/app/types.py`는 다음 공개 DTO를 정의한다. UUID/시간은 JSON 문자열로 직렬화하고 요청 DTO는 Pydantic ConfigDict(extra='forbid')를 쓴다. 비밀번호와 session_token은 공개 SessionView에 넣지 않는다.

```sql
RETURNS boolean LANGUAGE plpgsql SECURITY DEFINER
SET search_path=pg_catalog,security,pg_temp AS $body$
DECLARE
 ctx_session uuid; ctx_user uuid; ctx_tenant uuid;
BEGIN
 IF session_user <> 'ai_web' THEN RETURN false; END IF;
 BEGIN
  ctx_session := NULLIF(current_setting('app.session_id',true),'')::uuid;
  ctx_user := NULLIF(current_setting('app.user_id',true),'')::uuid;
  ctx_tenant := NULLIF(current_setting('app.tenant_id',true),'')::uuid;
 EXCEPTION WHEN invalid_text_representation THEN RETURN false;
 END;

 RETURN EXISTS (
  SELECT 1 FROM security.sessions s
  JOIN security.accounts a ON a.user_id=s.user_id
  JOIN security.memberships m ON m.user_id=a.user_id
  JOIN security.tenants t ON t.tenant_id=m.tenant_id
  WHERE s.session_id=ctx_session AND a.user_id=ctx_user
  AND m.tenant_id=ctx_tenant AND m.tenant_id=row_tenant AND a.user_id=row_owner
  AND a.active AND m.active AND t.active AND s.revoked_at IS NULL
  AND s.auth_revision=a.auth_revision AND clock_timestamp()<s.expires_at
  AND clock_timestamp()<s.last_activity_at+interval '30 minutes'
 );
END;
$body$;
```

```python
import hashlib
import re
import secrets
from argon2 import PasswordHasher, Type
from argon2.exceptions import InvalidHashError, VerificationError

hasher = PasswordHasher(memory_cost=19456, time_cost=2, parallelism=1, type=Type.ID)
dummy_hash = hasher.hash(secrets.token_urlsafe(24))

def normalize_login(value: str) -> str:
    result = value.strip().lower()
    if re.fullmatch(r'[a-z0-9._-]{3,64}', result) is None:
        raise ValueError('login_id')
    return result

def token_digest(value: str) -> bytes:
    return hashlib.sha256(value.encode('ascii')).digest()

def verify_password(encoded_hash: str | None, password: str) -> bool:
    if len(password) > 128 or len(password.encode('utf-8')) > 512:
        return False
    try:
        valid = hasher.verify(encoded_hash or dummy_hash, password)
        return bool(encoded_hash) and valid
    except (InvalidHashError, VerificationError):
        return False

def new_secret() -> str:
    return secrets.token_urlsafe(32)
```
