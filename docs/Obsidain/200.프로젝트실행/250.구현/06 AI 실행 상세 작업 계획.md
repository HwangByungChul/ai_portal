# AI 실행 상세 작업 계획

승인된 [[03 일반 대화와 중앙 AI 구현 계획]]의 B04를 순차 수행한다. B03 소스 `40a28621652d91b04ee7eb613955db5b0bb813f5`, 문서 `2c508dde2c4d117182e55d966d8739fc5f7e929d`가 시작 기준이다. 예상 4~5시간은 사람 작업 추정이며 실제 작업 시간과 구분한다. 이번 단계 외부 AI 호출·요금·API 키 조회는 0건이다.

1. 기존 000~007, 합성 자료, 평가 질문, 비공개 실행 설정과 16개 업무 테이블을 보존한다.
2. 008에 실행 소유권, 예약, 단 한 번의 발사, 정산, 미발사 해제, 재시작 복구를 고정 함수로 구현한다. 로그인 역할의 직접 원장 쓰기와 meter의 본문 읽기는 계속 차단한다.
3. 예약 3.64원과 슬롯(전체 2, 조직 1)은 같은 짧은 트랜잭션으로 반영한다. 슬롯 대기 최대 5초는 연결 밖에서 수행한다. 발사 전 현재 최초 세션·조직·권한·Agent 설정·예산·실행 세대·10초 허가를 재검증한다. 예약/발사 커밋 확인 실패 시 SDK 호출 0건이다.
4. 사용량과 원격 종료를 별도로 기록한다. 동일 영수증은 재반영하지 않고 다른 영수증은 정산 충돌로 신규 호출을 중지한다. 실제 금액이 예약을 넘으면 실제 금액을 기록하고 중지한다. 사용량 미확인 금액과 종료 미확인 슬롯은 시간 경과만으로 풀지 않는다. 권한 상실 후에도 이미 발사한 호출의 정당한 사용량만 meter가 반영한다.
5. 모의 제공자와 고정 OpenAI SDK 어댑터를 동일 계약으로 구현한다. SDK 재시도 0, 60초, 최대 출력 1,024토큰, 기본 서비스 등급이다. 실제 모드는 명시 설정과 준비 검증을 요구하며 모의로 자동 대체하지 않는다. SDK 시험은 가짜 전송으로만 진행한다.
6. 단일 실행 관리자(데이터베이스 전용 리더 잠금)가 작업 소유권을 획득한다. 20초 heartbeat/60초 lease/180초 총 제한을 적용한다. 취소 우선, assistant와 completed 원자 저장, 동일 결과 저장 1회 재시도, 재시작 시 unfinished→interrupted 및 발사 재실행 0을 시험한다.
7. events API를 fetch SSE로 연결한다. 최초/재연결 snapshot, 250ms 단위 draft, 15초 keepalive, 실행당 구독 1·사용자당 2를 적용한다. 매 본문 전달 전 현재 접근 재검증, 저장 후 terminal, 끊김 자체는 성공·취소로 처리하지 않는다. 종료 시 초안 메모리를 폐기한다.
8. 신규 실패·경쟁·권한·정산·취소·복구·SDK·SSE 시험과 기존 전체 backend/browser 회귀를 실행한다. 008만 기본 DB에 적용 후 재적용 0건·업무행 보존·연결/임시 DB/프로세스 정리를 확인한다.
9. 단계 결과, 증거, 대장, 로컬 소스 및 문서 커밋을 기록한다. 후속 B05 사용자 대화·운영 화면 상세 계획을 보고한다. B05 UI, C GraphRAG, B06 유료 대표 호출은 이번 범위 밖이다.

현재 기존 Agent가 비활성이고 조직 예산 미설정인 기본 DB는 임의 초기화하지 않는다. 실행 활성화는 명시 서버 설정이며, 시험은 별도 폐기 DB의 합성 계정·예산을 사용한다.

공식 근거: [OpenAI 스트리밍 이벤트](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events). usage 마지막 chunk의 choices는 비어 있을 수 있고, 중단 시 usage를 받지 못할 수 있다. 누락을 0원으로 확정하지 않는다. 설치 SDK 3.24.0의 코드·가짜 전송으로 호출 옵션과 종료 동작을 확인한다.
