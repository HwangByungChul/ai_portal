# DP-09 동적 AI 자산 초안 관리 구현 결과

사용자 요청 “조사 결과에 대해 개발 계획서 작성 후 개발 진행”에 따라 [[15 전체 기능명세서 잔여 기능 개발 실행 계획]]·[[24 DP-09 동적 AI 자산 기반 상세 설계와 실행 계획]]을 Obsidian에 먼저 저장한 후 첫 묶음을 구현했다.

## 구현한 실제 기능

- 관리자5174의 **AI 자산 관리**(`/manage/admin/assets`)에서 새 Agent 초안 등록·최신 상세·이력 조회·수정 버전 저장이 가능하다.
- 등록 ID/버전 ID·서버 계산 SHA256 지문·등록자·작성 시점을 PostgreSQL에 저장한다. 기존 버전은 수정/삭제 권한 없이 보존한다. 목록은 지시문을 제외하고 cursor로 나눈다. 상세 이력은 최근50개를 표시하고 과거 버전 저장은 유지한다.
- client_request_id 기반 동일 요청 재확인과 CAS revision 충돌, 동시 수정·감사 실패 rollback을 구현했다. 응답 유실 시 입력을 고정하고 같은 요청으로 확인한다. 충돌 시 입력 초안을 보존하고 최신 이름/설명/실행 방식/지시문을 비교 후 다시 저장한다.
- 현재 tenant 관리 권한을 API와 DB RPC에서 각각 확인한다. USER·타조직·회수 권한·제한 PADMIN·직접 테이블 접근을 차단한다. 공통 CSRF/Origin/body32768 제한/조회 rate limit을 유지한다. audit에는 원문 지시문 대신 ID와 revision만 저장한다.
- fixed general/rules_rag는 결정적 UUID의 읽기 전용 view 연결이다. 현재 설정 기본값을 표시하며 수정은 기존 Agent 관리→승인·검증 경로로 안내한다. 조회 중 DB를 쓰지 않으며 새 tenant에도 같은 투영을 적용한다. 해당 지문은 현재 관리 설정 지문이며 실행 snapshot 지문이 아니다.
- 최초 asset 종류는 agent, execution_kind는 general/rules_rag이다. 새 자산은 draft로만 저장하고 실행 API에 연결하지 않는다. 승인/활성버전 계약 없이 실행/공개할 수 없다.
