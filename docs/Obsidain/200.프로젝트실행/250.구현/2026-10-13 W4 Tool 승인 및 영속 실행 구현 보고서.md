## 요청과 완료 범위

사용자의 ‘다음 작업 진행’ 승인에 따라 W4 Tool의 독립 읽기 실행을 구현했다. 작업 계획29를 Obsidian에 먼저 저장하고 실패 테스트부터 진행했다. 실제 Python API·PostgreSQL 승인/실행 원장 구현과 합성 시험 DB 검증이다. 기존 local 데이터베이스 적용·기관 연결·관리자 React 화면·전체 F4/F5·상용 운영 완료를 뜻하지 않는다.

변경은 현재 프로젝트 `/Users/jwpios/antigravity/202610_AI 플랫폼` 원본에서 수행했다. Unicode 디렉터리는 실제 NFD이며 기존 수정·미커밋 파일을 보존했고 일괄 되돌리기/커밋/배포는 없었다.

## 구현 동작

1. 관리자는 서버 registry의 Tool3종 중 하나를 승인 요청한다. Tool ID, 인자 schema, 명시 adapter revision, adapter/registry 원본 코드 SHA, 실행 mode, timeout을 digest로 묶는다. 임의 URL·handler·비밀을 클라이언트가 제출할 수 없다.
2. 다른 PADMIN이 CAS revision으로 승인/반려한다. 자기 승인과 TADMIN의 승인 결정은 거부한다. 조직별 head가 정확한 요청 버전을 참조한다. 변경·재승인·철회는 현재 head revision을 요구한다. 관리자 목록은 현재 head revision을 포함한다.
3. 사용자 실행은 현재 계정·소속·조직, 승인 head, mode/digest, audience all/restricted와 허용 사용자 목록, 설정 period/mode의 플랫폼 중지·stop latch 및 존재하는 조직 중지를 확인한다. 미관측 기간의 플랫폼 설정도 준비로 인정하지 않는다.
4. 요청 ID는 필수 UUID다. DB 키 tenant/user/client ID와 Tool/version/strict arguments 지문으로 동일 재시도는 기존 결과를 재생하고 다른 인자/Tool/version은409다. 다른 조직·사용자는 같은 client ID를 독립적으로 사용할 수 있다.
5. accepted에서 dispatch token으로 한 요청만 실행한다. dispatched 이후 timeout/취소/오류·프로세스 중단은 unknown(확인 필요)으로 보존하고 같은 ID로 자동 재호출하지 않는다. accepted 상태는 다시 안전하게 claim할 수 있다. 외부 효과 exactly-once 보장을 의미하지 않는다.
6. 성공 결과는 출력 policy 검사와 현재 권한 재확인, DB 저장 성공 후에만 반환한다. 입력 차단은 admission·handler보다 먼저 적용한다. 원문 arguments는 DB receipt/audit에 저장하지 않는다. 저장 결과 조회에도 현재 policy와 승인 회수를 재확인한다. 실패 원문·외부 예외를 public result로 반환하지 않는다.
7. 요청 body와 출력은 UTF-8 32KiB로 제한한다. string type·required·enum·maxLength·additionalProperties와 기존 URL/SQL/경로 안전 검사를 적용한다. 현재 Tool schema는 bounded string만 허용하므로 object/list를 문자열로 변환해 실행하지 않는다. 사용자별 미완료 queue20건으로 admission을 제한하되 이미 저장한 요청의 재시도는 유지한다.
8. mock에만 FixtureToolAdapter를 명시 주입한다. fixture 결과는 source=fixture로 표시한다. real 기관 adapter는 미구현이므로409이며 모의 데이터로 대체하지 않는다. execution_enabled도 실행 gate로 유지한다.

## API 계약

| 경로 | 인증과 동작 |
|---|---|
| `GET /api/v1/tools` | 현재 조직 Tool 카탈로그, execution_ready·mode·version_digest. 미승인/정지/미준비는 ready=false |
| `POST /api/v1/tools/{tool_id}/invoke` | `arguments`, 필수 `client_request_id` UUID; CSRF/write context, execution_enabled, 현재 승인과 strict 검사를 통과한 독립 읽기 실행 |
| `GET /api/v1/tools/{tool_id}/receipts/{client_request_id}` | 본인·현재 권한의 저장 결과 조회. 비공개 dispatch token/claimed는 응답에 포함하지 않음 |
| `GET /api/v1/admin/tool-approvals` | 관리 범위의 최신50요청·현재 head revision 목록. 후속 UI 전체 pagination은 별도 |
| `POST /api/v1/admin/tool-approvals` | tool_id, client_request_id, expected_head_revision, audience, member_ids. descriptor는 서버가 구성 |
| `POST /api/v1/admin/tool-approvals/{request_id}/decision` | decision=approve/reject, expected_revision. 타인 PADMIN 결정과 head CAS |
| `POST /api/v1/admin/tools/{tool_id}/revoke` | expected_revision으로 현재 head 철회 |

실행 응답 state는 accepted/dispatched/succeeded/failed/unknown이며 receipt_id/client_request_id/tool_id/approval_id/version_digest/revision/result/error_code를 제공한다. 조회 시 정책 차단은 저장된 succeeded 이력을 실패로 바꾸지 않고 result=None·result_access=blocked로 표시한다. 실제 timeout은 Tool별 timeout, DB lease는 timeout+5초다. 조회/동일 요청 재시도 시 만료 dispatch를 unknown으로 확정한다. 배경 재발사는 없다.
