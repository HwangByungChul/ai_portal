# DP-05 개인 문서함 구현 결과

작성일: 2026-10-07. [[10 DP-05 개인 문서함 수용 기준]], [[03 DP-05 개인 문서함 변경 영향 분석]], [[12 DP-05 개인 문서함 상세 설계]]에 따라 TXT/Markdown 개인 문서함과 질문 첨부 범위를 구현·모의 검증했다.

## 사용 가능한 흐름

1. 사용자로 로그인하고 현재 조직을 선택한다.
2. **내 자료**에서 제목과 UTF-8 TXT/Markdown 파일을 선택해 **문서 접수**한다. 이 문서는 현재 조직에서 본인만 읽는다.
3. 본인 문서 제목·접수/처리/게시 상태를 확인한다. 새로고침과 처리 목록으로 진행을 확인한다.
4. 게시 완료 후 **AI 업무 → 규정 질의 → 읽을 수 있는 자료**에서 개인 버전을 선택하고 질문한다. 근거·원문을 확인할 수 있다.
5. **내 자료 → 문서 삭제 → 문서 삭제 확인**으로 삭제한다. 접근 차단은 즉시 적용되고 내용·파일 정리는 별도 작업으로 진행한다.

일반 등록 접수와 색인 완료·게시를 구분한다. 파일은 128KB·40,000자, 제목 200자, 전체 요청 147,456바이트 이하로 제한한다. 기존 TXT/Markdown 파서·GraphRAG·자료 선택·중앙 비용 제한을 재사용한다.

## 구현과 권한

| 변경 | 결과 |
|---|---|
| 사용자 multipart 계약 | client_upload_id/title/media_type만 허용; owner/tenant/share/reader 입력은 거부 |
| 개인 목록·상태 | 사용자 경로로 직접 등록한 본인 문서·작업만 조회; 서명 커서를 주체·조직·목록 종류에 바인딩 |
| DB 023 | user_owned 불변 구분과 8개 사용자 고정 함수 추가; 기존 문서는 false 유지 |
| 작업자·복구·삭제 정리 | 대상이 사용자 개인 문서이며 현재 주체 소유일 때만 기존 처리 권한 조건에 추가; 계정·조직·멤버십·리스·Agent·요금 통제 유지 |
| 관리자 경계 | 기존 관리자 등록/버전/공유 권한 검사 유지; 관리자에게 타인 개인 원문 읽기 권한 추가 없음 |
| 삭제·봉인된 답변 | 검색·신규 질문·기존 답변·근거·원문·피드백 접근 회수; 사용량·감사·실행 출처 식별자 유지 |
| 화면 | 내 자료 개인 등록/목록/상태/삭제 및 기존 규정 자료 선택; 조직 전환·모바일·응답 유실 재접수 검증 |

기존 GET /api/v1/documents는 게시 자료 읽기 목록이므로 그대로 유지했다. 본인 관리 목록은 GET /api/v1/documents/mine, 작업은 /api/v1/document-jobs, 등록과 삭제는 /api/v1/documents를 사용한다. 상세 API·소스는 [[12 DP-05 개인 문서함 상세 설계]] 및 src/backend/README.md에 기록했다.
