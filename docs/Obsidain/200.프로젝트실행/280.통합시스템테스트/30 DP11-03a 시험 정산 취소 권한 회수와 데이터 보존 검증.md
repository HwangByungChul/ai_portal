## 실패와 수정 이력

처음에는 router 들여쓰기, 신규 RLS 순환 조회, 완료 answer_kind/provenance 제약 누락, SQL CASE 구문을 발견해 수정했다. trial unknown slot은 기존 원장의 보존 계약이므로0을 기대한 시험을 바로잡았다. 재시작은 기존 리더 advisory lock을 잡는 시험으로 수정했다. 잘못된 UUID 문맥은 false로 거부하고, 제한 helper가 sequence scope를 owner로 바꾼 회귀는 이전 scope를 즉시 복원하여 수정했다. 삭제/purged 메시지 순번 재사용 방지 시험을 재통과했다.

한 auto-review는 worker 조회에 agent_admin scope를 추가하는 변경을 거부했다(권한 범위 확대 우려). 해당 변경은 적용하지 않았다. 기존 관리 권한을 이미 통과한 worker claim 응답에서 sealed 초안 출처를 받는 대안으로 해결했다. 관리 권한을 새로 부여하지 않았다.

검증 harness/pytest를 동시에 실행해 공용 bootstrap role tuple 갱신·HTTP 포트 충돌이 발생했다. 제품 성공으로 집계하지 않고 단독 순차 실행으로 재검증했다. 첫 브라우저 단독10사례는8pass/2fail: worker claim 직후 취소 CAS가 stale여서 취소가 진행되지 않았고, 다음 fixture 초기화에도 영향을 주었다. 최신 상태 조회 후 동일 취소 의도를 한 번 재시도하도록 수정하여 최종 단일10pass. 초기 실패 요약은 browser-prior-safe.json에 보존했다.
