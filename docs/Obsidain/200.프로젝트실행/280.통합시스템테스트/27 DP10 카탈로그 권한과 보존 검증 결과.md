## 실패·보정 경위

1. 카탈로그 API fail-first1건은 미구현404로 실패했다. 초기19건 중8건은 기존 agent_admin RLS에서 FOR UPDATE 행 잠금이 허용되지 않아404였다. 기존 관리 권한 함수의 agent_availability scope로 Agent를 잠근 뒤 agent_admin으로 복귀했다. 보정 후19 pass.
2. 전체 pytest는159 pass/16 setup error에서 중단했다. HTTP 테스트 포트8000 충돌과 과거 synthetic snapshot이 비어 있던 b_schema 초기화 오류였다. 프로젝트 소유 서비스만 중지하고 fixture를 현재 불변 출처 형식으로 보정했다. child=None 정리 오류도 보정했다.
3. 관련327건에서 남은 사용량 fixture3건의 빈 snapshot을 보정했다. 출처 trigger나 SQL000~028을 완화하지 않았다. 과거028 보존 검사는028까지의 파일만 적용하도록 고정해029와 분리했다.
4. 보강41건의 요약2건은 일반 대화 권한을 회수한다는 잘못된 테스트 가정이었다. 실제 요약은 rules_rag를 사용한다. 해당 정책으로 시험을 보정하고 summary_admit·summary_replay의 제출 gate도 추가했다. 신규/진행 중 요약과 재시도는 같은 현재 권한을 확인하며 과거 본인 이력 조회는 유지한다. 전체 요약 회귀를 다시 검사했다.
5. 프런트 초기 타입 오류는 공통 홈 호출부와 blockReason dictionary 사용을 보정했다. JSON 크기 제한은 기존 문서 multipart 제한과 중복되지 않도록 정리하고 실제 초과 byte413을 검증했다.
6. 초기 브라우저는 호환 combined 화면으로 진입해 새 메뉴를 못 찾았다. 분리 앱·실제 사이트 link를 사용하도록 수정했다. 저장/조회 role=status가 동시에 보이는 정상 상태는 안내별 선택자로 구분했고, 사이트 이동 후 메뉴 준비를 기다렸다. 복수 조직 계정은 조직 선택 전 안내가 표시되는 정상 동작에 맞춰 진입 대기를 보정했다.
7. 실제 관리 화면에서 계정이 비활성이지만 membership이 활성인 후보가 보였다. 별도의 관리 후보 조회로 계정·membership 모두 활성인 동일 조직 사용자만 제한된 페이지로 반환하도록 수정했다. API38건과 관련 화면을 재검증했다. 모바일 필터 label과 입력도 각 이름 아래에 배치했다.
