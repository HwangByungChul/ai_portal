# T280-2 잔여 통합 조건과 실제 실행 준비

입력은 [[02 통합 검증 1차 결과와 결함 조치]], 설계 [[../240.설계/08 검증과 재현 설계]], `evidence/T280-integration/verification-matrix.json`이다. **다음 작업은280의 잔여 검증이다.** 이행290은280의 판정과 인계를 받은 뒤 수행한다. 요구41개를 서버 시험 개수나 관련 모듈 통과만으로 완료 처리하지 않는다. 10/31·주20h이상·기존80h(여유10h 포함)를 유지하며 아래 예상 시간은 기존280의6h 안에서 재배정한다. 개인 실투입은 미측정이다.

## 1. 기존 증거의 정확한 입력 대조 — 예상45분

설계 DB/REQ/AI/RG/UIV 각12개(총60개)와ACL16의 입력·기대 결과를 단일 행동까지 나눈다. 현재 추적표의 관련 case가 실제로 그 행동을 수행했는지 코드의 assertion·실행결과·제품/시험/설정 SHA·actor/조직/모드를 확인한다. 범위가 덜 검증된 입력은 부분 근거와 남은 행동을 함께 기록한다. 기존 backend747/C06 모의Q20 20/20는 이전 결과로 표시하고 이번 전체 재시험으로 바꾸지 않는다.

완료 결과: 각 입력의 최종 pass/fail/not_run 및 근거 위치, V 하위 조건과 상위 판정, mode M/R 구분. 원본 Q20의실행상태는변경하지않는다. 현재132개 보수적 미판정 하위조건에는 이미관련모듈시험이있는항목도 포함되므로 신규시험132개가 필요하다는 뜻이 아니다.

자체 표식이 있는 비primary 폐기용 DB만 사용한다. 새로운 테스트용 강제완료/원장조작 API를 제품에 만들지 않는다. 양순서가 있는 새 시험은 양순서×3회, 한도+1은 독립 카운터와새발사0을 확인한다. 수정이 있으면 영향 있는 서버 시험 및 전체 화면을 재시험하고 소스지문을 갱신한다. 수정이 없으면 이미 통과한 동일 소스의 시험을 무조건 반복하지 않는다.

완료 결과: 사례별 기대/관측/결함/수정/재시험과관련SHA. 자료유출·상한우회·중복유료발사·원장/자료소실은 해당 판정을 차단한다.

## 3. 기존 원장을 보존하는 실제 실행 프로필 설계 — 예상45분

현재는 기본mock·RAG비활성·real색인0이고 설계real프로필과지속fixture에차이가있다. A에실500원/내부기발생0.19원·잔여499.81원, Breal배정없음이다. 키등록은실제권한성공증거가아니다. 새DB/새500원/사용0초기화로 우회하지 않는다.

다음 설계에서는 다음 항목을 문서로 먼저 구체화한다.

1. 기존지속DB/원장·mode별사용/예약/unknown·기간을 그대로사용하는별도통제실행설정과source-store, defaultmock복구를정한다. 제품의primary보호guard를약화하지않는다.
2. source7버전의모드별index/게시포인터/공유v1·privateowner·currentACL을확인한다. mock벡터를real검색에재사용하지않는다.
3. B질문에필요한배정은기존총500원안의재분배안으로작성한다. A기발생0.19·예약·unknown을보존한다. 범위/배정변경이필요한부분은구체적설계를검토받은뒤실행한다.
4. 중앙모델경로·SDK재시도0·같은call1회·기간/권한·개별/조직/프로젝트상한·remoteunknown종료/기본설정복구를명시한다.
5. 가격과키권한/프로젝트usage는실제호출직전에공식자료/현재상태로다시확인한다. 기존16.96원(7doc배치/5query/최대4gen), 최대112doc배치37.96원은내부예약예시로청구액이아니다. 기존일반3회를불필요반복하지않는다.

완료 결과: 실행 대상·모드·기존원장동일성·예산안·복구·대표입력·중단조건이포함된실행계획. 조건이충족된뒤에만대표실RAG4정상+1보류를최소횟수로검증한다. 준비미완료이면R은not_run을유지한다. 부정권한 입력에는 유료 호출이 필요하지 않다.

최종추적표와JSON/사람이읽는보고서를같은판정으로갱신한다. 필수조건미수행은완료기준과분리하고실측가능한항목만통과처리한다. 사용자직접피드백은270의대기로유지한다.
