## 호출 제어 시험 방법

표식이 있는 비primary 시험 DB와 Mock/가짜 SDK 전송만 사용한다. 키를 넣지 않고 실제 외부 모델에 요청하지 않는다. 원장과 현재 권한은 실제PG/보호 함수로 검증한다.

- 일반 생성은 실제 run 접수/claim→예약→dispatch→Mock→정산→저장 흐름을 사용한다.
- 문서 임베딩은 실제 업로드/Job/claim→배치 permit→dispatch→정산/checkpoint 흐름을 사용한다.
- 질의 임베딩과RAG 생성은 게시된 합성 자료를 실제 ACL로 검색하는 run에서 각각 앞 단계와 다음 단계의 중지 경계를 확인한다.
- 중지는 현재 권한을 가진 관리자 API 또는 기존 보호 제어 함수로 적용한다. 이미 발사된 작업의 비용을 지우지 않으며 동일 요청 재전송·재개·재시작으로 자동 새 발사가 생기지 않는지 확인한다.
- 양순서가 있는 새 경계는 양순서×3회 반복한다. 한도+1은 거부 상태뿐 아니라 실제 provider 호출 수와 독립 counter를 대조한다.

시험 전후 primary의 키·기본mock/RAG비활성·원장·한도·자료와 이전 증거를 보존한다. 강제 완료/원장 수정용 시험 API를 제품에 추가하지 않는다. SQL 정책을 변경해야 하는 결함이면 기존 migration을 고치지 않고 변경 원인·영향·새 migration 필요성을 먼저 구체화한다.

## 보호 정보와 정확한 입력 판정

등록된 실제 비밀값의 정적 검사와 별개로, 서로 다른 조직·개인 자료에 식별 가능한 합성 보호 표식을 넣는다. 비허용 직접ID 조회·과거 답변·원문·운영 Job·usage·오류/로그에서 해당 표식이 나오지 않는지 확인한다. 실제 키 원문을 보고서/로그에 기록하지 않는다.

DUAL-ADM의 A→B 전환 중 늦은 A 설정 응답은 실제 브라우저 요청 지연으로 재현한다. 이전 조직 응답 때문에 B의 폼/권한/저장 대상이 바뀌지 않아야 한다. RAG 실패는 저장 상태와 현재 Agent를 함께 확인해 허위 완료나 자동 일반Agent 전환이 없는지 검증한다.

취소/완료의 명시 선후 순서는1차에서 확인했다. 진짜 두connection 동시CAS·timeout/중지 중retry 조합과 세션 회수/로그아웃 뒤 Job의 현재 주체 권한·origin session 계약은 설계와 실제 SQL을 먼저 대조하고 빠진 동작을 시험한다. 기존 검증을 모두 수행한 것으로 가정하지 않는다.

각 상세 입력에는 actor/조직/mode·실존 자원·기대·실제 관측·caseID·제품/시험SHA·판정 이유를 붙인다. 보수적인 not_run 중 기존 시험의 정확한 입력 증거가 확인되면 pass로 갱신한다. 단순 이름 유사성으로 판정하지 않는다.

## 실제 실행과 이행의 선행 조건

기존 A대표 실배정500원/내부기발생0.19원·예약/unknown/slot0을 보존한다. B실배정·real색인·통제된 실행 프로필과 설계의 차이를 해결하기 전에는 실제RAG를 수행하지 않는다. 키 등록은 실제 호출 권한 성공 증거가 아니다.

기존 총대표배정500원 안의 A/B 배정안·원장/기간 동일성·mode별index/source-store·종료 시 defaultmock 복구를 문서로 구체화한다. 새DB/새500원/사용0초기화로 우회하지 않는다. 실제 호출 직전 공식 가격·현재usage·권한·기간·배정을 다시 확인한다. 기존 예약16.96/최대37.96원 예시는 청구액이 아니다.

이 단위가 끝나면 실제 실행 계획과280 최종판정/290 인계를 구체화한다. 새 환경 설치/복원과 사용자 직접 시연 피드백은 별도 증거가 필요하다.
