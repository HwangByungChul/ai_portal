# 삭제 문서 정리 작업 보완 결과

정상 삭제 요청으로 접수된 정리 Job은 로그아웃·세션 만료·유휴 만료 후에도 복구한다. 현재 계정·조직·소속·관리 권한, 삭제된 문서와 삭제 revision, 저장된 주체·Job·mode·lease·세대·증명을 검사한다. API 로그인 조건과 본문 RLS는 유지한다. 정리 과정에는 AI 호출이 없다. 이번 단위만 완료했고 전체 T280은 진행 중이다.

## 실제 검증 결과

- 변경 전 실제 삭제·로그아웃 입력 1건에서 중단을 재현했다.
- 신규 39건: 세션 경계9, 권한 회수10, 실행 역할2, 작업 증명11, 실제 서버 복구6, 두 DB 연결의 동시 claim1.
- 관련 서버 371건 통과, 실패 0건. 18개 모듈 회귀와 최종 정리/관측 모듈 재시험을 대조해 중복을 제외했다. 동시 claim의 세대 기대값 보정은 해당 입력을3회 재시험했다. 중간 실패는 증거에 남겼다.
- 화면 빌드와 브라우저 64건 통과. 이전 전체 서버856건은 역사 증거이며 이번 전체 서버 재실행으로 표시하지 않는다.

실제 HTTP 접수·삭제와 동일 DB의 재시작에서 정상 대기 및 DB 본문 정리 후 파일 제거 실패 상태를 복구했다. 로그아웃/만료 이후 API 401을 유지하고 새 로그인에서는 완료 상태를 조회했다. 두 번째 재시작에서 Job·원장·파일 상태를 보존했다. 두 연결의 동시 claim에서는 유효 lease 하나만 생성됐다. 이는 취소/완료 경합 시험과 다르다.

권한 회수 시험은 합성 fixture에서 회수 시점을 제어했다. 각 단계와 파일 제거 전에 현재 권한을 확인하며 DB와 파일 전체가 하나의 원자적 트랜잭션인 것은 아니다. 본문 삭제 뒤 권한이 회수돼도 삭제된 본문을 복원하지 않는다. 파일 실패는 완료로 승격하지 않고 복구 가능한 상태로 남긴다.
