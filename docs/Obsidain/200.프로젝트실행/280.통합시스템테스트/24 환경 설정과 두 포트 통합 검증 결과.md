## 발견·수정

정적 시험 이후 실제 개발 서비스 복구 확인에서 `/manage/admin` HTTP404를 발견했다. Vite admin base(`/manage/`)에 대해 HTML rewrite를 root `/apps/...`로 처리한 것이 원인이었다. 선택된 base를 포함하여 rewrite한 뒤 개발 모드 포트4를 추가 실행했고 최종 서비스에서 HTTP200과 정확한 관리자 main entry를 확인했다. 처음의 복구 검사를 성공으로 표시하지 않는다.

기존 U12_05는 같은 출처 BroadcastChannel 즉시 logout 가정이었으므로 실제 다른 포트의 관리 탭으로 바꾸고 server session 폐기 후 reload에서 login을 검증했다. 이 수정은 서버 세션 무효화를 완화하지 않는다. U13은 invalid origin/CSRF 후 세션 유지, logout 후 다른 포트 auth/me401과 UI 재인증을 함께 검증한다. Playwright 기본 fixture 서비스에 admin5174를 포함했다.

## 증거·보호 범위

[[200.프로젝트실행/280.통합시스템테스트/evidence/UI13-environments/verification-summary.json]]과 `source-manifest.json`, `build-manifest.json`, `ports-and-home-10.json`, `sites-regression-7.json`, `development-ports-4.json`, `prd-build-rejection.json`, `service-health.json`, 세 `*-cleanup.json`을 저장했다. test ID/상태/시간·공개 URL·SHA만 기록하고 비밀번호/키/DSN/CSRF/질문·문서·기본 지시문은 포함하지 않는다. 실패의 민감 진단과 화면은 private runtime에 유지한다.

소스 SHA는 실제 프로젝트 파일을 대조한다. 각 apply는 변경 전 SHA와 백업을 보존했다. 해당 단계 migration 변경0·기존 주 DB reset0·유료 모델 호출0. 브라우저/DB 시험은 합성 계정·폐기용 fixture·mock으로 수행하며 cleanup의 fixture/비밀/소유 source 제거와 pool0을 확인했다. 서버 복구는 기존 소유 스크립트로 수행하고 다른 프로세스를 종료하지 않았다.

최종 user JS299.54kB/gzip90.09, admin295.26kB/gzip88.68, 공통 CSS20.16kB/gzip4.96. 외부 환경 성능·보안·SSO·CI/운영 배포 수용 시험은 미수행이다. 다음 작업은 [[100.프로젝트계획/12 사용자 관리자 사이트 분리와 상용 이행 설계]]의 인증과 운영 profile 단계다.
