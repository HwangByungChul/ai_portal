# 다음 단위 — 문서 Job의 로그아웃 독립성과 현재 권한

입력은 [[06 모델 호출 제어 통합 검증 결과]], 승인된 240.02/04·AI-07·REQ-08, 최신 검증표와 `contract-gap.json`이다. 설계 불일치를 먼저 보완하고, 현재 권한·회수·비용·재시작을 검증한 뒤 잔여 입력 판정을 이어간다. 전체 280단계는 진행 중이며 290단계는 미착수다.

## 상세 작업 순서

| 순서 | 예상 배정 | 수행 내용 | 완료 증거 |
|---|---:|---|---|
| 1 | 20분 | Job 접수·claim·guard·대기 작업 복구·본문 RLS에서 원래 로그인 세션을 사용하는 지점을 대조한다. 로그아웃 전/후 claim, 진행 중 로그아웃, 세션 만료와 유휴 만료를 분리한다. | 채팅의 세션 검사와 문서 Job의 작업 승인·lease를 구분한 변경 목록 |
| 2 | 60분 | 소유한 Mock 시험 DB에 정상 문서 Job을 접수하고 실제 로그아웃 API로 재현한다. 백그라운드 작업의 현재 주체 권한 검사와 승인 계약을 보완한다. | 로그아웃만으로 Job 삭제·자동 취소 없음. 계정/소속/역할·개인 ACL·문서 삭제·Agent 중지 시 신규 호출과 공개 거부 |
| 3 | 40분 | 같은 DB와 Job·색인·원장·기간을 사용해 실제 서버 재시작을 검증한다. 복구에서도 현재 작업 주체의 권한을 검사한다. | 중복 접수 0, 미발사만 해제, 기발생 비용 보존, 불명 호출 자동 재발사 0. 필요한 두 순서를 세 번 반복 |
| 4 | 30분 | 두 DB 연결의 실제 취소/완료 경합과 timeout·중지 중 재시도에서 부족한 입력만 추가한다. 중지·한도 축소·재개 조합을 대조한다. | 최종 상태 하나, 실제 호출·call·정산 수 일치. 명시 선후 순서 시험과 동시 경합을 구분 |
| 5 | 30분 | HTTP request-ID→run/Job의 첫 연결을 확인한다. 개인/다른 조직의 제목·본문·Job·사용량·예외 표식과 늦은 응답, RAG 실패 후 Agent 상태를 대조한다. | 보호 내용 노출 0, 자동 일반 Agent 전환 없음. 입력별 관측·시험 ID·소스 SHA·판정 이유 |
| 6 | 20분 | 상세60·ACL16의 정확한 입력과 실제 모델 검증 조건을 갱신한다. | pass/fail/not_run과 근거를 분리한 검증표. 미완료를 전체 완료로 승격하지 않음 |

예상 3시간20분은 기존 T280의 6시간 안에서 재배정할 검토안이며 80시간에 새 공수를 더하지 않는다. 개인 실제 시간이 미측정이므로 일정 달성을 확정하지 않는다. 범위가 초과하면 기존 여유 10시간과 10/31 목표 안에서 남은 일정을 재산정한다.

## 구현 원칙과 검증 범위

SQL 변경이 필요하면 기존 000~017을 수정하지 않고 새 변경 파일로 추가한다. 본문 RLS/FORCE RLS, 관리자와 개인 본문 권한의 분리, 최신 계정·소속·역할·문서·Agent 권한, 저장된 Job 승인·lease·세대 검사를 유지한다.

문서 Job의 origin session은 감사 참조로 남긴다. 채팅은 원래 세션을 신규 단계와 본문 공개 조건으로 유지한다. 로그아웃 독립성을 구현하기 위해 현재 주체 권한 검사를 삭제하지 않는다. 강제 완료·원장 조작·시험 API를 제품에 추가하지 않는다.

## 이후 실제 실행 준비와 인계

기존 persistent DB, 대표 총배정 500원, A 기발생 내부 추정액 0.19원, 기존 기간과 원장을 보존하면서 A/B 배정안을 같은 총액 안에서 정한다. B 실배정, real 색인과 자료 저장 분리, 키의 호출 권한, 공식 현재 가격과 사용량을 확인하기 전 실제 RAG를 수행하지 않는다.

새 DB·새 500원 배정·사용액 초기화로 준비 조건을 우회하지 않는다. 종료 시 기본 Mock과 RAG 비활성 복구를 포함한다. 실제 모델 검증, 새 환경 설치·복원, 사용자 직접 피드백은 각각 별도 증거가 필요하다.
