# 다음 작업 상세 계획

입력은 [[08 문서 색인 Job 권한 통합 검증 결과]], 기존 240 설계·AI-07·REQ-08과 최신 검증표다. 색인 계약 보완을 정리 Job이나 전체 T280의 완료로 확대하지 않는다.

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| 1 | 삭제 후 정리 Job의 접수 권한·현재 주체·문서 삭제 상태·서비스 작업 승인 계약을 대조한다. 로그아웃/만료가 정리를 멈추는 경계를 실제 HTTP로 재현하고 필요한 새 migration과 worker 변경을 검토·보완한다. | 실제 삭제 문서의 정리만 허용, 다른 조직/Job 위조 차단, API 로그인 유지. 같은 DB 재시작에서 중복 정리·원장 손상 없음 |
| 2 | 두 DB 연결에서 취소/완료를 경합시키고 timeout·중지·재시도·한도 축소·재개 입력 중 부족한 조합을 추가한다. | 최종 상태 하나, 실제 호출·call·정산 일치. 선후 순서 시험과 실제 동시 경합을 구분 |
| 3 | 실제 HTTP request-ID→run/Job 첫 연결, 개인/타 조직 제목·본문·Job·사용량·예외·로그의 보호 표식, 늦은 응답을 확인한다. RAG 실패 이후 Agent 상태도 대조한다. | 보호 표식 노출0, 자동 일반 Agent 전환0. 입력·시험 ID·현재 소스 SHA와 관측을 기록 |
| 4 | 상세60·ACL16과 V-001~041 하위 입력을 하나씩 대조한다. 현재 통과·실패·미실행과 이유를 갱신한다. | 회귀 통과만으로 미검증 조합을 승격하지 않고 증거가 있는 정확한 입력만 판정 |
| 5 | 위 결과를 기반으로 실제 모델 실행 준비를 점검한다. 기존 DB·기간·대표 총액500원·A 사용액0.19원을 보존하고 A/B 배정, real 색인/자료 저장 분리, 키 권한, 공식 현재 가격/사용량을 확인한다. | 준비 조건 충족 후 최소 비용 시험. 새 DB/예산 초기화로 우회하지 않고 종료 시 Mock/RAG 비활성 복구 |

다음 실행 단위는 1번 정리 Job 계약이다. 변경 전 재현→보완→권한/격리/재시작 회귀→보존 확인→단계 산출물 순서로 수행한다. 2~5번은 그 결과와 정확한 잔여 입력에 따라 이어간다. 소유한 합성 시험 DB를 사용하고 실제 문서나 비공개 원문을 산출물에 넣지 않는다.

공수는 기존 T280 6시간과 전체 80시간 안에서 재배정한다. 개인 실제 투입 시간이 미측정이므로 새 예상치로 달성을 확정하지 않는다. 10/31 목표와 기존 여유10시간을 유지하며 초과 예상 시 범위와 일정 변경안을 보고한다. 290 설치·복원과 300 완료보고는 전체 검증 조건을 확인한 뒤 진행한다.
