## 실패 및 수정 이력

초기 일반 USER 게시 읽기는 SELECT FOR SHARE가 UPDATE RLS를 요구하여404였다. 사용자 UPDATE 정책을 넓히지 않고 공유 advisory lock과 게시/철회 exclusive lock을 짝지어 해결했다. 사용자 admission audit는 기존 관리 scope만 허용하여 실패했으므로 정확한 본인 published run과 admission action만 허용하는 좁은 INSERT 정책을 추가했다. 이전 SQL000~035는 수정하지 않았다.

시험 코드의 usage_events에 없는 run_id 조회를 call_id JOIN + settle event로 수정했다. heartbeat는 기존 정책상 p_config=false이므로 고정 정책 변경 검사는 reserve/dispatch/finish에서 검증하도록 기대를 수정했다. 수정 중 SQL 문자열 인용 오류로 한 번 collection 실패한 이력도 있다. 자료 삭제 후 시험 cleanup의 지원하지 않는 DOCUMENT_UNAVAILABLE fail code는 EXECUTION_BLOCKED로 정정했다. worker의 current publication/source AppError401/403/404/409도 안전한 EXECUTION_BLOCKED로 정규화하여 실행이 실패 상태로 종료하도록 했다.

회귀 실행165 중 취소/철회2는 worker 시작 전 accepted 실행을 만들었기 때문에 시작 recovery가 이를 interrupted 처리하여 provider 대기가 timeout됐다(기존 정상 복구 정책). 테스트를 leadership 취득 후 새 admission하도록 수정했다. 나머지163은 통과, 최종 신규22가 모두 통과하여 기존144+신규22 최신166이다. 실패를 지우거나 전체 suite 단일166pass로 표현하지 않는다. 최종 source에 맞춘 SQL/동시성 검증과 브라우저27·빌드는 재실행했다.

## 검증 한계

실제 외부 모델/Entra/기관 업무 품질/상용 DB·운영 배포는 미검증이다. 중지/예산/재시작 중앙 실행 경로는 기존 회귀로 확인했으며 모든 dynamic-specific native crash/부서 이동/네트워크 중단 경계를 검증했다는 의미가 아니다. 개인 자동조건/모의 pass를 의미적 품질 검증으로 확대하지 않는다. 신규 표에 primary 합성 업무를 넣지 않았다. 미완료/다음 범위는 [[33 DP12 동적 Agent 승인 게시와 사용자 실행 구현 결과]]에 보존한다.
