# 다음 실행 단위 — 취소 경합과 부족한 실패 입력

입력은 [[10 문서 정리 Job 권한 통합 검증 결과]], 기존 AI-07·REQ-08·상세60·ACL16과 최신 검증표다. 이번 정리 claim의 동시성 증거를 취소/완료 경합의 증거로 사용하지 않는다.

| 순서 | 상세 작업 | 완료 기준 |
|---|---|---|
| 1 | 기존 취소/완료 전이와 원장 기록을 대조한다. 두 독립 DB 연결에서 실제 완료와 취소를 경합시키고 각 선행 순서를 별도로 시험한다. | 최종 상태 하나, 중복 정산0, 기발사 호출 비용 보존. 동시 경합/선후 순서를 구분한 입력·관측 |
| 2 | timeout 이후 중지·재시도, 한도 축소 후 재개, 사용량 불명 호출에서 정확히 부족한 입력만 추가한다. | 새 호출 허용/차단 수, call·원장·slot 상태 일치. 불명 호출 자동 재발사0 |
| 3 | 실제 HTTP request-ID→run/Job 첫 연결을 확인하고 개인/타 조직 제목·본문·Job·사용량·예외·로그 보호 표식과 늦은 응답을 대조한다. | 보호 표식 노출0, 추적 연결 보존, RAG 실패 후 일반 Agent 자동 전환0 |
| 4 | 상세60·ACL16·V-001~041 하위 입력을 증거별로 판정한다. | 정확한 입력의 pass/fail/not_run과 이유. 관련 회귀 수만으로 전체 승격하지 않음 |
| 5 | 기존 persistent DB/기간/총액500원/A 내부 추정0.19원을 보존하면서 실제 실행 준비를 확인한다. | A/B 배정·real 색인/자료 분리·키 권한·공식 현재 가격/사용량 확인 뒤 최소 비용 시험. 종료 시 Mock/RAG 비활성 |

다음은 1~2번의 독립 실행 단위다. 변경 전 부족한 증거 확인→필요한 보완→권한/비용 회귀→같은 DB 보존 확인→산출물 순서로 진행한다. 3~5번은 이어지는 단위로 유지하며 실행하지 않은 입력은 미실행으로 기록한다. 새 DB/새 예산/사용액 초기화로 준비 조건을 우회하지 않는다.

기존 T280 6시간·전체80시간 안에서 공수를 재배정하고 여유10시간/10월31일 목표를 유지한다. 개인 실측 공수는 미측정이므로 일정 달성을 확정하지 않는다. 초과 예상 시 범위·일정 변경안을 보고한다. 290 설치·복원과 300 완료보고는 별도 완료 증거가 필요하다.
