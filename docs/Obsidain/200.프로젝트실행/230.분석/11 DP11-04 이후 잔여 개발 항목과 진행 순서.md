# 남은 개발 항목과 진행 순서

사용자 “남아 있는 작업들이 무엇이 있나요?” 요청에 대한 최신 계획·구현 기록 기준 정리다. 근거는 [[15 전체 기능명세서 잔여 기능 개발 실행 계획]], [[30 DP11-04 시험 이력 수동 평가와 버전 비교 구현 결과]], [[31 DP11-04 시험 증적 권한 평가 불변성과 비교 검증]]이다. 이번에는 코드 변경/새 테스트/전체 기능명세 재감사를 수행하지 않았다. 이전 부분 구현을 전체 완료로 환산하거나 기존 F 완료 집계를 새 비율로 제시하지 않는다.

## 현재 구현된 범위

초안·불변 버전 저장, 구조화 시스템/개발자/사용자 프롬프트, 변수 조합 검증, 저장 버전 복제, 명시 자료 범위, 일반 모델/RAG 검색·생성 시험, 시험 정산·취소·동일 요청 복구, 본인 시험 이력·수동 평가·두 시험 비교는 실제 앱 구현과 모의 검증이 있다. 고정 운영 Agent 카탈로그/즐겨찾기·이용 대상과 기존 고정 설정 승인도 구현되어 있다. 신규 동적 Agent의 운영 승인·게시·사용자 실행은 아직 연결되지 않았다.

## 실제 환경 검증·보류

Microsoft Entra ID 실제 SSO·사이트별 세션 검증, 실제 모델 제공자 품질/비용, 업무 자료·업무 전문가 평가, 기관 시스템/DRM/DLP/망 연동, 운영 DB·TLS·관제·백업복원·부하·최종 UAT는 별도 실제 환경 검증으로 남는다. local/dev/tb/prd 설정과 사용자/관리자 포트 분리 자체는 이미 구현했다. 도메인 미정은 위 기능 개발을 막는 조건이 아니다. 운영 배포 실행은 이번 요청 범위가 아니다.

기존 제외 F050~060 거버넌스와 최초 오픈 제외 T5는 별도 결정 전 포함하지 않는다. PPTX/OCR은 사용자 보류 상태를 유지한다.

다음 순서: DP11 평가셋 → 승인 증적 계약 → DP12 동적 승인·게시 → DP13 모델 관리 → 역할·보호 정책/연계/Workflow/업무 Agent 및 사용자·운영 확장. 범위와 순서는 착수 시 최신 코드로 상세화하고 의미 있는 개발 단위마다 Obsidian 기록을 계속 갱신한다.
