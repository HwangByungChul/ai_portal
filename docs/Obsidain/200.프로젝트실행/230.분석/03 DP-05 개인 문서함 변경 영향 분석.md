# DP-05 개인 문서함 변경 영향 분석

## 현재 구조와 변경 이유

기존 DocumentRepository의 등록·접수 제한·삭제·작업 조회와 백그라운드 작업 주체 검증이 관리자 권한을 요구한다. 개인 문서 읽기는 이미 소유자/게시 상태/현재 조직을 검증한다. 관리자 검사를 일반 사용자 검사로 일괄 완화하면 기존 조직 문서 작업까지 허용하므로 별도 사용자 경로가 필요하다.

## 영향과 대응

- document_access에 user_owned 불변 구분을 추가한다. 기존 행은 false로 유지한다. 신규 개인 업로드만 true이며 private·등록자 소유·독자 지정 없음으로 고정한다.
- 사용자 고정 DB 함수는 run_authorize와 현재 조직의 소유권을 검증한다. 관리자 고정 함수는 기존대로 유지한다.
- 백그라운드 색인/게시/복구/삭제 정리는 관리자 조건에 해당 작업 대상의 user_owned·private·소유자 일치 조건을 추가한다. 일반 사용자에게 ai_index 로그인·원문 제어 권한은 제공하지 않는다.
- 기존 GET /documents는 게시된 읽기 자료를 제공하므로 보존한다. 개인 관리 목록은 GET /documents/mine, 개인 작업 목록/상태는 /document-jobs로 분리한다. 별도 서명 커서 영역으로 관리자 커서 재사용을 차단한다.
- 사용자 접수도 기존 파일 저장·해시·파서·색인 계획·요금 제한·호출 원장·현재 자료 권한 검증을 사용한다. 등록/삭제 감사에는 식별자와 상태만 기록한다.
- 현재 읽기 가능한 게시 버전의 질문 첨부와 기존 RAG 답변/근거/평가 접근 차단을 재사용하고 삭제 전후 회귀로 확인한다.

실 모델 호출과 운영 배포는 수행하지 않는다. 새 마이그레이션 023만 추가하고 000~022는 변경하지 않는다. 기존 DB 원본 열/행의 전후 해시를 비교한다.
