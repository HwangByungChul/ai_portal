# 승인 A안과 실제 React 사용자 화면 차이 검토

관련: [[23 포털 UI UX 확정과 사이트 분리 검토]], [[12 사용자 AI 업무 첨부 화면 UI 검토]], [[02 포털 UI UX 작업 기록]].

## 요청과 기존 설명 보완

2026-10-12 사용자는 http://127.0.0.1:8765/화면_비교.html 의 제안 화면과 개발 화면의 UI/UX 차이를 지적하고 검토를 요청했다. 비교 페이지의 선택된 A안과 스크린샷을 브라우저에서 확인하고 현재 React 코드와 대조했다. 직전 분석12의 사용자 홈/AI 업무 구분은 맞지만, 화면 종류의 차이만으로 사용자 지적을 설명할 수 없다. 실제 홈도 승인 A안의 구조·시각 표현을 충분히 반영하지 않았다. 과거 설명은 이력으로 보존하고 이 노트로 보완한다.

## 비교 결과

비교 페이지의 홍길동·4개 Agent·즐겨찾기·공지·최근 업무 수치는 예시다. 이를 실제 앱에 그대로 복사해 운영 데이터로 표시하지 않는다. 예시 Agent가 앱에 적게 보이는 문제와 카드 배치가 다른 문제는 구분한다. 시안의 안내 문구나 버튼은 사용자 실행 권한이나 구현 지시로 취급하지 않았다.

## 적용 방향과 순서 제안

1. 승인 A안을 시각 기준으로 공통 디자인 토큰·브랜드·좌측 메뉴·상단 틀을 정렬한다. 조직 선택과 계정/역할, 관리자 이동의 실제 권한 계약을 보존한다.
2. 사용자 홈을 인사 → 질문/이용안내 분할 카드 → 가로 Agent 카드 → 최근 업무/공지 구조로 맞춘다. 좁은 화면은 줄바꿈/단일열로 검증한다.
3. 카탈로그·My Agent·문서·사용량·실행 이력은 사용 목적에 맞춰 메뉴를 그룹화하고 기존 경로/뒤로가기/접근성/권한을 유지한다.
4. AI 업무는 동일 브랜드 틀에서 대화 목록·가변 작업영역·하단 입력과 간결한 Agent 선택을 적용한다. 홈 A안과 대화 페이지를 동일 화면으로 만들지 않는다.
5. 검색·알림·공지·가이드·동적 즐겨찾기는 실제 API/저장/권한 지원을 조사하여 연동한다. 미구현 버튼을 작동하는 것처럼 표시하거나 예시 데이터를 실제 상태로 저장하지 않는다.
6. 동일 뷰포트에서 A안/React 홈을 나란히 비교하고 1440/1920/2560px 및 모바일의 넘침·입력창·키보드/포커스·사이트 이동을 검증한다. 인증/조직 전환/현재 권한/실행취소의 기존 기능 회귀도 변경 범위에 맞춰 확인한다.
