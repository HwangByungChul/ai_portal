## 요청·범위·결론

사용자가 상세 수정 계획 개발을 완료했고 추가 개발도 있으므로 확인·검토하도록 요청했다. 계획26, 최신 작업로그의T1~T8/듀얼UI 주장과 실제 현재 소스를 대조했다. 기존 미커밋 여러 작업이 섞여 있으므로 git diff 전체를 새 작업으로 취급하지 않았다.

인증/CSRF 호출, effective_role 수정, 정책 DB와 Overview RPC, 도구 strict 일부검사/어댑터분리, Workflow provider 호출, 사용자·관리자 시각 분리 등 추가 구현을 확인했다. 그러나 계획의 핵심 운영 계약은 일부 미연결이고 실제 경로에서 재현되는 문제가 있어 상세 계획 전체 수정 완료로 인정할 수 없다. 기존 작업자의 검증 기록을 삭제하지 않고 이번 독립 검증을 구분해 보완한다.

## 우선 발견 사항과 재현

### F1 · P1 실제 stream 원문 유출 경로 잔존

`src/backend/app/ai/gateway.py:52`는provider에on_delta를직접전달한다. `execution/manager.py:82`는검사전hub.append를호출한다. 최종body검사는나중에마스킹하므로초기원문은회수할수없다.

독립재현: 실제AiGateway.execute에 합성전화문장을반환/stream하는spy provider, reserve/dispatch대역, meter대역을사용했다. 결과는raw_stream_before_inspection=true, final_body_masked=true. 실DB/네트워크/유료모델호출0이고 실제개인정보가아닌합성문자열을사용했으며 보고서/출력에원문을저장하지않았다.

`test_remediation_output_gate.py`는실제Gateway를실행하지않고시험내부collector를provider에넣는다. received_from_hub는소비자연결없이빈배열상태라검증이실서비스배선을보장하지않는다. Gateway→manager→SSE/메시지경로를검사하는수용시험으로교체해야한다.

### F2 · P1 real 모드라도 운영 라우터가 mock

`execution/manager.py:10`는router가없으면GLOBAL_ROUTER를사용하고`main.py`의manager생성에서mode/keyresolver를담은router를전달하지않는다. GLOBAL_ROUTER는execution_mode='mock'다.

독립재현: ExecutionManager(None,spy_provider,'real',None)의manager.mode는real인데gateway.router.mode는mock, gpt-4o요청의provider는MockProvider였다. 새Router단위시험4개가통과해도운영조립은해결되지않는다. `ai/providers.py`의OpenAI실제요청도gpt-4o-mini고정이므로선택모델/가격계약은추가보완해야한다. 실제OpenAI호출은하지않았다.

### F3 · P1 DB 정책/감사와 검사 엔진 단절

관리API는GuardrailRepository로정책을읽고저장하지만`guardrails/engine.py:141`의_CURRENT_POLICY를입출력evaluate가읽는다. 실행Gateway와conversations는`guardrails.routes.record_violation`의메모리_VIOLATIONS를기록한다. 새DBaudit조회가보여주는표에실제위반이자동적재되는연결이없다.

따라서관리화면의output_pii_action변경이실행에적용된다고확인할수없고재시작/worker일관성도아직미완료다. 저장정책→현재조직effectivepolicy→검사revision→DBaudit의일체화를수정해야한다. 이번실DB정책수정/재시작은하지않았다.

### F4 · P1 도구의 멱등/조직 실행 계약 미완료

`tools/registry.py:95/137`캐시는client_request_id→args_hash만기억하고동일ID동일args이면handler를또호출한다. 조직/사용자/tool_id가key에없고receipt를영속저장하지않는다. HTTP에서client_request_id도선택사항이다. routes의ctx를registry로전달하지않아로그인후도구별조직권한검사가없다.

독립재현: 새ToolRegistry에counter handler를넣고동일client_request_id/args로2번호출하면handler count=2. 다음수정은조직·사용자·tool·body지문을봉인한영속receipt/permit/CAS와현재권한검사다. strict검사도현재required/extra/enum중심으로JSON schema type/길이전체를검증하지않으므로strict완료로인정하지않는다.

### F5 · P1 Workflow/표준 Agent 운영 경로 미완료와 추가 출력문제

`workflows/routes.py`는로그인된사용자의클라이언트전체DAG를운영실행하며버전ID/currentpublication/제작자역할로제한하지않는다. `runner.py:58`의SimpleNamespace(call_id)는기존confirmeddispatch가아니며provider를Gateway/예산/정산/현재자료/policy밖에서직접호출한다. checkpoint는메모리리스트이며`runner.py:72`의context_snapshot과checkpoint.output이원시입력을그대로회신한다. 예외str도클라이언트에전달된다.

독립재현: input→output Workflow에합성전화문장을넣었을때returned checkpoint/context에원문이포함됐다. 실제PII/기관자료는사용하지않았다. 이는새로붙인Workflow provider호출과함께중앙출력검사를우회하는문제다.

`use_cases/routes.py:87`은여전히Deterministic Output Generation으로문자열을조합하고tool오류를except Exception:pass로삼킨다. 승인asset/version/실제model/run/취소/정산으로연결되지않았으므로10종실업무Agent완료는아니다. 정적tool fixture의기관데이터를real로표시하지않도록모드/어댑터주입도필요하다.

### F6 · P2 Overview와 공통 헤더의 거짓 정상 표시

043 SQL은AI Gateway/Guardrail서비스에관측없이observed_ok와현재시각을매번생성한다. DB읽기성공으로추론서비스/정책엔진의정상까지입증하지못한다. `operations/overview.py:54`는pool없음에집계0과observed_ok를반환한다. 데이터없음과실측0을혼동한다.

`packages/ui/src/TenantHeader.tsx:31`의관제시스템정상과PortalShell하단상태도하드코딩이다. 정직한unknown/관측시각/TTL/실제health자료로바꿔야한다. 기간검사는diff>31이므로양끝포함32일을허용하고today/SQL일경계의Asia/Seoul일치도재검증해야한다. 단순API이동만으로R7이해결된것은아니다.

### F7 · P2 동적 승인 상세 진입 연결 누락

AdminHomePage는onApprovals(request_id,kind)를호출하지만실제독립관리앱`apps/admin-web/src/App.tsx:22`는id만받아유형을버리고ApprovalsPage는settings를기본으로한다. 호환src/App.tsx도kind인자를선언했으나사용하지않는다. 동적요청UUID로운영설정상세를조회하게되어올바른상세에진입하지못한다.

실제apps/admin-web→kind+id→ApprovalsPage/AssetDeploymentsinitial선택전체를연결하고최소동적1건과고정1건을홈에서선택하는브라우저시험이필요하다. 이번에는실제승인/게시/fixture작성이나클릭은하지않았다.

### F8 · P2 추가 UI의 동작/근거 일치 검증 미완료

화이트사용자/다크관리자·SVG메뉴·분할입력/가이드·카드영역개편코드를확인했다. 다만통합검색은readOnly이며Ctrl+K힌트의실제동작은확인되지않았다. 현재페이지와상관없는고정브레드크럼·상태문구도실제탐색과맞춰야한다. 이턴에는로그인된동일뷰포트/모바일스크린샷재검증을수행하지않았으므로100%시안일치/1초역할구분같은정량표현을독립확인한것으로기록하지않는다.
