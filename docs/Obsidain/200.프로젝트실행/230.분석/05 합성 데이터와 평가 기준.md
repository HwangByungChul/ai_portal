## 개체·관계·근거의 판정 기준

A의 D-A-R1/R2는 동일 개체 A:process:loan-review를 사용하고 담당/위험 승인/기록 보관 관계를 서로 다른 R/EV에 연결한다. B의 같은 업무 이름은 B:process:loan-review로 별도다. 공유 D-S는 A 소유 개체를 유지하되 관계 ID와 EV를 버전별로 구분한다. 관계를 이름/개체만으로 합쳐 버전·문서 근거를 섞지 않는다.

원문 근거 18개와 정답 관계 16개를 선언했다. EV는 사람이 작성한 조항 위치이며 실제 chunk_id가 아니다. JSON에는 문서/버전·정확한 quote·원문 line_start/line_end·anchor·SHA를 기록했다. 파일 내용 변경 시 SHA/행/정답도 함께 다시 검증한다. 파서가 EV marker를 개체/업무 사실로 취급하지 않도록 240 색인 계약에 전달한다.

정답 relation별 evidence_ids는 해당 문서/버전의 실제 구절을 가리킨다. Q-007/008은 같은 업무의 승인/보관 근거를 반대로 인용하면 실패, Q-009는 두 문서의 서로 다른 책임을 각각 올바른 근거로 연결해야 한다. Q-010은 동일 업무 이름의 A/B 혼입을 판별한다. Q-011/012는 요청→접수 담당→확인 기한의 연쇄 관계와 버전별 차이를 판별한다. 단일 문서 요약을 관계 질문으로 세지 않고 관계/근거 연결을 별도 기대값으로 기록했다.

## 채점과 실제 실행 전달

- answer: 기대 핵심 사실을 모두 표현하고 각 사실/관계에 맞는 문서·버전·근거를 인용한다. 자연스러운 표현 차이는 허용하지만 모순/추정 책임자·임의 수치·근거 교차는 실패다. 자동 의미 판정/인용 형식은 240에서 설계한다.
- hold: 정상 허용 검색에서 답을 확인할 수 없음을 알리고 제약/추가 정보 요청을 설명한다. 검색 오류를 근거 부족 성공으로 숨기거나 무권한 자료 존재/제목을 언급하지 않는다.
- deny: 명시적 무권한 문서/근거 요청은 생성/질의 임베딩 전에 검사하여 내용 없이 거부한다. 정확한 HTTP 코드/오류 표현은 240 설계다. 일반 범위 질의의 근거 부족과 직접 자원 거부를 혼동하지 않는다.
- acl_allowed_evidence_ids는 읽을 수 있는 전체 corpus 범위다. required_evidence_ids는 그 질문의 정확한 정답 근거 부분집합이다. 읽기 허용이 질문 관련성/현재 선택 버전까지 보장하지 않는다.
- forbidden_evidence의 unauthorized는 모델 문맥과 모든 반환 경로에서 보호 제목/본문/관계/파일 노출 금지다. wrong_relation_or_selected_version은 읽을 수 있어도 그 질문의 답/인용으로 사용하는 것을 금지한다. 이 두 범위를 같은 ACL 거부로 처리하지 않는다.
- 누설 판정은 권한·문서 버전 출처와 보호된 고유 사실을 함께 확인한다. 같은 업무 이름 또는 허용 v1/미공유 v2의 동일 제목만으로 실패를 단정하지 않는다. B의 v1 제목 사용은 허용하되 미공유 v2의 존재·버전·고유 담당자/기한/복구 목표 노출은 실패다.
- 결과는 질문별 실제/모의·답변/근거·사용량·증거·통과/실패/미수행으로 기록한다. 현재 모든 결과는 not_run/null이며 제공자 비용 기록도 없다.

일반 Agent 실제 연결은 V-005로 별도 확인한다. Q20은 ACL16 및 V41의 직접 URL/ID·관리 승격·개인 공유/재공유·동시 Job/RLS/풀·중지/한도·취소/실패·재시작·설치/성능 시험을 대체하지 않는다. Q20의 일부 ACL 사례를 적었다고 전체 운영/보안 검증이 완료된 것은 아니다. 품질 목표/성능 수치/실제 실행 계획은 240/260/280에 연결한다.

## 정적 점검 결과와 한계

JSON 구문, 문서6/버전7/근거18/관계16/질문20 ID 중복, 분류6/6/4/4, 파일 SHA·조항 위치/quote, 관계→같은 문서/버전 근거 연결, 필수 근거⊆허용 근거 및 금지 근거와 비중복을 확인했다. 선언 권한 규칙 기준으로 B v1 허용/v2 금지/회수 후 v1 금지·타인 개인/관리자/비활성 거부 기대값을 대조했다. 이 대조는 fixture 일관성 확인이며 서비스/DB ACL 코드 시험이 아니다.

원본 GraphRAG/BNK 자료는 수정하지 않았다. 신규 앱 소스·실제 계정·DB·색인·API 키 설정/유료 호출은 없다. 실제 조항 분할/개체 추출/검색 품질은 아직 알 수 없으며 분석 명세를 자동 색인 결과로 쓰지 않는다. 230 종합 검토는 A230-05 후 수행한다.
