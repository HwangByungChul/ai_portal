## 선행 판단

DP-05 문서함과 제한된 DP-06 형식 지원은 이번 범위의 입력으로 사용할 수 있다. DP-07은 PPTX·OCR을 선행으로 요구하지 않는다. DP-18은 수집 정책만 구현되어 있어 전체 선행 완료로 처리할 수 없다. 요약 전용 입력/결과 검사·정책 revision 보존·검사 실패 차단을 P0로 구현하고 검증해야 요약 호출을 활성화한다. 조직별 정책 관리·일반 대화·Tool 정책은 별도 후속이다.

원문 근거 단위와 규정 typed fact는 다르다. 일반 문서를 규정형으로 강제하거나 모델이 새 사실을 작성한 뒤 인용을 붙이는 방식은 첫 묶음에 적용하지 않는다. 규정 GraphRAG와 summary의 완료 정책을 분리한다.

## DB·권한·비용 영향

기존 실행/비용 원장을 유지하고 요약 전용 task 구분·요청 snapshot·근거 레코드가 필요하다. 기존32개 테이블의 원래 열/행 값과SQL 000~024 파일 지문 보존을 비교한다. 새 열/테이블/함수만 허용하되 필요한 제약·함수 교체는 신규 migration에서 명시한다. 025는 이번 설계의 예약 번호이며 아직 migration 파일을 만들거나 적용하지 않았다.

요약 admission·worker claim·dispatch·finish·현재 조회·삭제/회수·export가 같은 task/source snapshot을 검증해야 한다. 기존 chat API로 summary 실행을 시작하거나 summary 결과를 일반 규정 답변으로 조회하는 우회도 시험한다. 신규 DB 권한은 전용 함수에 한정하며 웹/회계 역할에 전체 원문 권한을 추가하지 않는다.

등록 단계의 임베딩 비용은 이미 발생할 수 있다. ‘요약 임베딩0’은 새 요약 실행 자체만 뜻한다. 원문 한도·1회 생성·기존 cap을 유지하고 최신 단가를 추정하여 변경하지 않는다. 실모델 품질은 모의 시험과 구분한다.
