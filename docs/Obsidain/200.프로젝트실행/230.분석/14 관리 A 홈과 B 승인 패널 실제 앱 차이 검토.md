# 관리 A 홈과 B 승인 패널 실제 앱 차이 검토

관련: [[23 포털 UI UX 확정과 사이트 분리 검토]], [[13 승인 A안과 실제 React 사용자 화면 차이 검토]], [[02 포털 UI UX 작업 기록]].

## 요청·확정 기준·검증 방법

2026-10-12 사용자가 관리자 사이트도 제안과 실제 UI/UX 차이를 검토하도록 요청했다. 확정 기준은 관리 A 운영 현황을 기본 홈으로 하고 승인·검증에 관리 B 목록·상세를 적용하며 하나의 관리자 탐색 흐름을 유지하는 것이다. B 시안의 짙은 사이드바를 승인 페이지 이동마다 적용해야 한다는 결정은 없으므로 화면별 쉘 변경을 새 요구로 단정하지 않는다.

브라우저에서 http://127.0.0.1:8765/관리자_화면_비교.html 의 A/B 선택 상태·구조·스크린샷을 확인했다. 실제 http://127.0.0.1:5174/manage/admin 새 탭은 로그인 화면이었다. 이번 턴에는 로그인/계정·권한 변경·승인/철회/배포를 실행하지 않았으며 인증된 동일 뷰포트 실제 앱 화면 비교는 미완료다. 실제 차이는 현재 React 코드와 공통 CSS로 확인했다. 관리자 홈/승인 기능 전체 재시험이나 백엔드 전체 조사 결과로 확대하지 않는다.

## 관리 A 홈 비교

| 항목 | 승인 시안 | 현재 React | 판단 |
|---|---|---|---|
| 공통 틀 | 좌측 브랜드·아이콘/그룹 메뉴, 경로·알림·프로필 상단 | 공통 PortalShell의 전체너비 조직/역할 헤더·평면 텍스트 메뉴 | 사용자 A안과 함께 공통 틀 정렬 필요 |
| 조회 기준 | 기간/조직·조회 요약·집계 기준 시각 | 헤더 현재조직·usage.period·모드·새로고침 | 임의 조직 전체조회는 권한 계약에 따라 분리, 기간/집계시점 계약 조사 필요 |
| 운영 알림 | 상단 운영 이슈 요약·상세 이동 | usage.blocked 시 제한 알림 | 호출 제한과 서비스 장애/지연 알림은 다른 의미. 홈 모니터링 계약 미확인 |
| 지표 | 호출/비용/검토 요청/게시 자산 | 호출/추정 확인금액/예약금액/불명사용량 | 시안 지표 미정렬. 정산 불명과 예약을 삭제하거나 0원으로 바꾸면 안 됨 |
| 중간 | 호출 추이 + 우선 승인 요청 | 운영설정 배포 요청 + 관리 바로가기 | 추이 UI 없음, 실제 시계열 API 지원은 미확인 |
| 하단 | 공통 서비스 상태 + 최근 관리 이력 | 홈에 해당 섹션 없음 | 조직·플랫폼 권한별 데이터/API 확인 후 연동 필요 |
| 승인 진입 | 우선 확인할 요청 | /admin/agent-deployments?status=pending&limit=5 조회만 사용 | 동적 Agent 배포 요청은 이 홈 목록에 연결되어 있지 않음 |

현재 AdminHomePage.onAssets는 App에서 agents 경로를 열며 버튼도 Agent 설정 열기로 표시한다. 시안의 AI 자산 관리/게시 자산 진입과 목적이 다르므로 실제 자산 메뉴와 구분해 정렬해야 한다. 현재 정산 지표는 실제 안전 계약으로 유지하고 관리 A 주요 지표와 보조 정산 정보를 나눠 제안한다. 전체 조직 모니터링은 조직관리자에게 임의로 노출하지 않는다.

## 관리 B 승인·검증 비교

공통 .approval-layout은 minmax(250px,340px) 목록과 나머지 상세의 2열이고 좁은 화면은 1열이다. 기본 목록·상세 방향은 이미 적용되어 있어 모두 미구현으로 표현하지 않는다.

| 항목 | 시안 | 현재 코드 | 판단 |
|---|---|---|---|
| 상태 요약 | 대기/검토 중/반려 건수와 상태 탭 | 운영설정 상태 select, 증적/동적 요청은 별도 목록 | 상태·건수·검색 UX 통일 필요. 검토 중 상태를 프론트에서 임의 추가하지 않음 |
| 검색 | 요청명/담당조직 | 운영설정은 불러온 페이지의 이름/Agent/요청자ID만 필터 | 전체 검색과 다르며 이미 범위 안내 있음. 서버검색 필요 여부 조사 |
| 목록 정보 | 이름/요청자/조직/버전/접수시각/상태 | 운영설정 이름/기반버전/시각, 증적·동적은 버전/상태/UUID 일부 중심 | 최소 허용 표시정보 계약에 맞춰 이름·요청자 등 보강 필요 |
| 상세 | 요청 개요·요청자·버전·사용범위 + 검증/변경/이력 탭 | 운영설정은 3탭 적용, 증적·동적은 조건/JSON details/심사/게시이력을 긴 페이지에 표시 | 유형별 상세 정보 위계와 검증/변경/이력 표시를 통일할 필요 |
| 처리 | 검토 의견 동선 | 실제 의견·승인/반려 및 동적 품질/보안확인/게시철회·복원 연동 | 실제 기능은 보존하고 읽기/판단/최종액션 구획 정렬 |
| 홈→승인 | 요청에서 상세 이동 | 홈 initialId는 운영설정만, 동적 승인 유형은 기본 settings에서 별도 선택 | 유형+요청ID를 함께 전달하도록 개선 필요 |

동적 Agent의 정확한 버전·자료권한·증적지문·타인승인·CAS와 정산 보존은 디자인 정렬 시 유지한다. 개인 trial 질문/답변·기대문구는 시안과 맞추기 위해 타인에게 노출하지 않는다. 증적 제출과 승인/게시 완료를 같은 상태로 표시하지 않는다. 승인자 역할이 아닌 조직 관리자에게 승인 버튼을 임의 부여하지 않는다.

## 적용 순서 제안

1. 사용자·관리 공통 토큰/브랜드/간격을 정렬하고 관리자 메뉴를 운영/제작·자산/권한·정책 등 목적별로 그룹화한다. 미연결 모델·보안·감사·공지 화면을 완료로 표시하지 않는다.
2. 관리 A 홈의 지표/추이·승인/서비스·이력 배치를 복원한다. 구현/API 지원을 확인한 항목부터 실제 데이터를 연결하고 미지원은 확인 불가 상태를 명확히 한다.
3. 우선 운영설정과 동적 배포 대기 요청을 홈에서 구분해 진입하고 유형+ID로 올바른 상세를 연다. 건수는 불러온 5건을 전체 건수로 표시하지 않는다.
4. 세 요청 유형의 목록·검색·상태·상세 요약·검증/변경/이력을 B 패널 기준으로 통일한다. 증적 공유는 승인 요청과 역할/상태 계약이 다름을 유지한다.
5. 동일 뷰포트 시안/실제 인증 화면 및 1440/1920/2560px/모바일에서 비교한다. 장문 증적·JSON·확인액션·조직 전환·권한별 빈상태/거부와 홈 deep-link를 검증한다.
