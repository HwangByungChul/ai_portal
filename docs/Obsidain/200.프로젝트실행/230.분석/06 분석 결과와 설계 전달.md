# 분석 결과와 설계 전달

## 종합 결론과 완료 상태

A230-01~05 분석 문서 작성과 자체 점검을 완료했다. 기존 GraphRAG는 문서 처리·schema/검색/근거 계약·고정 흐름의 골격을 선별해 활용한다. 실제 인증/조직 권한·DB/RLS·지속 Job/대화·중앙 AI 호출/원장·관계별 근거·버전 공유/회수는 새 포털의 요구에 맞게 보완해야 한다. 기존 백엔드의 모의 인증/category 권한·직접 SDK·전역 prompt·모의 완료/저장 실패 무시는 새 실행 경로에 그대로 사용하지 않는다.

승인된 React/Vite, 하나의 FastAPI, PostgreSQL+GraphRAG common_core와 논리 멀티테넌트 A/B를 유지한다. API G/W·AI G/W 역할은 같은 백엔드의 공통 모듈로 구현할 설계 입력이며 구매 제품·별도 서버·다중 모델·새 Agent 유형을 추가하지 않는다. 최소 비용 모델과 API 합산30,000원은 유지한다.

완료는 **분석 산출물 작성/참조 점검**이다. 2026-10-04 사용자 “네 진행 바랍니다”로 종합 결과와240 착수를 확인하여230 분석 기준선을 확정했다. 이 시점의 확정은 과거 검토 대기 기록을 소급 변경하는 의미가 아니다. 앱 구현, 실제 계정/DB/RLS/색인, 모델/화면/성능 시험은 미수행이다. 요구 연결41/41과 질문 작성20/20은 실제 기능/시험 통과율이 아니다.

각 P0는 별도 제품/서버가 아니라 필수 정확성/권한/저장/통제다. 구조 순서는 권한/저장→실행/공통AI→문서/Graph/근거/회수다. 화면은 이 계약을 소비하며 모의 지표나 타이머를 실측/완료로 쓰지 않는다. 일반 Agent에는 문서 근거를 꾸미지 않고 RAG만 실제 허용 자료와 연결한다.

구현 전달은 세 기능 묶음으로 나눈다: I1 인증/테넌트/DB 기반 및 기본 사용자·관리 진입, I2 일반 대화/본인 기록·Agent 설정/중지·중앙AI/usage·한도, I3 문서/색인·GraphRAG·근거·삭제/공유 회수. 각 묶음의 상세 설계 검토 및250 구현계획 후 구현/260 시험을 진행한다. 프론트/백엔드가 모두 독립 완료되었다고 계산하지 않고 업무 흐름 단위로 검증한다.

## 자료·판정에서 설계로 넘길 주의점

D-A-R1/R2의 같은 A 업무 개체에 다른 관계 근거를 연결하고, B의 같은 업무 이름은 별도 namespace로 유지한다. D-S는 A 소유이며 BASE에서 v1만 B 공유, v2는 미공유, 회수 후 과거 v1 링크도 차단한다. 버전 간 제목이 같을 수 있어 공통어/허용 제목만으로 누설을 단정하지 않고 보호된 버전/고유 사실/근거 출처를 판정한다.

원문 EV/관계 R은 평가자용 정답 식별자다. 실제 파싱/청킹/추출 산출물과 연결해야 하며 정답 관계를 그대로 검색 결과에 주입해 품질 통과로 표시하지 않는다. 개인/금지 근거·정답 JSON을 모델이나 일반 화면에 통째로 전달하지 않는다. 직전 회수 후 저장 인용 본문 재표시, Job 공개 시점/권한, 실제 chunk 연결, 물리 삭제 시점은240에서 결정할 계약이다.
