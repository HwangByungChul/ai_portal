# Task1 contract handoff · 2026-10-15

`MeetingInput`: memo StrictStr default empty, <=4000 characters, NUL rejected; blank requires document_refs. `meeting_date`: date or exact ISO YYYY-MM-DD wire string or null; datetime/int/bool rejected. `document_refs`: <=3 `{document_id: UUID, version_id: UUID}`, unique document and version IDs. Task2 must resolve current ACL, tenant, exact version/hash and source text; schema validation does not establish access.

`EvidenceItem`: text/quote existing bounded fields; `source_ref` defaults `memo`. Document reference spelling: `document:<canonical version UUID>`. `MeetingResult.check_evidence(source: MeetingInput, document_sources: Mapping[str,str] | None = None)` retains old call. Map only contains server-verified source text; only selected version keys accepted; title/page are not model metadata. Method validates quote exact substring, owner explicit substring and returns self, normalizing action fields in place. It does not resolve ACL. Model source IDs cannot introduce arbitrary documents. Memo cannot be overridden by map.

`ActionItem`: existing assignee/due_date plus due_expression, deadline_status (`unspecified`, `resolved`, `unresolved`), deadline_reason. Any supplied due_date conflicting with canonical deterministic result (including relative dates and missing base) is rejected `MEETING_DEADLINE_UNCONFIRMED`. Wrong ISO in quote is rejected by that equality check. Model status/reason are overwritten. Expression must occur verbatim in quote; absence is rejected. Semantic owner/deadline relationship still requires review.

`resolve_deadline(quote: str, meeting_date: date | None, expression: str | None = None) -> DeadlineResolution`: frozen dataclass fields due_date, expression, status, reason, human_review_required. Monday week; this-week weekday may be past; next-week weekday adds seven from week Monday. Today/tomorrow/day after, bounded 0..3660 calendar days, ISO date supported. Ambiguous/biz-day/missing base/conflicting dates/calendar overflow remain unresolved. No wall-clock/holidays/time inference. Past date resolves with reason past_due and human_review_required True. No detected deadline expression yields unspecified. A bounded recognition policy for unsupported periods (월말/월초/분기말/연내/연말/연초/다음달/이번달/이달/주말, with optional spaces for month phrases) yields unresolved/unsupported_expression even when the model omits due_expression; the detected original expression is retained. 이번주 without weekday remains ambiguous, including 이번주 안. Unsupported periods also prevent a supported expression in the same quote from producing false certainty. Explicit unsupported expression yields unresolved. Same-date multiple expressions resolve; differing ones remain unresolved. Quote can contain unrelated dates: human review is required at quality layer.

`evaluate_structure(result, source, document_sources=None) -> StructuralQuality`: works on deep copy, never mutates input; fields evidence_valid, item_count, unresolved_deadlines, past_deadlines, error, human_review_required (always True). Evidence valid is structural only. `HUMAN_RUBRIC` has accuracy/omission/owner/deadline descriptions, no scores, ratings or semantic-pass field. Synthetic v2 fixture includes a structurally valid but wrong owner example.

`meeting_contract()` revision 2 adds rules_sha256 for dates and quality, preserving existing validator_sha256 and deterministic digest. Catalog/ready flags untouched. Any code/rule/digest change needs fresh Workflow approval; old snapshots/results must remain unchanged. Raw runtime/Workflow and context bounds/ACL enforcement are Task2 and later, not implemented here.
