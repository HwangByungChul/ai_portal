## 검토 기준 정정

2026-10-04 사용자 정정에 따라 학습·MVP 대상은 **BNK 그룹 공동 생성형 AI 플랫폼 도입**이다. 최초 저작권 관련 정보시스템의 요구사항·정산 데이터·103개 상세 요구행은 이번 플랫폼의 기준으로 사용하지 않는다. 앞서 검토한 BNK_AI_Compliance HTML 21개는 이전에 지정한 화면 자산이며, 새 플랫폼 화면의 전체 범위로 간주하지 않는다.

2026-10-04 사용자의 이관 지시에 따라 문서 저장 위치를 BNK 프로젝트의 `10.Obsidain/그룹 공동 생성형 AI 플랫폼/개발/AI 통합 포털`로 변경했다. 기존 검토 문서와 시연 자료를 함께 이관했으며 이후 생성되는 문서도 이 위치에서 관리한다. 이전 도메인 검토는 과거 자료로 보존하고 이 문서를 현재 기준으로 우선한다.

## 확인한 자료와 해석

- RFP 원문 DOCX에서 사용자 포털·Marketplace·관리자와 RAG/Agent/운영 기술요건을 확인했다.
- 기존 실제 구축 설계 문서의 Control Plane + Tenant Cell, Next.js + Spring Boot + FastAPI, Private LLM 우선 기준을 확인했다. 문서 상태는 `review`이며 구현 완료의 증거가 아니다.
- `11.구축`에는 구성도·기능명세·IA 등 설계 자산이 있다. 이번 열람에서 앱 소스나 실행 가능한 서버 프로젝트는 확인하지 않았다.
- 기존 추적성 문서는 기능 F-001~060과 기술 T-001~062를 제시한다. 이는 기존 상세범위 파생 기준이며, 이번 검토에서 XLSX 개별행을 재대조한 수치가 아니다. RFP의 RAG/ONM 식별자는 아래에서 직접 확인했다.

## 범위 대응

| 플랫폼 구성 | 개인 MVP에서 실제 구현할 것 | 확장 대상으로 남길 것 |
|---|---|---|
| 통합 진입·사용자 포털 | 로그인, 조직 선택, Agent 2개, 채팅·이어하기·본인 기록·근거 표시 | SSO, 대규모 사용자 온보딩 |
| Marketplace | 승인 Agent 목록·검색, 사용신청·승인·회수 | 조직별 템플릿 복제·랭킹·커뮤니티 |
| Agent Builder | 설정 폼으로 Prompt·Model·Knowledge·버전 지정, 고정 RAG 흐름 시험 | 자유 Canvas, 병렬·장기 실행, 외부 Tool/MCP |
| 관리자 | 사용자·역할·조직, Agent 게시/중지, 모델 설정·한도·실사용량 | GPU 자원 배분, 기관 비용 정산 |
| 거버넌스 | 개발자와 승인자 분리, 버전 승인, 정책 스냅샷·실행 이력 | 금융 동의권원·DRM·전문 연계 |
| API G/W | 인증·조직 문맥·권한·요청 ID·요청수 제한의 공통 진입 | 별도 Gateway 제품·HA |
| AI G/W | 모델 호출 공통 어댑터, 토큰·비용·오류·한도·정책 통제 | 다중 모델 Serving, GPU Routing |
| Knowledge/GraphRAG | 합성 규정 5~10개, 권한 검색, 관계 근거, 삭제 반영 | OCR·다양한 문서·무중단 색인 전환 |

**원 사업은 10개 이상 계열사·여러 Agent·온프레미스 운영을 다루지만, 개인 실습은 가상 조직 A/B와 공통영역, Agent 2개로 같은 책임과 데이터 경계를 검증한다.** 공통영역은 명시적으로 공유 승인된 자산만 포함한다. 개인 실습의 논리 격리가 원 사업의 물리 격리 요건을 충족한다고 표시하지 않는다.

## 기술 선택 조정

개인 학습용은 기존 경력과 GraphRAG 코어를 활용해 React/Vite + FastAPI + PostgreSQL로 시작하는 안을 유지한다. 인증·정책·자산·원장 모듈과 AI 검색/호출 모듈의 책임은 분리하되 초기 배포 수를 줄인다. 이는 기존 기업 설계의 Next.js + Spring Boot + FastAPI를 개인 실습 규모로 축소한 **새 검토안**이다.

Spring Boot 경험을 직접 활용하려면 업무 Core만 Spring Boot로 두고 GraphRAG를 FastAPI에 둔다. 두 서버 간 인증 문맥·오류·트랜잭션을 다뤄야 하므로 초기 부담은 늘어난다. 원 사업 재현이 목표가 될 때 이 구성으로 확장한다.

Private LLM 운영과 GPU 클러스터는 후속 실습이다. 처음에는 모의 모델로 흐름을 검증하고, 실제 모델 단계에서는 사용 가능한 개인 모델 또는 외부 API 중 하나를 선택한다. 외부 API 사용은 원 사업 Private LLM 운영 적합성을 입증하지 않는다.

## 개인 실습 순서

1. **기반:** A/B 조직·개인/공유 문서 권한, 모의 모델, Agent 등록·게시·중지, 대화 재조회.
2. **중앙 호출:** 실제 모델 1개, 모든 생성/임베딩 호출의 공통 경로, 토큰 원장·한도·스트리밍 실패/취소.
3. **지식 Agent:** 기존 GraphRAG 공통 코어를 연결하고 DB 지속성·색인·근거·격리를 검증.
4. **운영 흐름:** 제한된 Builder 설정, Agent 버전 평가·승인·회수, Marketplace 사용권한, 비교 평가.

개인 준비물은 합성 규정/책무 문서, 사용자·승인자·관리자 테스트 계정, 예상 질문과 근거 정답, 모델 호출 예산, 로컬 PostgreSQL이다. 일정은 첫 단계의 실측 후 산정한다.
