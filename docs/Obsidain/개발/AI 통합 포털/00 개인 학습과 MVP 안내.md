## 검토 결론

개인 개발이 가능하다. **기존 화면에서 채팅·사용자 권한·기록 저장·관리자 사용량·AI 호출 통제를 연결하는 작은 흐름**을 먼저 완성한다. 사용자/관리자 포털, API G/W, AI G/W의 역할을 이해하되 처음부터 네 개의 독립 제품과 복잡한 인프라를 운영하지 않는다.

## 세 가지 접근 비교

| 접근 | 장점 | 부담·학습 범위 | 적합한 경우 |
|---|---|---|---|
| 기존 AI 포털 제품 조합 | 빠르게 채팅·문서 질의를 경험 | 화면·업무·호출 통제 내부 구조의 직접 학습은 줄어듦 | 사용성·시연이 우선 |
| 작은 자체 포털 + 서버 + AI 호출 계층 | 기존 화면 활용, 인증·DB·API·AI 연계를 순서대로 학습 | 서버와 권한·오류·저장 설계를 직접 이해해야 함 | **개인 학습과 MVP에 권고** |
| 포털·API GW·AI GW·RAG·SSO를 모두 분리 | 기업형 구조에 가까움 | 배포·계정·비용·장애 지점이 많음 | 기본 흐름 검증 이후 확장 |

## 목표를 단계로 구분

- **M0 준비:** 핵심 사용자·기능·API·데이터·모의 모델을 정의한다.
- **M1 기본 MVP:** 실제 대화, 본인 대화 저장, 승인된 프롬프트 2개, 관리자 설정·사용량, 권한/사용제한/오류 처리가 동작한다.
- **M2 문서 질의:** TXT/Markdown 합성 문서 5~10개로 문서 업로드·권한 검색·근거 응답·삭제 반영을 검증한다.
- **M3 통합 확장:** 독립 AI 게이트웨이, 모델 2개, 서비스 등록·승인·중지, 간단한 자산 목록을 연결한다.
- **M4 후속 과제:** MCP·다단계 Agent·워크플로우 빌더·기업 SSO·복잡한 AI 생애주기·다중 조직을 분리 과제로 검토한다.

현재는 검토·학습 계획 작성 단계이며 앱 구현·유료 서비스 사용·모델 연결은 수행하지 않았다. 아래 자료는 검토안이며 최종 기술 선택·착수일은 확정되지 않았다.

## 가장 먼저 준비할 것

사용자 2명과 관리자 1명, ‘일반 질문 / 문서 요약 초안’의 두 사용 사례, 합성 문서 5개, 예상 질문·답 10개, 주당 학습 시간, 월 API 비용 상한을 정한다. 처음에는 모의 모델로 화면·저장·권한을 연결하고, 이후 개인이 사용할 수 있는 모델 API 한 개를 서버에서 연결한다. GPU·모델 학습·기관 데이터는 초기 준비물에 포함하지 않는다.

경력 자료를 추가 검토해 플랫폼/API/운영 및 AI Full-Stack 경험을 확인했다. **현재 맞춤 권고는 [[개발/AI 통합 포털/04 경력 기반 집중 과제와 착수안]]을 우선 읽는다.** 주당 시간·모델 계정 보유 여부는 아직 미확정이다. 앞서 만든 저작권 합성 데이터는 별도 도메인 시연 자산이며 AI 포털의 초기 문서·질문 세트와 자동 통합하지 않는다.
