# 데이터 사전과 계산 규칙

## 파일·주요 필드

| CSV | 식별자·참조 | 의미 |
|---|---|---|
| 권리자 | party_id, member_id | 합성 권리자 A~E, 회원 연결 |
| 사용자 역할 | user_id, role, party_id, department | 회원은 본인, 직원은 담당 부서 범위 |
| 저작물 | work_id, internal_code, evidence_id | DEMO 식별자는 내부 시연 코드이며 국제 코드가 아님 |
| 초기/정정 지분 | rights_version, work_id, party_id, share_units/total_units | RV1 초기와 RV2 소급 정정, 정수 분수 지분 |
| 시연 요율 | tariff_version, unit_rate_krw, fee_krw, tax_krw | 계약 단가·0원 수수료/세금의 기준 |
| 모의 신탁계약 | trust_contract_id, application_id, party_id, initial_state | APP001 이벤트 전 DRAFT, 종료 후 MOCK_SIGNED |
| 이용계약 | license_id, work_id, status, tariff_version | LC001/T001 100원, LC002/T002 1,001원 단가의 시연 계약 |
| 음악사용자료 | usage_id, source_record_key, usage_date, quantity, unit_rate_krw | 원천 2건, 9월 사용분 |
| 모의 입금 | invoice_id, usage_id, billed_krw, received_krw | 전액 모의 입금, 실제 금융 연계 없음 |
| 분배 기대값 | run_id, usage_id, party_id, floor_krw, residual_bonus_krw | 원 단위 결과와 잔여금 분리 |
| 소급 조정 기대값 | original_run_id, original_krw, corrected_krw, adjustment_krw | 지급 전 원결과 보존·차액 초안 |
| 신청 상태 이벤트 | application_id, seq, actor, from_state/to_state | 초기 DRAFT에서 순서대로 재생하는 이벤트 fixture |
| 증빙 목록 | evidence_id, path, sha256, mode | 원본 대체 텍스트와 해시 |

CSV는 UTF-8 BOM, 금액·수량·지분단위는 정수다. CSV 문자열은 적재 시 명세에 맞게 숫자·불리언으로 변환한다. 통합 JSON은 타입을 유지한다. 파일 경로는 시연 폴더 기준 상대경로다.

## 권리 시점

사용기간은 2026-09-01 이상, 2026-10-01 미만이다. 시간대는 Asia/Seoul이다. RV1은 2026-10-04 09:20 승인, RV2는 같은 날 11:10 승인이다. 09:30 기준 조회는 RV1, 11:15 기준 조회는 W001에 RV2를 적용한다. W002는 RV1 그대로다.

효력기간과 기록·승인시점을 분리한다. 같은 버전·같은 저작물·권리자의 기간 중첩은 오류다. 다른 정정 버전의 동일 효력기간은 소급 정정의 정상 표현이며 중첩 오류로 처리하지 않는다. 해당 기준시점에 승인된 최신 버전을 선택하고 권리자별 여러 버전 지분을 섞지 않는다.

## 예시 규칙 R1

`정산액 = 사용량 × 계약 단가`. 수수료와 세금은 0원이다. 사용자료의 단가는 계약 요율의 복제값이며 계약의 T001/T002와 일치해야 한다. 전액 입금 전까지 분배 확정과 지급을 보류한다. 부분 입금에서는 비례 분배하지 않고 전체 청구액을 보류한다. 계산 초안과 확정은 별도 상태다.

지분 합은 정확히 1이어야 한다. 3인 균등 지분은 33.33%의 반올림 대신 각각 1/3로 저장한다. 각 지분 금액을 원 단위 절사하고 남은 금액을 party_id 오름차순으로 1원씩 배정한다. 이는 **내부 예시 정책**으로 실제 기관의 잔여금 규칙이 아니다.

RUN001은 지급 초안이며 송금하지 않는다. RUN002는 W001만 재산출하고 원결과와 조정액을 연결한다. 원분배+조정=최신 결과다. 이미 지급된 금액의 환수·상계와 회계전표는 별도 시나리오가 필요하다.

## 중복과 권한

파일 중복은 내용 해시로, 행 중복은 원천 제공자 범위의 source_record_key로 관리하는 구현 기준을 제안한다. 분배 중복 키는 BASE001/RV1/R1/202609 조합이다. 권리 버전이 변경되면 다른 실행을 생성하되 원결과를 삭제하지 않는다.

USER-A~E는 본인 자료만 조회한다. USER-STAFF는 권리 지식, USER-FINANCE는 정산 지식을 열람한다. 공개 지식은 모두에게 허용한다. 공개·회원 응답에는 내부 지식의 제목·문장·요약도 노출하지 않는다.

patch의 replace 키는 개체 선택 후 필드 변경을 뜻한다. rights.RV1.W001.evidence_id는 해당 지분 2행 모두 변경한다. append는 같은 명시된 버전의 테스트 지분을 추가한다. resubmit/request/retry는 시연 동작이며 데이터 전체를 병합하는 명령이 아니다.
