## Immutable result display metadata

GET run also returns own-only `meeting_context` for newly sealed runs: `{meeting_date,memo_character_count,aggregate_character_count,documents:[{document_id,version_id,source_ref,title:null|string,current_available:boolean}]}`. No original memo/document body/object key/parser mapping is exposed. When source withdrawal/filesystem verification fails, title is null and current_available false, while persisted meeting date and safe refs remain. For historical runs without sealed context, metadata is omitted; frontend uses null date and labels historical metadata unavailable. The UI must use this immutable server date/docs for result labels, never current form state.

Document evidence additionally has server-added `source_display:{title,version_id,page_start?,page_end?,structure_locations?,location_ambiguous:boolean}`. Source title/locations derive from exact currently authorized verified original mapping and quote offsets; model-authored metadata is rejected. Memo evidence keeps source_ref memo without document display. These display fields decorate public output only, not persisted original model result/quality digest.

Repeated identical quotes are mapped to all matching original locations; `location_ambiguous=true` warns that occurrence association remains human review. Deferred cases reject explicit date/docs fields even when null or empty.
